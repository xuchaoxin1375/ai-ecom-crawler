## 范围与顺序

这里跟踪 React v2 当前实现尚待处理的问题，不作为已批准的改版规格。先修用户会据此做错判断的问题，再从批次详情验证入口和布局方案，最后视效果推广到站点和任务详情。本轮只登记界面待办；路由拆包另见[首屏加载与路由拆包](35-前端设计系统与视觉方向.md#首屏加载与路由拆包)。

审计基线为 `7efe384` 构建产物，在 Windows／Chromium 156.0.8078.4 上使用 FastAPI、临时 SQLite 和本地商品夹具。截图与几何记录保存在仓库外证据库的 `workbench/ui-audit-7efe384-*`；未访问实站或调用模型。

## 优先修正结果口径

| 优先级 | 问题与证据 | 建议与复验条件 |
| --- | --- | --- |
| P1 | **任务已结束却显示无明细。** 本地复现：摘要显示 2 件有效商品，导出的 ZIP 及 CSV、任务明细接口均有 2 条；站点页 5 秒内仍显示空结果，区块内刷新才恢复 CSV。 | 任务转终态时，按任务 ID 同步刷新商品预览、CSV 和明细；新结果读回前显示「正在更新结果」，不要把旧空结果当终态。复验：先在同一浏览器打开运行中的任务，再等它完成并下钻站点；不手动刷新，摘要、预览、明细和 ZIP 内容一致。另验真实空结果和读取失败可区分。 |
| P1 | **批次导出文案不表明范围。** 已完成批次的三个导出入口实点均下载同一地址；代码显示活跃状态页头仍写「导出 ZIP」，实际与侧栏的「导出部分结果」使用同一部分导出请求。 | 批次只保留一个常驻导出入口，按判定结果明确区分「导出部分结果」和「导出批次 ZIP」；站点页明确导出的是当前任务。复验：排队、运行、暂停和结束时，文案、请求参数、ZIP 清单与导出范围对应；完整档案不暗示每个站点都采集成功。 |

## 入口与布局

| 优先级 | 问题与证据 | 建议与复验条件 |
| --- | --- | --- |
| P2 | **同页同范围动作重复。** 可采未启动站点有三个「启动采集」；批次页的页头和「下一步」打开同一个启动弹窗，状态带与清单也重复提供部分筛选。 | 页头保留对象级动作，表格负责行操作与勾选批量操作，「下一步」负责解释或指向实际操作区。复验：同页同状态同范围只有一个常驻入口；不把整批、单站、已勾选站点三个范围混为一谈；保留有独立用途的跨页入口和取消确认。 |
| P2 | **辅助栏占宽，但长短变化没有改善阅读。** 1280×900 下，单站批次主列／侧栏约 224／733 px，18 站批次约 1222／733 px；任务页的 920 px 宽 CSV 表放在约 607 px 的主列，桌面也需横滑。390×900 下已完成批次首屏只露出清单标题。 | 不硬拉等高。先在批次详情让站点清单优先占全宽，批次事实收起，低频管理进入「更多」；任务／站点详情默认先看结果，CSV、历史、规则与诊断按需展开。仅保留需要并排参照的短侧栏。复验：用单站、多站和有历史记录样本，在 1280、1279、390 px 检查首屏顺序、表格可读性及键盘操作，不以「没有页面横向溢出」代替。 |
| P2 | **下钻后显式返回丢失上下文。** 实点「返回批次」后，原批次清单的搜索参数消失。 | 带回原来的搜索、筛选及列表位置；直接打开详情深链时回到默认清单。复验：从多站清单定位并打开一行，再返回后能从原条目继续处理。 |
| P2 | **构建审批可能埋在长页后部。** 代码走查发现「待处理请求」位于构建事实和修复历史之后；未运行真实模型审批。 | 构建等待人处理时将请求和恢复说明前置；先用批准、拒绝和无待办状态复验，再按发布要求走查真实审批。 |
