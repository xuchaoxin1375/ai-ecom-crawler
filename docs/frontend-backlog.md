## 范围与顺序

这里跟踪 React v2 当前实现尚待处理的问题，不作为已批准的改版规格。先修用户会据此做错判断的问题，再从批次详情验证入口和布局方案，最后视效果推广到站点和任务详情。路由拆包已完成，见[首屏加载与路由拆包](35-前端设计系统与视觉方向.md#首屏加载与路由拆包)。

审计基线为 `7efe384` 构建产物，在 Windows／Chromium 156.0.8078.4 上使用 FastAPI、临时 SQLite 和本地商品夹具。截图与几何记录保存在仓库外证据库的 `workbench/ui-audit-7efe384-*`；未访问实站或调用模型。

两项 P1 的复验记录：

- 终态结果刷新用查询阶段键区分 live／final，任务转终态后商品预览、CSV 和明细各重新读取一次；读回前显示「任务已结束，正在更新结果…」。新增 `taskResultRefresh.test.tsx` 覆盖三个区块；本地站点页在任务从 `RUNNING` 改为 `FINISHED`、不手动刷新时，CSV 从 0 行自动变为 20 行并切到 `products.csv`。
- 批次详情只保留侧栏一个常驻导出入口；`batchExportLabel` 按任务状态给出「导出部分结果／导出批次 ZIP」，站点与任务导出统一写明「当前任务」。批次页「查看导出入口」只聚焦侧栏按钮，不再重复下载。`RUNNING` 副本的部分导出 ZIP 在 `batch.json` 标为 `running`，已完成副本的全量 ZIP 标为 `complete`，均带站点文件和清单。

## 设计复核与待确认方向

本轮结合上文 `7efe384` 桌面和窄屏截图、交互记录与源码复核。旧截图中的批次导出重复、任务预览未刷新属于上文已实现的 P1，不当作本轮新发现。侧栏中的模型配置来自同期独立改动，不作为旧版基线的一部分。

### 新发现与优先级

| 优先级 | 现象与根因 | 建议修法与复验条件 |
| --- | --- | --- |
| P1 | **只有排队任务时，下一步指向空清单。** `batches/detail.ts` 用「运行中 + 排队 > 0」展示「查看运行中的站点」，但点击只筛运行态。同时，`BatchStatusBand.tsx` 固定说「逐个执行」，而服务允许多个任务槽位。 | 只排队时指向排队项，排队与运行并存时仍可分别查看；除非掌握实际槽位，不承诺串行。复验：仅排队、仅运行、混合并行时，提示、计数和筛选结果一致。 |
| P1 | **未配置构建服务时，修复入口仍像可用。** 旧站点页截图同屏显示「修复规则」实心按钮和「启动构建会返回不可用」；`BuildPanel.tsx` 的入口只因忙碌置灰。 | 未配置时隐藏，或禁用并就地说明；同页页头、面板和其他能触发同一请求的入口共享阻断判据。复验：已配置、未配置、读取失败分别处理，不把读取失败当作未配置。 |
| P2 | **同一动作跨位置、跨对象改名。** `TaskDetailPage.tsx` 页头的「导出 ZIP」与侧栏的「导出任务 ZIP」共用下载处理；`SiteDetailPage.tsx` 也有页头和侧栏导出。批次的「启动 N 个」没写单位；「继续导入」也用于首次导入；「恢复任务」用于归档还原，又与继续暂停任务语义相近。 | 同页同对象同后果只保留一个常驻入口；跨页保留有独立用途的入口，但统一对象、状态和后果。复验：文案可单独分辨批次／站点／任务范围，按钮、确认和回执一致。 |
| P2 | **结果、验收和技术内容没有主次。** `TaskDetailPage.tsx` 先显示反馈，再依次铺商品预览、质量异常、CSV 预览、任务明细；右侧长事实栏挤压数据表。站点页同时常驻规则、历史和导出；旧窄屏截图里批次状态摘要占三段，站点清单到首屏底部才出现。 | 批次先看全宽站点清单；站点与任务先看当前采集或结果，历史、规则、反馈和诊断按用途分视图或按需展开。构建等待审批例外，提示与可处理入口不可折叠隐藏。复验看首次可见的业务行与关键操作，不只量页面总高度。 |
| P2 | **返回父对象不是回到原工作位置。** `BatchDetailPage.tsx` 的站点链接只传站点路由，不带原清单状态；`AppShell.tsx` 在路径变化时滚顶。 | 「返回列表／清单」恢复来源的搜索、筛选和位置；面包屑「打开父对象」与直接深链接可使用默认视图。复验要分别走显式返回、浏览器后退和无来源深链接。 |

### 入口与信息层级草案

既有[设计基线](35-前端设计系统与视觉方向.md#设计主张)已经要求「单一工作表面」和唯一主操作，但详情模板同时默认使用 8／4 分栏，并在右栏常驻放「下一步」动作。本轮提议调整的是这条详情模板，不是新换框架、配色或整套侧栏组件。参考 `admin-console-design` 中 Cloudflare 风格的 fable 外壳分组和列表工作表面；本地样例不是 Cloudflare 官方规范。

| 位置 | 放什么 | 本项目建议 |
| --- | --- | --- |
| 全局侧栏 | 可独立直达、作用于多对象的页面 | 「采集工作台」放采集批次、采集任务；「规则与设置」放规则构建记录、模型配置。新建批次是批次列表里的动作，不与页面入口混排；是否保留独立的全局快捷入口待确认。 |
| 页头 | 当前对象、状态和一个随状态变化的主操作 | 批次待启动时突出「启动 N 个可采站点」，有未结束任务时明确部分结果；归档或取消等低频管理放「更多」，取消保留确认。 |
| 主体工具栏／行菜单 | 当前数据的搜索筛选、单行和勾选批量动作 | 状态摘要只读，筛选归清单；单行菜单作用于一个站点，勾选后的操作只作用于所选站点，不冒充整批操作。 |
| 对象内视图／折叠 | 同一对象的并列任务、可选技术信息 | 批次默认就是站点清单，不额外造概览页；站点可切换「当前采集／任务历史／规则版本」；任务可切换「结果／质量反馈／运行明细」，CSV 预览按需；构建先显示审批或运行状态，再看验证和日志。视图名与最终分组待确认。 |

### 容易混淆的操作用词

以下是界面候选用词，不改[术语表](术语表.md)、状态码或业务行为；具体操作仍以[任务状态与计数契约](09-任务状态与计数契约.md)和[规则修复与异常工作流](34-规则修复与异常工作流.md)为准。

| 操作后果 | 候选用词 | 需要明确的区别 |
| --- | --- | --- |
| 首次为可采站点建任务并入队 | 启动采集／启动 N 个可采站点 | 已入队不等于正在采集；整批、所选、单站分别写明。 |
| 延续暂停的采集任务 | 继续采集 | 沿用当前任务，从暂停点继续。 |
| 为已结束的站点新建采集任务 | 重新采集 | 旧任务和结果保留；可在说明中使用项目术语「复跑」。 |
| 归档对象重新出现在默认列表 | 取消归档 | 不继续采集，也不创建任务。 |
| 生成新站规则，或对现有规则产出候选修订 | 构建采集规则／修复采集规则 | 与采集任务分开；规则修复通过不等于新规则已生效。 |
| 暂停后继续当前构建／为失败或中断会话发送补充指令／发起全新构建 | 继续当前构建／继续原构建会话／重新构建规则 | 前两项沿用当前构建或原会话，第三项产生新构建；不能都称「重试」。 |
| 把候选规则设为后续任务使用的版本 | 启用候选规则 | 不改写旧任务结果，不自动重采；证据不足时必须明确阻断原因。 |
| 选择目录发现策略／放宽采集任务预算 | 按分类与分页生成规则／不设任务数量或时长上限 | 「全量目录」在构建期只改规则发现策略，仍按样本验证；「全量采集」是运行期预算选择，均不承诺全站覆盖。 |

### 建议实施顺序

1. 确认布局方向后，以批次详情为首个改版切片：全宽清单、紧凑摘要、唯一入口；一并修正排队指向、导入／启动文案和站点下钻返回。保留已实现的部分／整批导出判定。
2. 用单站、多站、仅排队、部分结果和完成批次走查。首屏至少露出可操作的站点行；桌面 1280 × 900 像素、典型窄屏 390 × 900 像素下对照旧证据；检验键盘操作、筛选返回、取消确认和导出范围。获确认后再固化模板。
3. 推广到站点、任务和构建详情；优先处理未配置时的构建入口与阻断审批，再拆分当前采集、结果、历史、规则和日志。全局导航最后与并行的模型配置改动对齐，不修改旧版前端、后端业务接口或已分享的深链接。

### 批次详情试点规格

已选择清单优先。沿用现有 React 外壳、颜色令牌、表格、菜单、确认弹窗和原 URL。右栏不再常驻；因为当前站点是工作对象，不采用单独「总览」页。桌面同一内容宽度从上到下放标题与操作、只读进度、全宽清单和折叠资料。窄屏使用相同顺序，标题操作可换行，筛选改用单一选择控件；宽表在表格容器内滚动，页面仍随文档纵向滚动。

| 验收项 | 独立判据与验证 |
| --- | --- |
| `BD-01` 清单层级 | 非空批次在 1280 × 900 与 390 × 900 首屏至少出现首个站点；在空批次引导用页头「导入站点」，筛选无结果有重置、读取失败可重试。用真实浏览器检查几何和截图。 |
| `BD-02` 状态与文案 | 仅排队不会提示查看运行中或承诺串行；排队、暂停、已结束和结果完整性分开。筛选实际数据与标签一致。用规则测试和浏览器状态验证。 |
| `BD-03` 操作范围 | 待启动时显示启动对象数，运行中可暂停，归档后可取消归档；低频整批操作入「更多」，取消保留二次确认。站点行和勾选操作维持原有目标范围。导出入口唯一，未结束任务存在时走部分导出，否则使用整批 ZIP。用组件测试及隔离账本烟测。 |
| `BD-04` 返回清单 | 从站点行下钻后，显式返回或浏览器后退恢复原搜索、筛选和可用的滚动／焦点位置；直访站点时返回未筛选批次。用真实路由和浏览器验证。 |

本轮不改全局导航、站点主体、任务详情和构建配置。也不改变批次启动请求原有语义：勾选重新采集时，尚未启动且可采的站点也会一起入队；文案明确说明，不把原入口说成只作用于已结束站点。

### 试点验证与待验收项

2026-11-25，Windows／Chromium 156.0.8078.4，使用生产构建、临时 SQLite 账本和回环商品夹具。现有 `8765` 服务已读到新构建；在 Edge 中只读确认真实批次能打开新清单和导出入口，不在真实账本上启动、取消或归档任务。

- **清单与窄屏**：1280／1279／768／390／320 像素宽度均验证首行可见、表头与首行对齐、无页面级横向溢出；390 像素下横移表格后仍可操作固定在右侧的行菜单。查看了 1280 和 390 像素首屏截图；桌面批次详情 axe 违规为零。无筛选结果可一键重置。
- **操作与导出**：已验证归档确认的安全首焦、Escape 关闭及焦点回到「更多」；从新建批次到采集完成再返回批次，只有一个整批导出入口，ZIP 内任务结果与 2 条商品记录一致。仅排队的筛选与状态区分有规则测试；本轮未在浏览器重复下载部分 ZIP，也未实点批次取消或确认归档写入。
- **返回上下文**：显式返回与浏览器后退均验证恢复筛选和站点链接焦点；多站点样例验证实际滚动位置；无来源的直接深链接返回默认清单。
- **范围**：前端 74 项测试与 lint、格式、类型检查、构建通过；复验截图在仓库外证据库 `workbench/batch-detail-design-20261125-001229/`。本轮未重测 Firefox、WebKit、读屏或真实触屏设备；试点待项目方验收，其他详情页改版未实施。
