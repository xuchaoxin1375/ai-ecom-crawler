## 设计复核与推广依据

本轮结合上文 `7efe384` 桌面和窄屏截图、交互记录与源码复核。旧截图中的批次导出重复、任务预览未刷新属于上文已实现的 P1，不当作本轮新发现。侧栏中的模型配置来自同期独立改动，不作为旧版基线的一部分。

### 新发现与优先级

| 优先级 | 现象与根因 | 建议修法与复验条件 |
| --- | --- | --- |
| P1 | **只有排队任务时，下一步指向空清单。** 旧页只按运行态筛选，却把排队任务也当作「查看运行中的站点」的触发条件；摘要还固定说「逐个执行」，而服务允许多个任务槽位。 | 批次试点已修正。推广时继续区分排队和运行，未掌握实际槽位不承诺串行；用仅排队、仅运行和混合并行样本检查提示、计数与筛选一致。 |
| P1 | **未配置构建服务时，修复入口仍像可用。** 旧站点页截图同屏显示「修复规则」实心按钮和「启动构建会返回不可用」；`BuildPanel.tsx` 的入口只因忙碌置灰。 | 未配置时隐藏，或禁用并就地说明；同页页头、面板和其他能触发同一请求的入口共享阻断判据。复验：已配置、未配置、读取失败分别处理，不把读取失败当作未配置。 |
| P2 | **同一动作跨位置、跨对象改名。** `TaskDetailPage.tsx` 页头的「导出 ZIP」与侧栏的「导出任务 ZIP」曾共用下载处理；站点阶段 2 和任务阶段 3 都已收为页头或「更多」一处。批次的「启动 N 个」没写单位；「继续导入」也用于首次导入；「恢复任务」用于归档还原，又与继续暂停任务语义相近。 | 同页同对象同后果只保留一个常驻入口；跨页保留有独立用途的入口，但统一对象、状态和后果。复验文案可单独分辨批次／站点／任务范围，按钮、确认和回执一致。 |
| P2 | **结果、验收和技术内容没有主次。** 旧任务页先显示反馈，再依次铺商品预览、质量异常、CSV 预览、任务明细；右侧长事实栏挤压数据表。站点阶段 2 和任务阶段 3 已把结果前置、质量／数据／事实分视图；旧窄屏截图里批次状态摘要占三段，站点清单到首屏底部才出现。 | 批次先看全宽站点清单；站点与任务先看当前采集或结果，历史、规则、反馈和诊断按用途分视图或按需展开。构建等待审批例外，提示与可处理入口不可折叠隐藏。复验看首次可见的业务行与关键操作，不只量页面总高度。 |
| P2 | **返回父对象不是回到原工作位置。** `BatchDetailPage.tsx` 的站点链接只传站点路由，不带原清单状态；`AppShell.tsx` 在路径变化时滚顶。 | 「返回列表／清单」恢复来源的搜索、筛选和位置；面包屑「打开父对象」与直接深链接可使用默认视图。复验要分别走显式返回、浏览器后退和无来源深链接。 |

阶段 1 已按上表「未配置构建服务」和「构建审批」两项落地：共享可用性判据同时约束站点页页头、「下一步」、构建面板、构建启动对话框和构建详情的继续会话；审批区在站点页和构建详情都移到工作区之前。实现与验证见[阶段 1 实现与验证](#阶段-1-实现与验证)。

### 入口与信息层级草案

既有[设计基线](35-前端设计系统与视觉方向.md#设计主张)已经要求「单一工作表面」和唯一主操作，但详情模板同时默认使用 8／4 分栏，并在右栏常驻放「下一步」动作。本轮提议调整的是这条详情模板，不是新换框架、配色或整套侧栏组件。参考 `admin-console-design` 中 Cloudflare 风格的 fable 外壳分组和列表工作表面；本地样例不是 Cloudflare 官方规范。

| 位置 | 放什么 | 本项目建议 |
| --- | --- | --- |
| 全局侧栏 | 可独立直达、作用于多对象的页面 | 「采集工作台」放采集批次、采集任务；「规则与设置」放规则构建记录、模型配置。新建批次是批次列表里的动作，不与页面入口混排；是否保留独立的全局快捷入口待确认。 |
| 页头 | 当前对象、状态和一个随状态变化的主操作 | 批次待启动时突出「启动 N 个可采站点」，有未结束任务时明确部分结果；归档或取消等低频管理放「更多」，取消保留确认。 |
| 主体工具栏／行菜单 | 当前数据的搜索筛选、单行和勾选批量动作 | 状态摘要只读，筛选归清单；单行菜单作用于一个站点，勾选后的操作只作用于所选站点，不冒充整批操作。 |
| 对象内视图／折叠 | 同一对象的并列任务、可选技术信息 | 批次默认就是站点清单，不额外造概览页；站点可切换「当前采集／任务历史／规则版本」；任务可切换「结果／质量反馈／运行明细」，CSV 预览按需；构建先显示审批或运行状态，再看验证和日志。视图名与最终分组待确认。 |

### 容易混淆的操作用词

以下是界面候选用词，不改[术语表](术语表.md)、状态码或业务行为；具体操作仍以[任务状态与计数契约](09-任务状态与计数契约.md)和[规则修复与异常工作流](34-规则修复与异常工作流.md)为准。

| 操作后果 | 候选用词 | 需要明确的区别 |
| --- | --- | --- |
| 首次为可采站点建任务并入队 | 启动采集／启动 N 个可采站点 | 已入队不等于正在采集；整批、所选、单站分别写明。 |
| 延续暂停的采集任务 | 继续采集 | 沿用当前任务，从暂停点继续。 |
| 为已结束的站点新建采集任务 | 重新采集 | 旧任务和结果保留；可在说明中使用项目术语「复跑」。 |
| 归档对象重新出现在默认列表 | 取消归档 | 不继续采集，也不创建任务。 |
| 生成新站规则，或对现有规则产出候选修订 | 构建采集规则／修复采集规则 | 与采集任务分开；规则修复通过不等于新规则已生效。 |
| 暂停后继续当前构建／为失败或中断会话发送补充指令／发起全新构建 | 继续当前构建／继续原构建会话／重新构建规则 | 前两项沿用当前构建或原会话，第三项产生新构建；不能都称「重试」。 |
| 把候选规则设为后续任务使用的版本 | 启用候选规则 | 不改写旧任务结果，不自动重采；证据不足时必须明确阻断原因。 |
| 选择目录发现策略／放宽采集任务预算 | 按分类与分页生成规则／不设任务数量或时长上限 | 「全量目录」在构建期只改规则发现策略，仍按样本验证；「全量采集」是运行期预算选择，均不承诺全站覆盖。 |

### 批次详情试点规格

已选择清单优先。沿用现有 React 外壳、颜色令牌、表格、菜单、确认弹窗和原 URL。右栏不再常驻；因为当前站点是工作对象，不采用单独「总览」页。桌面同一内容宽度从上到下放标题与操作、只读进度、全宽清单和折叠资料。窄屏使用相同顺序，标题操作可换行，筛选改用单一选择控件；宽表在表格容器内滚动，页面仍随文档纵向滚动。

| 验收项 | 独立判据与验证 |
| --- | --- |
| `BD-01` 清单层级 | 非空批次在 1280 × 900 与 390 × 900 首屏至少出现首个站点；在空批次引导用页头「导入站点」，筛选无结果有重置、读取失败可重试。用真实浏览器检查几何和截图。 |
| `BD-02` 状态与文案 | 仅排队不会提示查看运行中或承诺串行；排队、暂停、已结束和结果完整性分开。筛选实际数据与标签一致。用规则测试和浏览器状态验证。 |
| `BD-03` 操作范围 | 待启动时显示启动对象数，运行中可暂停，归档后可取消归档；低频整批操作入「更多」，取消保留二次确认。站点行和勾选操作维持原有目标范围。导出入口唯一，未结束任务存在时走部分导出，否则使用整批 ZIP。用组件测试及隔离账本烟测。 |
| `BD-04` 返回清单 | 从站点行下钻后，显式返回或浏览器后退恢复原搜索、筛选和可用的滚动／焦点位置；直访站点时返回未筛选批次。用真实路由和浏览器验证。 |

## 推广计划

**状态：阶段 1–3 已验收；阶段 4 设计待确认。** 复用批次试点已经验证的原则，不把所有页面改成批次表格。首屏应能看懂当前对象、状态和下一步；同页同对象、同后果的操作只设一个常驻入口；只有需要并排参照时才留短侧栏。同一对象的并列视图可切换，独立工具或设置页走侧栏独立入口，低频说明按需展开。采集相关界面复用「继续采集」「重新采集」「取消归档」的区分；其余新名称仍在对应页面设计时确认。

### 实施顺序与退出条件

1. **先修会误导或阻断任务的问题。** 站点页和其他构建入口共用同一可用性判据：已配置才允许发起；明确未配置时隐藏，或禁用并说明；读取失败给重试，不冒充未配置。构建详情有待审批时，在首屏显示请求和处理后的影响，不要求先翻日志。退出条件：隔离样本覆盖已配置、未配置、读取失败，以及无待办、批准、拒绝、提交失败可重试；阻断时不能从另一入口发出同一请求。
2. **重组站点详情。** 默认先显示当前采集：未启动时检查可采条件与启动入口，执行中显示真实状态，已结束时优先显示结果；任务历史、规则版本和诊断移到各自入口。当前任务导出只留一处，不包含历史任务；候选规则验证不足时，保留阻断理由和查看证据的入口。设计草案与待确认决策见[站点详情改版设计](39-站点详情改版设计.md)。退出条件：从筛选过的批次下钻，走完待接入、可采、执行或结果路径，再返回原清单；已有规则版本、历史和修复入口未丢失。
3. **重组采集任务详情。** 商品任务先见商品结果，网址发现任务先见网址结果；质量反馈、运行明细和 CSV 预览按用途收纳，导出缩为单一入口。设计草案与待确认决策见[任务详情改版设计](40-任务详情改版设计.md)。退出条件：覆盖运行中、终态、部分结果、真实空结果和读取失败；核对状态、计数、明细与下载一致，用户能从结果进入质量反馈，再回原任务；关闭弹窗后焦点返回触发处。
4. **收口构建详情与全局导航。** 构建页先显示运行状态或待审批事项，再按需查验证证据、修复轮次和日志；明确区分继续原会话与重新构建。最后确认业务页与规则／设置页在侧栏中的分组，以及是否保留「新建批次」的全局快捷入口。设计草案与待确认决策见[构建详情与全局导航改版设计](41-构建详情与全局导航改版设计.md)。退出条件：已有地址可直达、可刷新、前进／后退和侧栏当前项正确；无待办时无需先看空审批模块；任务和构建记录不会被误认成同类执行对象。

### 各阶段共用的验收与回退

- **先列功能去向，再写代码。** 每阶段先写首屏线框、操作位置、状态表和深链接映射；没定的视图名称与全局导航分组不预写成已定稿。不要把现有功能藏进更深的菜单来换取首屏更短。
- **按使用场景验收。** 复用[前端测试入口](23-测试策略.md#前端测试怎么跑)，先过前端检查和受影响流程的浏览器回归，再用 1280 × 900 和 390 × 900 对照截图，交付前检查 768／320 像素。验证首屏能看到关键数据或审批、键盘和焦点、长表横滚后的操作可达、复制链接和返回恢复。在隔离账本中核对导出内容并测试取消、归档和审批等写入；真实账本只读走查，真实模型调用另按费用和环境授权执行。
- **分阶段交付与回退。** 每阶段独立预览和验收；失败先停在当前阶段，不继续铺开。保持现有后端接口、状态契约、已分享深链接、React 外壳与视觉令牌，不改旧版页面、不迁移账本；需要撤回时按该阶段恢复前端版本，不回滚用户任务及结果。
