## 用途与边界

**本页集中解释仓库里反复出现的编号和代号。** 它回答“这个编号属于哪套体系、是什么意思、在哪里定义、容易和什么混淆”，不记录完成状态，也不替代主题正文。

- 当前状态、证据和下一步看[交接与继续](15-交接.md)与[实施路线与交接](10-实施路线与交接.md)。
- 任务状态、计数和失败分类看[任务状态与计数契约](09-任务状态与计数契约.md)。
- 业务规则、字段和流程仍以 `01`～`09` 正文为准；编号定义页扩展编号时，本页同步更新。
- 本页与定义页冲突时，以定义页为准；本页不新增业务口径。

## 怎么判断一个编号

**先看上下文，再看前缀和前导零。**

- **上下文**：同一页可能定义局部编号。`19` 的验收场景表、`22` 的执行层级表、`23` 的测试分层表都各自定义了一套编号，先看它所在的小节。
- **前缀**：大写字母通常表示一套系列，如 `D` 开发交付、`A` 验收场景、`R` 研究任务、`S` 代表站、`T` 测试或执行层、`C` 能力层、`J` 关键决策、`G` 阶段门。
- **前导零**：正式系列常用两位编号，如 `D01`、`A16`、`R06`；不带前导零的 `D1`、`A1`、`R1` 往往属于另一套局部编号。`S1`～`S7` 是例外，正式编号就是一位。
- **不要推断**：编号本身通常不表示日期、优先级或完成度；这些含义只在对应表头或正文里成立。

### 其他版本号

| 形式 | 含义 | 出处 |
| --- | --- | --- |
| `v1`、`v2`、`v3` | 产品或运行时代际：v1 任务级并行，v2 每任务进程／worker 池，v3 外部队列／多 worker | `15` |
| `v1.0` | v1 交付版本的界面范围 | [v1 界面范围](25-v1界面范围.md) |
| `V4.1` | 模型版本，如 `DeepSeek V4.1 Flash` | `07` |
| `OpenCode V2` | 构建 harness 版本，不是本项目的 v2 | `07`、[来源与维护](来源与维护.md) |
| `schema_version` `1.0`／`1.1`／`1.2`／`1.3` | 规则 manifest 契约版本；`1.3` 增加 Shopify `product_source` | [采集方案与兼容契约](08-采集方案与兼容契约.md)、`22`、[ADR 0020](adr/0020-shopify-json产品源.md) |
| `plan_version` | 站点方案版本，和 `schema_version` 不同 | `08` |

**不要只看 `v2` 三个字符**：它可能是前端 v2、运行时 v2，也可能是 `OpenCode V2`；`V4.1` 则是模型版本。

### 运行对象 ID

- `web-<hash>`：采集任务 ID，例如 `web-946474de5cf1`。
- `b-<数字>`：批次 ID，例如 `b-586052683409`。
- `d04-product-rerun-001`：任务或运行标签，不是正式编号系列。

这些 ID 由系统在运行时生成，不是本页维护的编号体系；不要用它们反推 `D`／`A`／`R` 编号。

## 维护规则

- **先登记再使用**：新增编号系列时，先在定义页建立编号，再回写本页的总表和易混对照。
- **不复用旧号**：已停用或未分配的编号不重新分配；`A23` 在项目方确认前保持未分配。
- **只写含义和出处**：本页不记录完成状态、证据数量或当前优先级，避免与 `10`／`15` 形成第二份状态。
- **定义页优先**：编号含义变化时先改定义页，再同步本页；两者冲突时以定义页为准。
- **跨文档引用**：正文引用编号时可直接写 `A16`、`D08` 等短名，需要解释或查出处时链接本页。
