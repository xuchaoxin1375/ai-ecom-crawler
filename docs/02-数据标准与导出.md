## 适用口径

本文件是共同的数据业务标准。**字段名是沟通映射，各实现可设计内部结构，但须提供到本表的无损映射。** 示例数据不构成已经发布的API协议。

本表的字段用于内部规范化、任务报告和诊断；最终业务CSV只导出“导出与留存”一节的9列，其余字段不进入CSV。

按用户确认采用：允许普通浮点数；有效商品只接受正价；公开含税／未税报价通常选较小者；复杂正文有界尝试后可按部分内容交付并标注。不能把这些取舍解释为可以猜值、取错商品或隐瞒失败。既有执行版本的Decimal类型、零价／缺价、描述缺省和CSV形状按其冻结合同解释，不自动覆盖本标准或升级旧任务。本目录不附旧版本合同；新实现不受其约束，一律按本标准执行；旧任务兼容由承接方在项目技术文档中单独记录。

## 字段定义

| 字段 | 业务要求 | 缺失／错误处理 |
| --- | --- | --- |
| `name` | 主商品名称；保留品牌、型号、规格，清理明确本站域名及无意义相邻分隔符 | 必须有；不把店铺口号当名称，不猜测删除未知品牌词；清理后为空属错误 |
| `price.amount` | 当前主商品最低公开展示价，包含缺货有价变体；正常数值且大于零 | 零、负数、无价及非法数值不进入有效商品集，保留网址和原因 |
| `price.currency` | 同一报价明确的三字母币种代码 | 不凭货币符号、域名、语言或代理国家猜测 |
| `primary_image_url` | 必须有一张主商品图片；有依据时优先原尺寸，解析相对路径 | 不取Logo、占位图或推荐商品，不编造原图地址；不只因文件名含thumbnail就拒绝 |
| `description_html` | 完整商品正文和公开技术规格，按来源保留清洗HTML或真实裸文本；最终CSV统一输出清洗后HTML | 无正文／摘要回退／复杂部分提取须区分，不能用产品名填空冒充 |
| `description_format` | 内部字段：正文载体，`html`或`text`；最终CSV不输出本列 | 有正文时必填；无正文时为空并说明；不能只凭列名或内容猜测 |
| `categories` | 原站有意义的商品分类，内部结构化保存 | 无合适分类可空并记录原因；不使用`!`内部占位 |
| `brand` | 原站明确提供的商品品牌 | 未提供可空，不把店名或域名当品牌 |
| `options` | 型号、尺码、颜色等公开选择维度和值 | 未提供可空；真实存在但漏提取须修复 |
| `source_url` | 实际主商品公开网址 | 规范化不丢商品身份，保留必要重定向追溯 |
| `market`／`locale` | 实际目标或默认访客的市场／语言上下文 | 无法满足指定目标须明确未达标，不能虚标 |
| `availability` | 可确认的库存状态，附带记录；`OnlineOnly`／`InStoreOnly` 等渠道值不算库存状态；多门店／多市场时绑定具体门店／市场 | 可空；缺货不是排除有价商品的理由 |
| 追溯与质量信息 | 任务、方案标识与版本、提取时间、来源摘要、缺失／回退／部分内容及价格口径 | 内部命名可变，不能丢失实际事实 |

同商品多个网址、多个变体和多次请求不直接等于多个商品。身份与去重策略由团队定义并在验收前说明，不能通过重复记录提高产量。

## 价格及币种

1. 取同商品、同目标市场、同币种的最低公开当前变体展示价，包含缺货变体；不采其他变体报价矩阵，不枚举SKU组合。
2. 通常在公开含税／未税报价中选择数值较小者，注明实际采用的税价口径；特殊说明或业务例外须明确。税价选择与变体最低价分别处理，不能谎称两者语义相同。
3. 不取划线原价、分期金额、运费、附加服务差价或推荐商品价。组合商品取最低起价，不擅自累加组成件价格。
4. 普通浮点数或精确十进制均可实现，避免显示出明显二进制尾数、币种误标、错误排序或数量级错误。不得把文本按字典顺序比较价格。
5. 价格必须为有限正数。原站零价、未展示价、解析失败分别留因；可以留在观察／诊断数据中，不能作为有效商品导出，也不能谎称原网址不存在。
6. 千位符、小数符和不换行空格按实际页面语境解析。明确币种取同一报价对象或绑定证据，`$`本身不足以区分币种。
7. 按重量／长度计价的商品，`price.amount` 是该计价单位（如 `per lb`）的公开价，须在描述或内部追溯中保留单位语义，不把单位价当包装价。多门店／多市场站点，价格与 `availability` 绑定具体门店／市场，不能把一家门店的报价或状态当全站。
8. 变体商品：商品可售＝任一公开变体可售；`price.amount` 取公开最低变体价（含缺货有价变体按第 1 项口径），变体级 SKU／价格／库存保留在内部记录，不把每个变体当独立商品。平台字段可能是 Shopify `variants`、WooCommerce `data-product_variations` 或 Magento configurable；父级 JSON-LD availability 不能替代变体级库存。公开 JSON 不带币种时，币种取同一店面／市场的全局配置。
9. 阶梯价／批发价取公开最低适用价并记录数量门槛；询价／报价单（quote-only）不进入正价商品集。酒类、烟草、年龄限制或地区限制商品记录公开限制字段／文案，不把限制当缺货，不绕过年龄门或地区校验。
10. 多市场：同一商品按目标市场分别记录价格／币种；先定目标市场，不跨市场取最低价或仅按汇率换算；`?country=`／市场路径与 `Shopify.currency`／`og:price:currency` 交叉核对。价格单位按平台／接口确认（分或十进制），不得把 11900 分当 11900 元。
11. 多卖家 marketplace：先声明输出单位。按商品输出时，`price.amount` 只能是声明的聚合口径（如当前最低 offer），并保留 `offerCount`／成色范围；按 offer 输出时，seller／condition／price／shipping 逐 offer 记录。商品页 `AggregateOffer` 的 low／high／count 是当前 offer 汇总，历史 price guide 不是当前价；聚合 `itemCondition` 不能替代 item 级成色，运费注明目的地。

拒绝布尔值、NaN和Infinity；支持逗号／点、空格、直／弯单引号等有证据的千位分隔。单一分隔符后有三位数字等歧义须依页面及locale(地区格式)核对，不盲目认作千位或小数。币种为有明确来源且已分配的ISO 4217代码。

**例子**：缺货S码29.00英镑、M码35.00英镑，取29.00并保留S／M公开选项；若同报价另有未税24.17与含税29.00，默认可用24.17并注明未税，不能写成“含税最低变体价24.17”。

指定英国市场而取得美国报价，换算成英镑仍未满足英国市场要求。换汇作为独立结果保留原币、目标币、汇率来源和时点，不覆盖采集原值。

`SITE_DEFAULT`表示原入口真实默认访客上下文；目标市场、实际页面语言和报价币种分别核对。明显URL语言分支可用于发现，不能单独证明报价市场；模糊语言分支不强求完整翻译等价，也不虚标匹配指定市场。详情见[发现方法](方法指导/02-网址发现与分页.md)。

## 描述与清洗

**优先完整正文，接受有依据、有标注的复杂部分交付。** 先检查主描述、展开区域及分散技术规格；长文本不必然完整，短文本也不必然缺失。

| 内容 | 处理 |
| --- | --- |
| 产品段落、列表、强调、技术参数表 | 保留内容、顺序和结构，避免重复拼接 |
| 标题 | 规范为强调或合理段落 |
| 链接 | 移除可点击能力，可留链接文字；删除裸网址 |
| 脚本、样式属性、图片、视频、表单、按钮 | 移除，不执行原站脚本 |
| 联系方式、评价、物流、退换货和店铺政策板块 | 按实际结构识别并删除，不靠关键词误删商品说明 |
| JSON中的HTML正文 | 按HTML清洗，JSON只是载体 |
| 原生裸文本 | 保留真实文本，不伪造结构，也不把已有HTML压成纯文本 |
| 售价旁明确销售单位 | 正文未包含时补在开头独立段；不从重量／数量控件推算 |

复杂车型关联规格等内容难以完整加载时，允许在有界尝试后保留能可靠取得的产品内容。须记录缺失区块、尝试和限制，标记**部分提取**；不能把只抓到摘要伪称完整正文。需要时可用浏览器截图帮助核对可见区块，但截图不能证明未展开或未渲染内容已经完整。

正文状态至少能区分以下语义，内部枚举名称由实现方决定：

| 状态语义 | 条件 |
| --- | --- |
| 完整正文 | 可核对的相关正文区块均已取得并清洗 |
| 部分提取 | 已知存在难取区块，有实际内容、具体限制及说明 |
| 摘要回退 | 未取得正文，以有来源的摘要替代；不能叫完整 |
| 原站未提供 | 有足够依据确认无正文，而非选择器未命中 |
| 提取失败 | 内容存在但逻辑失败，或无法判断缺失原因；继续修复或明确失败 |

描述缺失时，`description_html` 保持为空并记录为“原站未提供”；预览或导出展示可用商品名兜底，但不得写入 `description_html`，也不得把兜底标成完整描述。JSON-LD 的模板摘要按“摘要回退”记录；清洗后只有空标签时，按“原站未提供”或“提取失败”区分，不能算完整正文。

商品页的 Description 可能由多块组成：营销正文、规格表、适配车型、套装清单、配料／营养／过敏原、商家内部说明／捆绑应用提示、运费／退换政策。按标题或嵌入 JSON 的 section 拆块；规格、适配、清单和配料／营养归对应字段，内部说明单独记录或剥离，政策排除；只有商品自身正文计入 `description_html`。页面把适配表放在 Description 标签下时，按结构化描述或部分提取记录，不冒充完整营销正文。食品、生鲜等类目可能把配料、营养、过敏原放在独立字段或接口；按重量计价生鲜可以没有描述，标“原站未提供”，不拿名称或单位价补齐。

可接受的部分描述仍不允许伪造内容，且须在预览、导出与报告可辨。针对指定任务的更高完整性要求，按该任务明确要求验收。

清洗使用DOM解析和标签白名单，删除属性与空标签；政策板块依实际结构识别，正文或书名中出现reviews／shipping等词、篇幅很短均不单独构成删除理由。HTML摘要列表与完整描述分开，预览不执行不可信脚本。名称兜底只用于展示或解释旧版本结果，不写入 `description_html`，不作为新标准的描述补全方法。

### 与旧版商品描述对齐

[旧格式导出样例](示例/法国运动用品数据导出样例.csv)的`Description`包含营销正文、`Informations complémentaires`规格表、空`span`和嵌套`p`。本系统按以下口径对齐：

- 营销正文和规格表都保留在`description_html`中，按原站顺序输出；规格表不拆入`attributes`，也不因板块标题含“Informations”就删除。
- 清理空`span`、`data-*`节点、脚本、样式和表单；修复嵌套`p`等无效结构；保留`br`、列表、表格和强调。
- `attributes`只表示可购买选项，例如`Taille#S/M|L/XL`；规格表中的Marque、Couleur、Genre、Age等不进入`attributes`。`attributes`是下游参考字段，不能替代描述。
- 旧格式的`Attribute 1 name=mycustom`是占位，真实维度名在`Attribute 1 value(s)`中，按值串保留。

以样例结构为例（正文省略）：

清理前：

```html
<span> </span><p><p>商品正文…</p><p>LES DÉTAILS…</p></p>
<span>Informations complémentaires</span>
<table><tr><td>Marque</td><td>Odlo</td></tr></table>
<div data-prodtagid="..."></div>
```

清理后：

```html
<p>商品正文…</p>
<p>LES DÉTAILS…</p>
<p><strong>Informations complémentaires</strong></p>
<table><tr><td>Marque</td><td>Odlo</td></tr></table>
```

## 分类、选项与字符

- 分类内部去首尾空白、大小写不敏感去重并保留首次形式与顺序；导出选择一个有意义类别，排除仅Home／Shop以及Women／Clothing等泛层级，不按字符串分隔符机械截断。用户的任务归属不等于原站分类。
- 选项是维度和值，例如Size的S／M、Color的Red／Blue；只保留公开选项，不构造全部组合，不采每个规格价。
- 忽略Quantity／Qty／Cantidad／Quantité／Menge／数量等购买数量组、附加差价和空占位；同名组大小写不敏感合并，值大小写不敏感去重，保留首次形式与顺序。移除末尾`+$2.00`、`EUR 5,00`等差价，空组不进入数据。点击跳到另一商品页不构成丢弃当前公开选项的理由。
- 按响应编码、JSON解析、HTML实体及实际字段格式解码，不连续反转义猜正文。清洗正文用结构化解析，不用全局正则拼接。
- 可缺字段留空且注明必要原因，不猜品牌、币种、选项或销售单位。原站未提供与有值却漏采分开。

名称清理仅针对来源主机明确等价的独立域名片段，可识别大小写、www和国际化域名等价；不顺手删除其他域名、邮箱、含路径URL或猜测品牌。销售单位保留原语言及明确数量，只在当前价相邻证据成立且正文未说明时补首段，不从Shipping、重量、包装尺寸或数量控件推算，也不拿单位代替正文。

类别有值时不同时报告缺失；缺失理由可区分未找到、未提供、不适用。旧内部占位`!`不进入标准分类。明确的Size／Color扁平来源可映射为结构化选项，无依据不从名称或SKU猜测。

## 导出与留存

最终业务CSV固定为9列，列顺序固定：

| 列 | 内容 |
| --- | --- |
| `name` | 商品名称 |
| `price_amount` | 当前主商品最低公开展示价，数值 |
| `price_currency` | 同一报价的 ISO 4217 三字母币种 |
| `primary_image_url` | 主商品图片 |
| `description_html` | 清洗后的商品正文；最终CSV统一输出HTML |
| `category` | 一个有意义分类 |
| `brand` | 原站明确提供的商品品牌，可空 |
| `attributes` | 内部`options`的兼容序列化 |
| `source_url` | 商品原链接 |

CSV只承载业务核心字段，不携带任务、方案、市场、语言、库存、税价口径、描述状态和缺失原因等追溯列。完整规范化记录、质量字段和追溯信息保存在内部存储中；导出侧通过任务结果和诊断文件保留可核对信息，不要求在CSV每行重复。此前按旧版22列导出的历史结果按原合同解释，不追溯改写；新导出一律使用上述9列。

系统不直接生成旧版12列导出；旧格式的SKU、Regular/Sale价格拆分、Tags、Images文件名和`Attribute 1 name`等列由后期独立程序基于9列输出和内部记录转换。转换所需信息以`description_html`和结构化`attributes`为准，系统不得为压缩导出丢失描述结构或选项。

裸文本源的正文在最终CSV中按段落转义包装为HTML；内部记录仍可保留来源载体和`description_format`，消费方不需要从CSV猜测格式。

任务结果`task-result.json`至少保留任务级`task_id`、`plan_id`、`plan_version`、`market`、`locale`、`counts`、`coverage`、`stop_reason`和`business_acceptance`。有效商品中存在正文非完整或缺失原因时，增加`quality_exceptions`数组，按`source_url`列出`description_status`、`partial_reason`和`missing_reasons`；完整且无缺失的商品不重复列出。结构按[任务状态与计数契约](09-任务状态与计数契约.md)。

排除、失败和待处理商品继续使用独立诊断清单，保留`source_url`和原因；零价、无价、重复、范围外与技术失败分别说明。

CSV的`attributes`是内部`options`的兼容序列化，不是第二套业务字段；解析时按转义规则还原，内部仍保留结构化选项。

`missing_reasons`和`partial_reason`在任务结果中按JSON规则引用和转义；JSON字符串内的双引号按JSON规则双写，不得手工拼接。市场、语言、库存和缺失原因随内部商品记录保留，消费者不应假设它们只存在于任务元数据。

兼容属性串采用诸如`Size#S|M~Color#Red|Blue`这样的形式；内部保持结构化。保留字符`\`、`#`、`|`、`~`以反斜杠转义。CSV引号、逗号、换行和中文按标准编码，不丢HTML；面向表格软件时处理不可信单元格公式风险。

具体转义为`\`到`\\`、`#`到`\#`、`|`到`\|`、`~`到`\~`。面向表格软件默认给以`=`、`+`、`-`、`@`开头的不可信文本单元格添加单引号等保护；面向可信机器消费。金额按数值格式输出，避免将有效正数当文本公式。
