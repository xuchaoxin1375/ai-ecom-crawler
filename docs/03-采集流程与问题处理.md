## 从业务目标到有效结果

按步骤交接，允许发现与商品处理有界交错；**构建、验证、执行和评价分别承担职责**。更多分析方法见[方法目录](方法指导/README.md)。

| 步骤 | 操作 | 交付与推进条件 |
| --- | --- | --- |
| 确定目标 | 保存原入口、范围、市场／语言、资源边界及数据口径 | 可追溯任务；不是只记录一个域名 |
| 最少取证与规划 | 验证入口内容；适用方案先复用，否则Agent尽早分析目录／语言／分页 | 有依据的方法或明确缺什么，不等全部网址建好才首次介入 |
| 实体与深度 | 明确计数单位、身份键、页面层级和主数据源；抽样估算请求与时间 | 有实体模型和深度决策；预算内可完成，或明确收窄／部分交付 |
| 发现目录 | 判断sitemap、HTML索引、公开目录、基础分类和后续页面；先保留导航与商品候选，再按内容判型和身份去重 | 持久网址及剩余入口；样本足够不等于发现结束 |
| 获取商品内容 | 核商品身份、内容有效性、动态就绪和必要交互 | 真实输入及来源摘要，200不能单独证明成功 |
| 构建与试跑 | 按字段选择来源、覆盖模板差异，实际试跑和有界修订 | 可保存方案，完整字段与例外清晰 |
| 离线及真实灰度 | 固定真实样本对照，再走小范围实际网络／浏览器链路 | 通过数据与执行验证，失败不能靠改期望洗绿 |
| 持续执行 | 框架按方案发现／获取／提取、接纳结果并记录检查点 | 普通批次无逐页模型调用，错误分类可见 |
| 交付与维护 | 导出有效数据、停止原因、限制；变化后修复和复验 | 原目标与历史可追溯，不让用户拼接多个新任务掩盖失败 |

## 目录和完成判断

1. 有未访问的有效分类／品牌／型号分支、下一页或持续带来新商品的动作时，在原边界内继续。
2. 一个分支无新增不结束其他分支；用身份去重和分页状态避免循环。
3. 队列结清且无后续动作可报告自然结束，不要求先证明全站总量。
4. 超时、预算、权限不足或访问失败属于保护性停止，保存进度并说明未完成。
5. 用户认为覆盖基本满足业务需要时，可明确验收或更改业务处理状态；同时保留系统实际停止原因、未处理数量和覆盖未知事实。

**人工满意度不能覆盖采集事实。** 例如“用户已验收，范围未知，因预算停止，仍有12个待访问分类”可以同时成立；不能自动改成“目录自然耗尽／整站100%”。任务状态、计数和覆盖的机器口径见[任务状态与计数契约](09-任务状态与计数契约.md)。

## 采集深度

采集深度是业务决策，不是框架默认。列表／型号层已能提供名称、编号、价格、状态等核心字段时，不为同一字段逐条下钻详情；详情页只补正文、规格、兼容关系等独有字段。

默认先保证基础字段：身份与来源 URL、名称、价格与币种、状态、主图和描述存在性。完整正文与规格、兼容关系、选项变体、文档和全量覆盖属于进阶项，任务未要求时不默认下钻。

全量详情前先抽样比较“浅层已有字段”和“详情新增字段”，并估算请求、下载量和时间。超出预算时，按“减少深层请求 → 收窄范围 → 降低字段目标 → 最后才提高并发”的顺序调整；保留核心字段并标明未补字段，不能伪称完整。具体预算方法见[任务验收与效率](方法指导/05-任务验收与效率.md)。

## 故障分流

先定位失败层，使用最小有用证据比较，一次改变一个关键条件。错误和责任归属清楚后，再决定是否需要Agent修方案。

| 现象 | 检查 | 行动与结束边界 |
| --- | --- | --- |
| 依赖或浏览器无法启动 | 实际运行解释器、浏览器、代理客户端及加载版本 | 修运行环境，不把本机问题归因网站或模型 |
| 403／挑战／空壳 | 同一网址的最终位置、有效正文、客户端与出口 | 有界比较；按检测维度选择路线，避免盲目叠引擎 |
| 429 | 并发、速率和等待提示 | 降速、退避，耗尽边界报告访问受限 |
| 成功状态码但通用错误页 | 标题、主内容容器和稳定字段 | 判无有效商品内容，不把空壳当原站缺字段 |
| 404／410且无挑战特征 | 网址、站点可见性，必要时同会话对照页 | 资源级结论，不无限换引擎 |
| 手动浏览器成功、自动化失败 | 驱动／控制面、浏览器身份及会话差异 | 按证据试另一控制方式或合法复用会话，不能仅推断IP一定差 |
| 临时脚本成功、正式执行失败 | 环境、配置、会话、真实加载版本 | 修正式链路，用同一链路复验 |
| 内容有效但没有网址 | sitemap形状、分类入口、页面类型和过滤 | 修发现逻辑；不因陌生路径排除商品 |
| 网址多却商品少 | 导航／商品区别、待处理／在途／失败和重复身份 | 先对事实，不把所有请求数当商品数 |
| 列表／型号页已有字段仍逐条抓详情 | 字段来源层级、详情增量字段、每有效商品请求数 | 改为浅层取数或按需详情，停止重复抓取 |
| 停售／无价格／占位图被当失败 | 状态语义、图片占位特征、数据标准 | 分开记录可售／缺货／停售／无价格／原站未提供，不混入技术失败 |
| 同一实体多个网址或父级上下文 | 业务键、canonical、父子关系 | 按业务键合并，不把型号上下文当多个商品 |
| 页面很大但有效行少 | 主容器、列表行密度、是否整页解析 | 只取主容器和行级片段，避免重复导航与脚本 |
| 数字／陌生路径被当非商品 | URL 形态假设、样页标题和结构化数据 | 抽样验证后再判型，不按关键词或后缀删除 |
| sitemap 解析失败／403／HTML | 状态、`content-type`、gzip、robots 的 `Sitemap:` 行 | 先修解析或判访问限制，不直接判“无 sitemap” |
| 分页重复或停止过早 | 游标、下一页、去重及剩余分支 | 修循环或过早结束；保留停止依据 |
| 价格错误 | 商品归属、原价／分期／差价、币种和税价选择 | 按数据合同修复，明确实际口径 |
| 描述不全 | 摘要、展开区块、规格表、清洗误删 | 优先补齐；复杂难取区块有界尝试后可标部分，不能伪称完整 |
| 源码无描述／主图／状态但页面可见 | 主容器、展开区、JS 渲染、占位资源 | 截图核对可见状态；仍无内容按原站未提供或占位记录 |
| 型号／颜色／尺码漏采 | 控件、当前商品JSON与模板差异 | 修公开选项，不扩全部组合价格 |
| 乱码或字面转义 | 字符集和实际数据格式 | 依格式解码，不机械重复替换 |
| 市场／语言不符 | 原入口、公开市场选择、报价绑定 | 取目标上下文或明确未达标，换汇不能替代 |
| 模板变化 | 失败字段、影响模板和旧数据 | 阻止错误扩散、标明有效性，修复后重新灰度 |
| 任务看似不动 | 实际工作、队列、阻塞、模型与工具活动 | 不能仅用心跳或安静时间推断进展；按实际诊断处理 |
| 达到上限 | 剩余工作、停止原因、结果有效性 | 可导出有效部分，保留未完成，不自行加预算 |
| 登录／付费／私有数据 | 访问边界与目标范围 | 停止并说明；公开挑战按 [ADR 0022](adr/0022-挑战页处理边界.md) 恢复，但不扩为绕过登录、付费、年龄门或地区限制 |

## 修复后续接

1. 保存网址、字段／动作、方案版本、错误类型和必要证据摘要，脱敏日志。
2. 区分暂态访问、输入环境、明确不满足商品要求、方案错误和站点变化。
3. 修最小实际问题，检查同类模板或入口；需要Agent时提供真实反馈，不只反复换模型。
4. 按原目标验证方案及失败场景，进行真实灰度，清楚标明部分内容及例外。
5. 按影响处理旧结果有效性，再继续原目标；保持历史，新时点／新范围另建任务。

观察超时只表示这次查看结束，不表示后台已停止。取消必须实际结束自建执行与资源；不能让迟到结果重新写入已取消任务。任务状态、计数与迟到结果处理按[任务状态与计数契约](09-任务状态与计数契约.md)执行。

## 不支持与跳过的说明

登录／付费访问、无稳定公开商品、主要自由定制、指定市场不可得、预算耗尽、人工拒绝或明确政策限制均须分别留因。公开挑战按 [ADR 0022](adr/0022-挑战页处理边界.md) 和实际获准能力先有界恢复；不能未尝试已有适用能力就宣称永不可采，也不为单站无限安装或轮换工具。技术故障、暂态受限和待恢复保持未完成事实，跳过不将其改成全量成功。自动决定记录原因码和证据摘要，不要求用户每次补备注才能推进。

需要离线重新提取时，先确认原文确实保留且路径支持；默认无正式原文时不承诺该能力。新时点重采、旧结果纠错和原进度恢复分别处理。
