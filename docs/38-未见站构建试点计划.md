# 未见站构建试点计划

## 用途与边界

本计划落实[设计与现状评审](00-项目定位与可行性.md#设计与现状评审) P1 的“未见站构建成功率与成本”试点：用 3 个未进入过构建会话的公开商品站，在固定模型、固定范围和固定预算下各跑一次构建，再看规则执行和字段质量。

- 本轮只判断“是否值得扩大站点范围”，不外推通用成功率，也不把单站结果写成长期稳定性结论。
- 不把构建 Agent 的自述当验证；主机验证、任务结果和人工抽检分开记录。
- 不登录、不付费、不绕过访问控制、不采集个人信息；只用公开商品页。
- 本计划是 Proposed。执行前需要项目方确认模型费用上限和隔离环境；未确认时不发起付费调用。

## 试点站点

“未见站”指没有进入过构建会话、没有已安装规则、构建 Agent 未读取过站点记录的站点。以下站点只有可达性和商品页探测，没有构建证据；探测结论不提供给构建 Agent，不作为选择器或字段答案。

| 站点 | 市场／语言 | 平台与路径 | 难度 | 2026-11-24 预检 |
| --- | --- | --- | --- | --- |
| `stragier.com` | FR／fr-FR／EUR | 自定义/PrestaShop 风格静态 HTML；分类列表 → 商品页 | D1 简单 | 分类页 200，25 个商品链接；样例商品页 200、463KB、1 个 JSON-LD 块、价格和描述可见；根路径可达 |
| `babybubblestore.com` | FR／fr-FR／EUR | Shopify；sitemap index → 商品 sitemap → 商品页 | D2 中等 | 首页 200、563KB、6 个商品链接；sitemap index 131 个 `<loc>`；样例商品页 200、538KB、Product JSON-LD；普通 HTTP 会 429，浏览器指纹客户端 200 |
| `bybebe.com` | FR／fr-FR／EUR | BigCommerce；分类页商品卡 → 商品页 | D2 中等偏难 | 分类页 200、763KB、30+ 商品链接；样例商品页 200、774KB、Product JSON-LD 和价格可见；首页曾达 69.7s，需放宽单页超时 |

选择理由：

- 三个站点分属三种平台形态：自定义/PrestaShop 风格、Shopify、BigCommerce。
- 覆盖两条主要发现路径：分类列表和 sitemap index；不重复 D01 已用的 `familidoo`、`skatepro`、`sixmoondesigns`、`shopthebulkstore`、`campsaver`。
- 三个站点同为 FR／EUR，市场门禁和价格口径一致，便于比较构建成本；代价是本轮不能代表其他市场。
- `babybubblestore` 的 429 和 `bybebe` 的大页面是预期难点，不隐藏、不因失败换站。

## 固定条件

### 模型与版本

| 项 | 固定值 |
| --- | --- |
| 模型 | `opencode-go/deepseek-v4.1-flash`，variant `high` |
| 构建 Agent | 当前 `opencode serve`；执行时记录 OpenCode 版本 |
| 应用版本 | 执行时记录 `git log -1` 和 `app` 工作区状态 |
| 自动修复 | 1 轮；`ECOM_BUILD_REPAIR_SECONDS=240` |
| 规则激活 | 使用账本和规则目录副本；允许初始构建在副本内自动激活，不碰真实账本 |
| 运行期模型 | 0；执行任务只读候选规则 |

模型或 provider 不可用时停止并报告，不静默切换模型、渠道或代理。启用了[构建模型池](37-构建Agent-Harness集成与使用说明.md#构建模型池)时，提交试点构建要显式指定 `model_ref=opencode-go/deepseek-v4.1-flash#high`；也可在试点专用进程不配置模型池，保持本计划的固定模型。

### 预算

| 阶段 | 单站预算 | 停止条件 |
| --- | --- | --- |
| 构建 | 请求 `max_products=6`、`max_seconds=600`、`repair_rounds=1`；服务配置 `ECOM_BUILD_MAX_PRODUCTS=6`、`ECOM_BUILD_MAX_REPAIR_ROUNDS=1`、`ECOM_BUILD_VALIDATION_SECONDS=120` | 目标是单站 20 分钟硬停，包含启动、自动修复和主机验证；现行分阶段超时不能替代整站硬停 |
| 模型用量 | 建议上限 500,000 input tokens／50,000 output tokens | 达到上限停止；供应商账单金额上限待项目方按当前价格确认 |
| 执行验证 | 10 个商品、180 秒、`max_attempts=2`、`per_domain_rps=1` | 10 个商品或预算耗尽即停 |
| 人工抽检 | 每站 10 分钟 | 超时未检查的字段记为未测，不补写成通过 |

三站合计上限约 2.5 小时（构建 60 分钟、执行 9 分钟、人工 30 分钟，另留重试和记录时间）。模型费用上限在项目方确认前不执行付费阶段。

**付费试点启动前仍须验证预算能执行。** 构建请求的 `max_products` 写入构建简报，主机验证取服务端的 `ECOM_BUILD_MAX_PRODUCTS`；两边都要设为 6。`max_seconds` 约束初始会话，自动修复和主机验证另计。当前没有覆盖启动、验证和进程回收的整站硬停，也没有自动按 token 或金额取消构建的门禁；构建追踪记录用量不等于能实时拦截账单。先在试点专用环境用无模型用例验证整站停止及回收，再确认供应商侧硬上限或可执行的限额方案；不可把人工查看日志当作硬上限。

**单站判定不只读 `PASSED`。** 当前应用的主机验证通过不等于达到本计划的 6 件且 0 失败；需另核对 `candidate_smoke.valid_products`、`candidate_smoke.failed_products` 和币种样本。初始构建允许在副本内自动激活，但未达试点通过线的规则不进入执行验证，也不带出副本。

### 网络与隔离

- 默认静态 HTTP + 浏览器指纹客户端；先固定一个同市场出口，构建、主机验证和执行验证沿用。`babybubblestore` 的 429 先按 `Retry-After` 退避一次；仍失败时可测试最多两个同市场出口或切 browser engine，选定后固定到该出口并记录，不逐请求轮换，也不跨市场换出口。允许轻微价格浮动，但币种必须与批次市场一致。
- 库存／可售状态不是本轮业务必需字段；不以 `OutOfStock` 阻塞商品，只校验价格和币种。变体库存只作证据，不作为通过条件。
- 不使用 headless／有头矩阵轮换，不因单站失败切多个代理或改变出口地区。
- 单页超时按站点放宽：`bybebe` 产品页 60 秒，其他站点 45 秒；并发 1。
- 优先在独立低权限账号或专用 VM 运行构建；无法提供时记录 `isolation=not_satisfied`，本轮只作方法验证，不据此扩大试点。隔离要求见[构建环境与依赖基线](20-构建环境与依赖基线.md#受控试点的构建隔离)。

### Shopify JSON 优先

- Shopify 店铺默认先取公开 `/products.json` 的价格、币种、变体和描述，再决定是否需要 HTML；商品 `.js`／`.json` 单商品提取仍作为后续路径，当前未实现。
- 只有 JSON 被挡、描述为空或描述明显少于渲染页时，才回退 HTML／浏览器；回退时并发控制在 1–2，不因回退放大请求。
- 库存／可售状态不作为本轮通过条件；价格和币种必须与批次市场一致。
- 当前 `app` runtime 已实现 `product_source: shopify_json`（`schema_version: "1.3"`）：`/products.json` 负责枚举和字段映射，描述达到 `description.min_chars` 时直接提交，不足或 JSON 被挡时回退 HTML／browser；商品 `.js`／`.json` 单商品提取仍未实现。见 [ADR 0020](adr/0020-shopify-json产品源.md)。

### 人工介入

- 构建阶段不允许人工改规则、补选择器或修改字段；自动修复轮次属于构建过程，单独记录。
- 首次构建失败后，是否“继续失败会话”由项目方决定；若执行，作为第二轮单独计时、单独计量，并标记为人工辅助，不混入首次成功率。
- 执行验证只修运行错误（如网络重试），不按站点改规则；需要改规则时按失败记录。

## 执行步骤

1. **准备副本**：复制试点账本、规则目录和输出目录；确认不写真实账本，记录副本路径和哈希。
2. **逐站预检**：每站只做 robots `Sitemap:` 行、入口/分类、1 个商品页的只读检查；确认市场、币种和商品可访问，失败即标记未测，不继续消耗构建预算。
3. **首次构建**：按固定模型和预算启动；记录 build ID、开始/结束时间、阶段事件、工具调用、tokens／费用、自动修复轮次和主机验证。
4. **候选检查**：核对主机验证是否有 6 个有效商品、0 失败，记录币种、描述审计、规则哈希和版本；验证未通过、证据不完整或未达本计划通过线时，不进入执行验证。
5. **执行验证**：用候选规则跑 10 个商品的 product 任务；记录有效、排除、失败、请求数、墙钟、CSV 行数和运行期 LLM 调用（必须为 0）。
6. **人工抽检**：每站抽 10 个商品核对名称、价格、币种、主图、来源 URL、描述状态和分类；记录缺失字段的原站原因，不把可空字段计入失败。
7. **收口**：写每站小结和三站汇总；失败站保留原始记录，不删除、不替换成更容易的站。

## 失败分类

| 分类 | 判定 | 处理 |
| --- | --- | --- |
| `ACCESS` | 入口、分类或商品页在预算内不可访问；429／403／挑战未解除 | 记录出口、客户端、请求数和停止原因；不继续构建 |
| `DISCOVERY` | 找不到足够商品 URL，或分页／sitemap 枚举失败 | 记录来源、请求数、候选数和停止原因 |
| `EXTRACTION` | 商品页可访问但名称、价格、币种、主图或 URL 缺失 | 记录字段和页面样例，不猜测字段 |
| `BUDGET` | 达到时间或 token 上限 | 取消并记录阶段和已用量 |
| `MANUAL` | 需要人工改规则或继续会话才成功 | 不计入自动构建成功，单独报告 |
| `RUNTIME` | 候选规则可激活，但执行任务失败或计数不一致 | 记录任务 ID、失败分类和样本 |

## 成功与决策

| 结果 | 条件 | 决策 |
| --- | --- | --- |
| 通过 | 3/3 首次构建 PASSED（允许 ≤1 轮自动修复），执行 10/10 有效、0 失败，抽检通过，未超预算 | 进入下一阶段：扩大站点范围或做容量／恢复复验 |
| 有条件通过 | 2/3 通过；失败站有明确分类和一次可解释原因 | 只针对失败原因修指导或环境，按同一预算重跑失败站一次；不扩大站点范围 |
| 未通过 | ≤1/3 通过，或出现人工改规则、越权、账本污染、运行期模型调用 | 停止扩大；先修构建指导、验证门禁或环境，重新评审 P1 |

补充规则：

- 失败站和失败字段不删除；“通过率”按 3 个站点计算，不按成功商品数计算。
- 首次构建成功但执行失败，仍算该站未通过。
- 超预算即未通过，不因商品可用而豁免。
- 隔离未满足时，结果标记“受控但未隔离”，不得用于生产或扩大试点承诺。

## 记录与证据

证据放在仓库外 `workbench/build-pilot-2026-11-24/`，按站点分目录：

- `probe.json`：日期、地址、客户端、出口、状态、字节数、耗时、robots `Sitemap:` 行和停止原因。
- `build/`：构建记录、trace、消息、自动修复轮次、tokens／费用、候选规则和哈希。
- `validation/`：主机验证摘要、样本、回归、描述审计和证据哈希。
- `execution/`：任务结果、`products.csv`、`records.jsonl`、排除／失败诊断。
- `spot-check.md`：10 个商品的字段核对和原站缺失原因。
- `notes.md`：人工介入、重试、代理、异常和未测项。

不提交 CSV、整页 HTML、截图、trace 和运行期数据库；仓库只保留本计划、脱敏汇总和复验命令。

## 待确认

- 模型费用上限：按当前供应商价格，三站合计可接受的上限是多少；未确认前只做预检和方案准备。
- 隔离环境：是否有独立低权限账号或专用 VM；没有时是否接受“受控但未隔离”的方法验证。
- 是否允许首次失败后人工继续一次；如允许，确认它只作为单独的第二轮，不计入首次成功率。

## 离线预演

本地集成测试只使用临时账本、规则目录、回环商品服务和假构建适配器。先准备[后端开发环境](23-测试策略.md#后端测试怎么跑)，从仓库根运行。命令复用现有环境，不联网安装依赖，不提交模型请求，也不读取或复制正式账本。

```powershell
python -X utf8 -m uv run --offline --project app --extra dev --frozen --no-sync python -X utf8 app/tests/run.py build -k pilot_rehearsal -k per_build -k child_environment -k server_process_manager
```

- **流程通过条件**：集成测试先交付无效选择器，再用同一会话自动修复一次；主机验证须为 6 件有效、0 失败，任务须用账本中的同一规则哈希完成 10 件有效、0 失败。批次压缩包内的九列商品表和任务结果须与任务目录逐字节一致，并且核对固定商品的价格、币种、主图、描述和来源。
- **代码级边界**：单次初始会话超时后应取消；全局默认值较短时，不得提前取消有更长单次预算的构建。真实测试子进程只收到允许继承的变量和显式传入值，不收到测试注入的宿主变量。该检查不代表低权限账号或虚拟机的隔离已验证。
- **未覆盖**：三站的访问、模型认证、模型用量与费用、首次构建成功率和人工抽检均未执行。合成站点使用英国市场和英镑，只验证字段与市场口径的传递，不证明法国试点结果。命令非零时先看失败用例，不启动付费试点。

## 2026-11-25 执行结果

本轮按确认的边界执行：固定模型 `opencode-go/deepseek-v4.1-flash#high`，固定欧盟出口 `127.0.0.1:17216`（实测 `103.82.101.241`／FR／CDG），独立账本 `b-8132e0c77f95`，每站 500,000 input／50,000 output token，受控但未隔离，不允许人工继续。证据在仓库外 `workbench/build-pilot-2026-11-25/`。

| 站点 | 首次构建 | 自动修复 | 主机验证 | 执行验证 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `stragier.com` | 761s，83 次工具，0 工具失败 | 1/1，解决 `discovery.strategies` 不支持 `sitemap` | `PASSED`，6 件有效、0 失败、EUR | 10/10、0 失败、25s；抽检 10/10 核心字段一致 | 通过 |
| `babybubblestore.com` | 601s，34 次工具，规则已写出 | 未开始 | 未执行 | 未执行 | 未通过：`BUDGET` |
| `bybebe.com` | 602s，65 次工具、858 段 reasoning，未写出规则 | 未开始 | 未执行 | 未执行 | 未通过：`BUDGET` |

`stragier` 的 tokens 为 input 382,756／output 18,837／reasoning 22,725，output + reasoning 已占 50,000 上限约 83%；`baby` 和 `bybebe` 取消时 OpenCode export 为空，旧 trace 没有 tokens，已补 usage 事件保留和 trace 回退，但本轮结果仍按当时证据记录。

### 重跑（900 秒初始预算 + 修补后的简报）

首轮结束后，按项目方确认的“先补 browser 与 skill，再重跑”执行了两站，仍使用同一账本、固定模型和每站 500,000 input／50,000 output 上限；这是单独的重跑轮，不混入首轮首次成功率。

| 站点 | 构建 | 自动修复 | 主机验证 | 执行验证 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `babybubblestore.com` | 916s，41 次工具、1 次失败 | 0/1 | `PASSED`，但 `valid_products=1`、`BUDGET_EXHAUSTED`；120 秒 browser 验证跑不完 6 件 | 6/6、0 失败、约 166s；1 件描述 partial；规则只发现入口页 6 个链接 | 构建通过、验证样本不完整，未达 10 件执行通过线 |
| `bybebe.com` | 929s，66 次工具、0 失败 | 1/1，解决入口页发现为零 | `PASSED`，6/6、0 失败、EUR、描述审计 0 缺口 | 10/10、0 失败、约 20s；抽检 10/10 名称／价格／币种／主图一致 | 通过 |

`baby` 的静态商品页持续 429／`Verify your browser`，商品 `.json` 端点返回 403；真实 Chromium 200，因此规则声明 `default_engine: browser`。这验证了 browser 回退路径，但也暴露 120 秒主机验证预算不足。`bybebe` 首次验证为 0 件（入口页发现为零），自动修复后改为 listing 入口，6/6 通过；执行 10/10。

### 判定

首轮为 **未通过**（1/3）；重跑轮为 **有条件通过**（2/3 完整：`stragier`、`bybebe`；`baby` 构建通过但验证 1/6、执行 6/6）。不扩大站点范围，不把结果用于生产承诺。未执行人工继续，未在真实账本上启动、取消或归档任何任务。

### 根因

- **规则契约信息不足**：构建简报只写“use sitemap”，reference rule 只有 `entry_links` 示例；`stragier` 因此把 sitemap 写成 `discovery.strategies`，触发 1 轮自动修复。`bybebe` 的 reasoning 显示它长时间在猜 fallback 类型、`canonical` 语义和 `audit.blocks`。
- **构建任务币种占位错误**：`build-task.json` 对 FR 批次硬编码 `USD`，`bybebe` 自己发现并纠正；这会误导模型。
- **挑战站缺少早停**：`baby` 的页面多次出现 “Verifying your connection”／“Verify your browser”，静态路径重试消耗了预算；预检 200 不能代表构建期稳定。重跑切 browser 后构建通过，但验证时间不足。
- **预算语义不透明**：600 秒是初始回合，1,200 秒是整站上限；简报只写 600。首轮两个失败站都在 600 秒被截断，总预算未用。
- **验证样本与执行目标不一致**：构建验证采 6 件，执行要求 10 件；`baby` 和 `bybebe` 的入口页只暴露 6 个商品链接，规则没有主动扩大发现，导致执行只能 6 件或需要额外 listing。
- **供应商不是主要瓶颈**：固定模型探测 5.9 秒，`stragier` 83 次工具 0 失败，没有 provider error event；耗时主要来自站点访问、挑战页和规则 schema 探索。
- **Shopify JSON 路径**：`baby` 的商品 `.json` 返回 403，原 runtime 的 `public_json` 只用于发现，产品字段仍从商品页提取；本轮已补 `/products.json` 产品源和描述回退，真实 Shopify 店铺尚未验收。

### 已修补
