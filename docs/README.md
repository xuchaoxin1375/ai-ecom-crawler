## 用途与适用范围

**本项目业务核心正文。** 统一说明要构建的产品数据采集应用要解决的问题、数据标准、采集流程、方法、交付及验收。只在这里维护这些要求；项目技术文档负责具体接口、已选方案、运行限制及实现进度。项目层的定位、可行性与改进路线先读 [项目定位、可行性与改进路线](00-项目定位与可行性.md)，再按 01～09 进入业务规则。

本目录随业务确认持续更新，不另维护其他地方。

## 共同开发与交付

1. 先提交对业务要求的理解、技术方案、主要风险和分阶段计划，标明本次承诺的范围；通用任务编号不是实际开发状态。
2. 优先完成**AI生成完整方案、框架脱离AI独立执行、输出合格结果、同方案复跑**的核心闭环。
3. 补齐另一兼容环境复用、代表网站类型、必要隔离与故障处理，再交付可用的管理及预览功能。
4. 每阶段用[开发任务](04-开发任务与交付.md)和[验收场景](05-验收场景与比较方法.md)提交证据、限制和下一步，不能只交截图或模型自报结论。

框架、数据库、编程语言、Agent后端、前端和任务内部调度均可提出不同方案。固定的是业务结果、数据含义和状态真实性。技术选择应说明适用范围与维护代价，不把设计报告当作已经运行验证。当前 v1 的提议见[技术栈与运行形态 ADR](adr/0001-技术栈与运行形态.md)，它需要 D01 验证后才能确认。

## Skill材料与上游参考

业务相关Skill的方法在本目录内作为普通文档维护。开放的`resilient-browser-fetch`以方法摘要形式进入[浏览器与获取指导](方法指导/04-浏览器与会话复用.md)，本目录不附源码副本；需要核对实现时，按上游当前版本获取并验证。它不是自动跟踪上游的第二份Skill真源。

上游实现保留其自身许可与版本节奏；本文档只保留可迁移的方法判断。采用代码前由新组按自己的执行接口、依赖和资源政策验证；引用上游能力不表示已经与其实现集成。

## 分发与完整性

复制本目录的全部文件并保留结构即可独立阅读，正文链接全部在目录内。正式分发通过仓库的离线导出命令（仓库根`scripts/export_docs.py`）生成ZIP与`manifest.json`，源目录不保存需要手动刷新的主清单或另一份业务正文。生成的清单列出源文件大小与SHA-256；校验值用于检查传输一致性，不提供数字签名。

每次发放的是该时点的版本快照；修改从本目录开始，再重新导出，不回头编辑已经发出的副本。仓库命令与文件边界由项目文档入口说明，核心正文无需原仓库或本机路径也可阅读。

本文档不附真实商品网页原件、生产数据库、密钥、已登录会话或浏览器二进制。测试场景和合成示例随包附带，真实站点在获准环境重新取证。正式运行默认不保存整页原文，不能将源码工具的保存示例解释成采集任务默认留存政策。
