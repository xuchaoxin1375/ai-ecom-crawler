## 用途与边界

本文给出普通电商商品页的**基础采集模板**：先复用一套常见的发现、字段和清洗顺序，再按站点覆盖少量差异。目标是降低首次接入时间，不是承诺所有站点一套规则通吃。

当前阶段只比较**首次采集**：首次构建、首次有效结果和随机抽查质量。维护、漂移修复、长期稳定性暂不纳入本轮（J08）；但方案仍要保存，方便以后修。

## 背景：旧流程的时间基线

项目方经验：相对简单的站（如 familidoo）用基础模板几分钟甚至更快，名称、图片、分类、描述 XPath 首轮即可命中，基础清洗也已内置；普通或复杂难度站点通常约 10 分钟。AI 驱动的首次构建起步通常更高，时间不设硬性胜负（J09）；目标是结果可接受、方案留下，效率通过模板和指导逐步优化。

新流程要证明的不是“能不能抓”，而是：

- 首次接入能否产出可用的 9 列结果；
- 随机抽查是否通过；
- 方案是否留下、能否复用；
- 时间是否在可接受范围，并随模板和指导逐步下降。

如果新流程每次都要写站点专用 runner，它就没有继承旧流程“基础模板”的优势；模板必须优先，定制只做少量覆盖。

## 字段回退顺序

按顺序尝试，命中即停；记录实际来源，便于诊断。不同站点可以有例外，但不要为单站改公共顺序。

| 字段 | 回退顺序 | 备注 |
| --- | --- | --- |
| `name` | JSON-LD `Product.name` → `h1[itemprop="name"]` → `h1` → `og:title` → `<title>` | 从标题取时去掉站点名后缀；不要保留 `Shop - Product` 这类前后缀 |
| `price_amount` | JSON-LD `offers.price` → `product:price:amount`／`product:pretax_price:amount` → `[itemprop="price"]` → 主价格容器 | 同报价有含税／未税时取较小者并记录口径；不取划线价、分期、运费 |
| `price_currency` | 同报价的 `priceCurrency` → `product:price:currency` → `[itemprop="priceCurrency"]` | 不从符号、域名或语言猜 |
| `primary_image_url` | JSON-LD `image` → `og:image` → 主商品图容器 | 不取 Logo、占位图、推荐图 |
| `description_html` | JSON-LD `description` → `#description`／`.product-description` → 商品详情标签页 | 清洗后保留正文和规格；区分完整／部分／未提供 |
| `category` | 面包屑最后一个非首页项 → JSON-LD `category` | 站点分类不一定等于业务分类；原样记录，必要时另做映射 |
| `brand` | JSON-LD `brand.name` → manufacturer 元素 → 可见品牌字段 | 未公开就留空，不从商品名猜 |
| `options` | 变体 JSON → `select`／radio 组 | 只取公开可选项；不枚举全部 SKU 组合价格 |
| `source_url` | `canonical` → 最终 URL | 去重和追溯用 |

## 常见平台线索

| 平台／形态 | 线索 | 首轮优先检查 |
| --- | --- | --- |
| Shopify | `Shopify.currency`、`/products.json`、`variants` | 公开 JSON 列表；JSON-LD 可能重复，主题块优先 |
| WooCommerce | `data-product_variations`、`display_price` | 变体 JSON；价格可能是十进制而不是分 |
| PrestaShop | 无 JSON-LD 很常见；`product:price:amount`、`product:pretax_price:amount`、`#description` | meta 价格、面包屑、描述容器 |
| Magento | `jsonConfig`、`optionPrices`、`salable` | `salable` 空不能判缺货；库存需页面或授权接口 |
| BigCommerce | Product JSON-LD；价格可能在 `offers.price` 或 `offers.priceSpecification.price` | 两种价格形状都要查；描述可能只在 DOM |
| 自定义／微数据 | `[itemtype*="Product"]`、`[itemprop=price]`、`<title>` | 先查微数据，再退回 DOM 和标题 |

平台标记只是线索，不是结论；以商品页实际响应为准。

## 基础清洗默认

旧流程把基础清理放在模板里；新流程也应作为公共默认，不每站重写。

| 类型 | 默认处理 |
| --- | --- |
| 文本 | 去首尾空白、合并连续空白；从标题取名称时去站点名前缀／后缀 |
| HTML | 保留段落、标题、列表、强调、表格和规格；去掉脚本、样式、链接、图片、表单、按钮、“Lire la suite” 类展开控件 |
| 价格 | 按 locale 解析千位／小数符；同一报价的含税／未税取较小者并记录 `basis`；只接受有限正数；CSV 格式化到 2 位小数 |
| 分类 | 取面包屑最后一个非首页项；保留原站分类，不把品牌强行改写成业务分类 |
| 品牌 | 只取 JSON-LD、manufacturer 或可见品牌字段；未公开就留空，不从商品名猜 |
| 选项 | 去重、去价格差、去数量组；只保留公开可选项，不枚举全部 SKU 组合价格 |
| CSV | UTF-8、9 列固定顺序、RFC 4180 引号、公式保护；缺失和部分内容留在任务结果 |

## 效率评估与优化

- 时间只作参考，不设硬性胜负（J09）。
- 简单站：旧模板几分钟即可；AI 起步略高可接受，先保证结果可用和方案留下。
- 普通／复杂站：以 10 分钟为经验参照，不要求单次更快。
- 记录首个有效商品、首个完整方案和人工介入；看多站趋势，不纠结单站秒数。
- 优化方向：基础 manifest、字段回退顺序、平台预设、清洗默认、随机 10～20 样本、少读无关文档、复用上一站的方案结构。

## 基础 manifest 骨架

复制后只改 `site`、`scope`、`discovery` 和少量 `extract` 覆盖；不要把站点差异写进公共引擎。

```yaml
schema_version: "1.0"
plan_id: "<site>-<market>-base"
plan_version: "2026.11.20-1"
kind: declarative
status: candidate
created_at: "<ISO8601>"
updated_at: "<ISO8601>"

site:
  name: "<shop>"
  entry_urls: ["<entry>"]
  allowed_origins: ["<origin>"]
  allowed_path_prefixes: ["/"]
  market: "<market>"
  locale: "<locale>"
  currency: "<currency>"

scope:
  include: ["<product-path-pattern>"]
  exclude: ["<cart>", "<account>", "<search>", "<checkout>"]
  notes: "bounded first pass; not full-site coverage"

discovery:
  strategies: ["sitemap", "category", "pagination"]
  sitemap_urls: ["<sitemap-or-empty>"]
  category_seeds: ["<category-or-empty>"]
  product_url_patterns: ["<regex>"]
  url_identity: "canonical"

fetch:
  default_engine: "static"
  per_url_type:
    product:
      engine: "static"
      wait_until: "domcontentloaded"
  rate_limit: {concurrency: 1, delay_ms: 1000}
  retry: {max_attempts: 2, backoff_ms: 1000}
  timeout_ms: 45000
  browser: false
  login: false

extract:
  fields:
    name: {source: "json_ld|h1|og_title|title", required: true}
    price.amount: {source: "json_ld|meta|itemprop|price_container", required: true}
    price.currency: {source: "same_offer", required: true}
    primary_image_url: {source: "json_ld|og_image|main_image", required: true}
    description_html: {source: "json_ld|description_container", required: false}
    category: {source: "breadcrumb|json_ld", required: false}
    brand: {source: "json_ld|manufacturer|visible", required: false}
    options: {source: "variants|selects|radios", required: false}
    source_url: {source: "canonical"}

normalize:
  price: {tax_basis: "exclusive_or_inclusive", choose: "smaller_public_pair", positive_only: true}
  description: {mode: "clean_html", statuses: ["complete", "partial", "not_provided", "failed"]}

validate:
  required_fields: ["name", "price.amount", "price.currency", "primary_image_url", "source_url"]
  assertions:
    - {field: "price.amount", op: ">", value: 0}
  random_sample: 10-20

runtime:
  entrypoint: "<runner>"
  protocol: "cli|subprocess"
  notes: "first pass; full docs/08 contract can be tightened later"

compatibility:
  os: ["windows", "linux", "wsl2"]
  runtime: "python>=3.11"
  browser: "none for static"

evidence:
  sample_urls: []
  expected: []
  verified_at: null
  limitations: ["first pass; random sample only"]
```

## 首次接入流程

- **分诊**：1 个入口请求，记录状态、标题、Sitemap 行、sitemap、平台线索和最终 URL；不先开浏览器。
- **样页**：取 1 个商品页，按字段回退顺序确认名称、价格、币种、图片、描述、分类、品牌、选项和 canonical。
- **套模板**：复制基础 manifest，先只改入口、范围、商品 URL 形态和 1～3 个选择器；不要从零写 runner。
- **小跑**：随机抽 10～20 个商品；入口不足 10 个时做全量小样本并说明，不伪造抽样。记录首个有效商品时间、请求数、字段命中、失败和部分内容。
- **定稿**：保存方案和证据；随机抽查通过即可，不要求全量逐字段核对；维护和漂移后置。
- **记录**：字段来源、价格口径、品牌缺失、分类映射和站点例外写入方案 `notes` 或任务结果。

## R06 可执行子集与首次验证

R06 把本模板落成一个最小执行器，验证“只写声明式方案、不写站点专用代码”。规则包、任务类型、工作项和并行模型在[采集规则与任务运行时](19-采集规则与任务运行时.md)中定义；本节只记录当前执行子集。当前可执行子集：

| 部分 | R06 支持 | 暂不支持 |
| --- | --- | --- |
| 发现 | `entry_links`、`sitemap`（urlset／index／gzip、子图过滤）、`listing` 的 `page_param`／`next_link`（S5／Tognar 已验证）、`html_index` 的有限深度分类递归（S5／Familidoo 已验证）、`public_json` 的 page／offset／cursor | 单 source seeds 列表、POST／GraphQL、load more、无限滚动、详情补全；目标模型见 `22` |
| 获取 | 静态 HTTP、并发 1、间隔 ≥1000ms、`Sitemap:` 行探测（不读整份 robots） | 浏览器渲染、登录、代理轮换、挑战处理；当前原型已改为只探测 `Sitemap:` 行 |
| 提取 | `json_ld`、`css_text`、`css_attr`、`css_html`、`title`、`breadcrumb`、`option_groups`、`price_pair`、`canonical`、`constant` | 变体 JSON 全量、分页、复杂交互 |
| 输出 | 9 列 CSV、`task-result.json`、`run-summary.json`、诊断 JSONL／CSV | 断点续跑、取消回收、完整 NDJSON 协议 |

`familidoo` 首次验证（`r06-run-001`）：

- 入口页 6 个商品，6／6 有效；8 请求；运行 16.77s。
- 从写站点方案到首个有效商品 110s；不计执行器开发，不能和旧流程直接比快慢。
- 站点侧没有 `run.py`，只有 `plans/familidoo.yaml`；名称、价格、币种、图片、描述、分类和 canonical 均由声明式回退命中。
- 同方案复跑三次，业务 CSV 字节一致；只证明当前静态页面可复现，不证明跨站或长期稳定。
- 入口页只有 6 个商品，未做 10～20 随机抽样；这是入口范围限制，不是抽样通过。

运行方式与证据见 `experiments/r06/README.md`；它是原型，不是生产执行器。只做网址发现、不提取商品的站，按 `19` 的 `task_type=discovery` 使用同一规则包，不需要写 `extract`。R16 v0 已把 discovery 和 product 拆成两个任务并并行验证（6 URL／6 商品），细节和局限见 `19`。

## 验收口径

首次采集按以下条件判断：

- 9 列业务字段可导出，价格为正、币种有同一报价证据、主图非占位图、`source_url` 可追溯。
- 名称优先来自页面明确字段；从 `<title>` 取时去掉站点名，不把店铺口号当商品名。
- 价格口径统一：含税／未税二选一，记录 `basis`；同一对照表不混用两种口径。
- 描述状态可区分完整、部分、未提供；复杂区块有界尝试后可标部分。
- 随机抽查 10～20 个商品，失败和例外保留；不把样本写成全站覆盖。
- 时间在可接受范围；不要求单次低于旧模板；简单站 AI 起步略高可接受。
- 运行期无逐页 LLM；方案保存后可复跑。

## 非目标

- 不追求一套模板覆盖所有站点；平台差异和自定义主题仍需覆盖。
- 本轮不比较维护、漂移修复、长期稳定性和全站覆盖率；这些在后续阶段补。
- 不把基础模板当成“万能动作语言”；站点差异留在方案里。

## 维护规则

- 模板只收敛跨站共性；单站差异写进方案，不写进公共模板。
- 每次 R04 试点后回写字段回退顺序、平台线索和失败模式；不把一次成功写成通用结论。
- 价格口径、品牌来源和分类映射的变化，先改 `02` 或本模板，再改站点方案。
- 维护、漂移和全量覆盖后置；后续阶段再扩展本模板的验收口径。
