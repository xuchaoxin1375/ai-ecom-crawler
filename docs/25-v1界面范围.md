## 用途与边界

本页把 v1.0 本地 Web UI 的“必须有”和“可以后置”冻结成可验收清单，供 D08 实现与 A16 验收使用。它不新增业务口径，不替代[界面与任务管理](06-界面与任务管理.md)、[任务状态与计数契约](09-任务状态与计数契约.md)和[ADR 0004](adr/0004-任务粒度、资源配额与Web界面.md)；API 细节由[D08 任务服务与界面设计](26-D08任务服务与界面设计.md)维护。

**2026-11-21 已由项目方确认。** 本页范围作为 v1.0 的界面门依据；控制功能开工前先完成 D07 的暂停／取消隔离与恢复项。构建会话 UI 后置，harness 先做 `opencode serve` + HTTP/SSE 冒烟。

## 形态与共用层

- v1.0 是本地 Web UI：单机单用户，默认只绑定回环地址，浏览器访问；不做桌面壳。
- 前端只通过本地 API／SSE 读取任务、商品、方案和事件；不直接读 SQLite、不启动采集进程。
- CLI 与 Web 共用同一任务服务。当前 `app/` 已有 CLI、SQLite 账本和单进程执行器；界面实现不能另写一套业务逻辑。
- `run` 是一次性单任务入口；常驻服务在 D08 接入 `Worker`，v1.0 默认 `max_tasks=1`，A20 通过后再开放 2 个槽位。界面可以展示多个历史／排队任务，但并发执行、全局槽位和配额原因以后端实际能力为准，不显示虚假并行。

## v1.0 必须有

| 模块 | 必须行为 | 验收关联 |
| --- | --- | --- |
| 任务列表 | 显示任务 ID、类型（discovery／product）、站点、方案版本、市场、状态、`outcome`、停止原因、计数、覆盖状态和更新时间；按状态／类型筛选；空列表和读取失败有明确状态 | A16、A17、A13 |
| 创建任务 | 选择规则包／站点、市场／语言和预算（商品数、URL 数、秒数）；不要求用户填选择器；创建与启动分离，界面可一次提交两步；重复提交按 `request_id` 幂等；创建后显示排队／已启动，不把“已受理”写成“已完成” | A16、A08 |
| 任务详情 | 显示计数、`coverage`、停止原因、失败分类、`quality_exceptions`、最近事件和错误；URL／商品分页列表；商品预览显示价格、币种、正文状态、部分原因、缺失原因和字段来源 | A05、A14、A17 |
| 控制 | 暂停（`PAUSING`→`PAUSED`）、恢复、取消（`CANCELLING`→`CANCELLED`）和归档／还原；按钮区分请求已受理与实际完成；拒绝非法状态转移；不使用歧义的“停止” | A13、A16 |
| 导出 | 下载 9 列 `products.csv`、`task-result.json` 和排除／失败诊断；未结束任务只能显式部分导出；导出文件名包含任务 ID 和方案版本 | A14、A17 |
| 真实进度 | 以计数为主；只在 `coverage.status=KNOWN` 或明确预算上限时显示比例；不编造全站百分比、瞬时速率或 ETA；页面关闭不停止后台，重开从持久事实恢复 | A17、A16 |
| 安全与可用性 | 只绑定回环地址；不显示密钥、Cookie 或完整认证头；商品 HTML 预览按不可信内容处理，不执行脚本；键盘可达、焦点可见、基本对比度；开发期主目标桌面 1280，窄屏 768 与深色主题在交付前适配阶段纳入，不作为当前开发门阻断 | 06、17 |
| 多任务边界 | 列表和详情不合并任务计数；同站任务只做提示，不把站点分组当任务状态；并行未实现时显示排队原因，不伪造资源配额 | A20、ADR 0004 |

## v1.0 可以后置

- 构建会话查看／暂停／取消／移除；依赖 ADR 0005／0006 的 Harness 实现。
- 批次视图、站点分组、通知、图表、进度条、瞬时速率、ETA。
- 方案编辑器、规则构建器、任意 URL 输入和选择器调试面板。
- 永久移除、异步残留回收和删除确认流程；v1.0 只做归档／还原。
- 多用户、登录、远程访问、桌面壳、系统托盘。
- 深色主题、主题编辑器、高级响应式细节；开发期先保证浅色主题和桌面 1280，窄屏完整适配在交付前阶段。
- 全局任务槽位、浏览器实例配额的详细面板和配额编辑；单任务的排队原因仍按“多任务边界”显示，不能省略。

## 实现前需要的 API（范围声明）

| 方法／路径 | 用途 |
| --- | --- |
| `GET /api/health` | 服务、数据库、worker 和版本状态 |
| `GET /api/rules` | 列出受管规则包及站点、市场、版本；创建任务只能从这里选择 |
| `GET /api/tasks` | 任务列表与筛选 |
| `POST /api/tasks` | 创建任务为 `DRAFT`；返回任务 ID 与当前状态 |
| `POST /api/tasks/{id}/start` | 将 `DRAFT` 提交为 `QUEUED`；重复启动返回当前状态 |
| `GET /api/tasks/{id}` | 任务详情、计数、覆盖、停止原因和质量异常 |
| `POST /api/tasks/{id}/pause` | 请求暂停；返回已受理 |
| `POST /api/tasks/{id}/resume` | 恢复兼容任务 |
| `POST /api/tasks/{id}/cancel` | 请求取消；返回已受理 |
| `POST /api/tasks/{id}/archive`、`/restore` | 只改可见性 |
| `GET /api/tasks/{id}/items?kind=url\|product` | 分页查看 URL／商品 |
| `GET /api/tasks/{id}/events` | SSE 事件；断线重连先拉快照 |
| `GET /api/tasks/{id}/export` | 下载 CSV、任务结果和诊断 |

响应至少包含 `task_id`、`task_type`、`plan_id`、`plan_version`、`site_key`、`market`、`state`、`outcome`、`counts`、`coverage`、`stop_reason`、`quality_exceptions`、`archived_at`、`updated_at`；控制接口返回“已受理”，最终状态以账本为准。

## v1.0 完成条件

- 一个真实任务可以通过界面创建、查看计数与质量异常、暂停／恢复或取消、导出，并能在页面关闭后继续后台执行。
- 控制请求与实际状态一致；非法状态转移被拒绝；迟到结果不进入有效集。
- 任务结果和 9 列 CSV 与 CLI 输出含义一致，导出保真。
- 至少有一个真实站点的界面闭环证据；没有实现的功能按“可后置”列明，不用占位按钮冒充。
- 前端设计评审记录（按 [D08 前端设计包与评审](28-D08前端设计包.md)）与实现／交互证据一并保留；没有评审记录不算 A16 完成。
- 控制功能开工前，D07 至少完成暂停／取消隔离、迟到结果拒收、任务资源登记与回收和恢复对账；浏览器 adapter 的真实资源回收另计，未完成时只能交付只读列表／详情／导出，不交付控制按钮。

## 已确认口径（2026-11-21）

- v1.0 保留本页“必须有”清单；暂停、恢复、取消不再后置，先补 D07 控制项，再开 D08 控制界面。
- 构建会话 UI 后置；v1.0 不交付构建会话的查看／暂停／取消／移除界面。构建 harness 先按 ADR 0006 做 `opencode serve` + HTTP/SSE 冒烟、权限回复和关闭回收，不接真实站点。
- 永久移除和异步残留回收后置；v1.0 只做归档／还原，归档只改可见性。
- 多任务并行沿用 ADR 0004 的槽位模型，但服务默认 `max_tasks=1`；A20 通过后再开放 2 个槽位。界面必须显示排队原因，不伪造并行。
- D08 的实现架构、API 请求／响应、账本迁移、安全边界和测试切片见[D08 任务服务与界面设计](26-D08任务服务与界面设计.md)。

## 实现前置

- 任务服务常驻入口：页面关闭不停止后台，CLI 与 Web 共用同一 `TaskStore` 和 `Worker`；不能用一次性 `run` 冒充服务。
- 账本增加 `site_key`、`domain_key`、`market`、`archived_at` 和创建幂等键；现有 `tasks` 表不足支撑列表筛选和归档。
- API 契约、错误码、分页、SSE 事件和安全校验与页面原型一并评审；契约测试和页面实现可以并行，但不能用“API 先行”的顺序跳过前端设计。
- 一个可预览的前端原型先于正式实现，按 `06` 和 [D08 前端设计包与评审](28-D08前端设计包.md) 确认页面清单、关键流程、信息层级、状态矩阵和 1280 主规格线框；窄屏线框可在交付前适配阶段补，已有基础窄屏验证可复用；技术预览和实现页面不替代该评审。
- 前端设计评审未通过前，不扩大控制、归档和导出页面的正式实现范围；已实现页面按技术预览对待。
