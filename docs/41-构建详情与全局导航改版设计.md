## 用途与边界

本页是[React v2 前端改进待办](frontend-backlog.md)推广计划阶段 4 的设计草案：收口构建详情和全局导航。构建页先显示运行状态或待审批事项，再按需查验证证据、修复轮次和日志；侧栏按业务页和规则／设置页分组。

不改后端接口、构建状态契约、已分享深链接、React 外壳和视觉令牌。任务详情、站点详情和批次详情已完成阶段 1–3，不在本阶段重做。

本页的视图名称、构建事实位置、继续／重新构建的措辞和侧栏分组仍是待确认项，不当作已定稿规格。项目方确认后再写代码。

## 首屏结构与 HTML 草稿

线框主稿是可浏览的静态 HTML：`experiments/d08/build-detail-prototype/index.html`。打开方式、状态切换和覆盖点见该目录 `README.md`；1280 和 390 截图在仓库外 `workbench/build-detail-prototype-20261125/`。下方文字只固定内容顺序和验收口径，不替代实际原稿。

| 顺序 | 内容 | 桌面 | 窄屏 |
| --- | --- | --- | --- |
| 1 | 返回构建记录、构建 ID、站点、状态／结果／模式徽标 | 同一行，标题左、状态右 | 标题和状态换行，返回在上 |
| 2 | 停止原因、批次／站点链接、更新、实时状态 | 标题下方一行或多行 | 换行，批次和站点链接保留 |
| 3 | 主操作、更多、刷新 | 页头右侧同一行 | 按钮换行，主操作仍先出现 |
| 4 | 待审批请求（有则显示） | 摘要之前，整行 | 摘要之前，整行 |
| 5 | 紧凑摘要：状态、自动修复、耗时、验证 | 四列 | 两列，360 像素以下单列 |
| 6 | 视图切换：运行状态、验证证据、修复轮次、日志与 Trace | 标签栏 | 单选控件 |
| 7 | 运行状态：当前阶段、构建事实、继续原会话 | 状态和事实在前，日志不在首屏铺开 | 同顺序，单列 |

构建页首屏先回答“现在在做什么、是否等人、下一步是继续还是重新开始”；验证证据、修复轮次和模型日志按需进入各自视图。

## 操作位置

| 位置 | 放什么 | 约束 |
| --- | --- | --- |
| 页头 | 当前对象、状态、一个随状态变化的主操作 | 运行中突出暂停／继续；排队突出取消排队；失败或中断突出继续原会话；成功指向站点 |
| 「更多」 | 复制构建 ID、打开站点／批次、下载 trace、重新构建、取消构建 | 取消保留二次确认；继续原会话与重新构建必须分开命名 |
| 运行状态 | 当前阶段、构建事实、继续原会话说明 | 审批请求固定在首屏；继续原会话沿用同一 build 和会话 |
| 验证证据 | 字段变更、候选冒烟、同页回归、内容审计、存档统计 | 证据不足时保留阻断理由，不伪造通过 |
| 修复轮次 | 自动修复每轮的错误、验证摘要和时间 | 不把修复轮次混进模型日志 |
| 日志与 Trace | 构建时间线、模型输出、工具调用和 trace 下载 | 日志有界滚动，不把长日志铺满首屏 |

继续原会话和重新构建是两种不同后果：

- **继续原会话**：沿用当前构建记录、会话和工作区，把补充指令发回同一模型会话；不产生新的构建记录。
- **重新构建**：回到站点详情发起新构建，产生新的 `build_id`；旧构建记录、验证证据和日志保留。

## 状态表

| 构建状态 | 运行状态首屏 | 页头主操作 | 更多与辅助入口 |
| --- | --- | --- | --- |
| 排队 | 队列位置和等待说明 | 取消排队 | 复制 ID；站点／批次 |
| 运行中 | 当前阶段、模型与耗时、待审批（如有） | 暂停构建 | 验证证据、修复轮次、日志；取消（更多） |
| 暂停 | 暂停原因和继续说明 | 继续构建 | 取消（更多）；验证证据、日志 |
| 验证中 | 主机验证阶段和已用时间 | 无 | 验证证据、日志；复制 ID |
| 失败 | 错误分类、失败阶段和继续入口 | 继续原会话 | 重新构建（更多）、验证证据、修复轮次、日志 |
| 中断 | 会话和工作区已保留说明 | 继续原会话 | 重新构建（更多）、日志、站点／批次 |
| 成功 | 规则版本、验证结果和站点入口 | 查看站点 | 验证证据、修复轮次、日志、复制 ID |
| 已取消 | 取消原因和重新构建入口 | 重新构建 | 复制 ID；站点／批次 |
| 正在取消 | 取消进行中 | 无 | 日志、复制 ID |
| 读取失败 | 错误说明与重试 | 无 | 返回构建记录 |

无待审批请求时，页面不显示空的审批模块；有待审批时，请求和处理后的影响固定在摘要之前。

## 视图与内容去向

| 视图（候选名） | 内容 | 来源 |
| --- | --- | --- |
| 运行状态 | 当前阶段、构建事实、继续原会话 | 现有构建事实、继续构建会话、事件摘要 |
| 验证证据 | 字段变更、候选冒烟、同页回归、内容审计、存档统计 | 现有 `RuleEvidence`、`change_summary`、`validation`、`archive_stats` |
| 修复轮次 | 每轮错误、验证摘要和时间 | 现有 `RepairHistory` |
| 日志与 Trace | 构建时间线、模型输出、工具调用、trace 下载 | 现有 `BuildTimeline`、`trace_available` |

待确认：构建事实放在运行状态还是日志视图；继续原会话是否用页内展开卡还是单独对话框；下载 trace 放页头「更多」还是日志视图。

## 全局导航

侧栏按“采集工作台”和“规则与设置”分组：

| 分组 | 页面 | 当前项判定 |
| --- | --- | --- |
| 采集工作台 | 采集批次、全部任务 | 批次／站点详情归采集批次；任务列表／详情归全部任务 |
| 规则与设置 | 构建记录、模型配置 | 构建列表／详情归构建记录；模型设置归模型配置 |

- 分组标题在侧栏展开时显示；收起为 Rail 时用分隔线保持分组，不显示标题。
- 新建批次保留为批次列表里的动作，不再放全局侧栏快捷入口；避免把“新建对象”和“页面入口”混排。
- 现有路由和深链接不变；侧栏当前项、面包屑和页面标题保持一致。
- 移动端抽屉使用同一分组和当前项；关闭抽屉后焦点回到触发按钮。

## 深链接映射

- 现有 `/builds` 和 `/builds/{buildId}` 保持不变；构建详情视图用 `?view=status|evidence|repairs|logs`，默认 `status` 省略；无效值回到运行状态并用 `replace` 修正。
- 同一页面切换视图用 `replace`；浏览器后退仍回到进入构建前的页面。
- 继续原会话不新增路由；重新构建跳转站点详情并打开现有构建对话框，旧构建记录保留。
- 侧栏分组只改标签和分组，不改路由、导航参数和页面内深链接。

## 组件与数据复用

- 复用现有 React 外壳、颜色令牌、`Badge`、`Button`、`DropdownMenu`、`InlineNotice` 和确认弹窗。
- 复用 `RuleEvidence`、`BuildTimeline`、`RepairHistory`、构建事实和 trace 下载；不改 API 与状态契约。
- 侧栏复用现有 `NavLink`、折叠／Rail、移动抽屉和焦点管理，只增加分组结构。
- 不新增后端接口，不改构建状态、验证证据、依赖审批或会话恢复契约。

## 响应式与可访问性

- 1280 × 900 和 390 × 900 为首要对照，768 和 320 为交付前检查。
- 390 首屏至少看到构建对象、状态、主操作和当前阶段或审批；无待办时首屏不出现空审批模块。
- 视图切换支持键盘；窄屏用单选控件；关闭弹窗后回到触发按钮。
- 日志、验证证据和字段差异在自身容器内滚动，不产生页面级横向溢出。
- 侧栏分组标题可被读屏读取，Rail 模式下仍能通过 `aria-label` 识别页面；当前项有明确选中状态。

## 验收清单

- 覆盖排队、运行、暂停、验证中、失败、中断、成功、取消和读取失败；已配置与不可用构建服务分别处理。
- 有待审批时首屏能看到请求和处理影响；无待办时无空模块。
- 继续原会话和重新构建的文案、目标、结果和保留范围可区分；继续不会创建新构建记录。
- 验证证据、修复轮次和日志都能到达，证据不足时有阻断理由。
- 侧栏分组、当前项、面包屑和页面标题一致；直接打开深链、刷新、前进／后退均正确。
- 1280、768、390、320 无页面级横向溢出；键盘切换视图和移动抽屉焦点正常；桌面 axe 违规为零。
- 现有前端测试、lint、typecheck、format、build 和浏览器冒烟通过；真实账本只读走查，写操作在隔离账本验证。

## 待确认决策

| 编号 | 决策 | 推荐 | 备选与代价 |
| --- | --- | --- | --- |
| D1 | 构建视图组织 | 运行状态、验证证据、修复轮次、日志与 Trace 四视图 | 全部折叠区：实现简单，但首屏仍可能堆叠；独立子路由：链接清楚，但改现有 URL |
| D2 | 继续原会话位置 | 运行状态内的展开卡，页头主操作聚焦它 | 单独对话框：步骤更明确，但多一层弹窗 |
| D3 | 重新构建入口 | 页头「更多」+ 继续卡次操作，跳站点详情 | 页头常驻按钮：可见性高，但和继续原会话混淆 |
| D4 | 构建事实位置 | 运行状态内紧凑事实，日志只放时间线 | 事实与日志合并：页面更短，但技术信息混在一起 |
| D5 | 侧栏分组 | 采集工作台／规则与设置 | 保持平铺：改动小，但构建和任务仍易混 |
| D6 | 新建批次全局入口 | 移除侧栏快捷入口，保留批次列表动作 | 保留侧栏：新用户更快，但页面入口与新建动作混排 |

## 实施切分

1. 先按分组重排侧栏，移除新建批次快捷入口，验证当前项、Rail、移动抽屉和深链接。
2. 构建页搭页头、摘要、四视图和唯一主操作；把验证证据、修复轮次、日志和时间线移到各自视图。
3. 处理审批、继续原会话、重新构建、取消、成功和失败状态；无待办时不渲染空审批模块。
4. 补组件测试、浏览器走查、1280／390／768／320 截图和 axe；完成后做一次全站导航与深链接回归。
