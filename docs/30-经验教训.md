## 用途与边界

本页记录 2026-11-21 D08 设计讨论、仓库整理和浏览器 adapter 验证中形成的可复用教训，供本项目后续开发和类似项目参考。它不替代业务规则、ADR 或 skill 正文；具体操作规范分别落在 `swe-gov`、`frontend-design`、`repo-gov` 和 `resilient-browser-fetch`。

## API 契约清楚不等于前端设计清楚

「契约冻结后前后端可以并行」默认假设有独立的前后端实现者和评审上下文。单人或单个 coding agent 串行开发时，物理上仍是一前一后；如果先把后端和数据契约定完，再让 Agent 按 API 字段生成页面，很容易出现：

- 页面按字段直排，用户任务和信息层级没有单独设计；
- 空态、失败态、部分结果、控制已受理和禁用状态在实现时才临时决定；
- 设计和实现互相追着改，评审只能用已经写好的页面，形成循环论证；
- 负责人没有前端设计背景时，Agent 把“你想怎么布局”原样抛回，推进停滞。

本项目的具体表现：D08 页面先于独立设计稿实现，1280 复核最初用的是已实现页面；质量异常曾直接显示整段 JSON；后来补了初步设计稿和用户视角的状态整理。

可复用做法：

- 把前端设计当成独立工件：目标用户、主流程、页面清单、信息层级、状态矩阵、主规格线框、关键取舍；
- Agent 先出 2–3 个可预览方向、推荐稿和取舍，负责人确认业务目标和选择，不要求负责人先画线框或写 CSS；
- 设计决定先于页面扩散；实现可以按纵向切片串行推进，但不要用 API schema 直接生成页面结构；
- 纯 CRUD、内部工具且交互显然时可以简化设计稿；面向运营／分析人员的控制台、长任务、多状态页面不适用豁免；
- 小团队或单人亦可只维护一份轻量设计稿，不强行拆前后端两套流程。

## 运行期数据库不应随仓库分发

任务账本、SQLite 数据库及其 WAL／SHM 是本机运行状态，通常具有以下问题：

- 二进制、易冲突，无法可靠 review 或合并；
- 会随着运行增长，包含任务历史、临时状态甚至用户数据；
- 不同机器、不同任务的数据库不能互相替代，提交后容易让后来者误以为它是可复用的 fixture；
- 证据价值不如任务结果、CSV、事件摘要和可重跑命令稳定。

本项目已将 `tasks.db` 等运行期账本移出版本控制，加入忽略规则；需要长期保留的证据使用 `task-result.json`、`products.csv`、`records.jsonl`、事件摘要和复跑步骤。

例外：小型、合成或脱敏、测试确实需要的 fixture 数据库可以保留，但必须写明用途、生成方式和例外规则；不因为扩展名一律忽略合法 fixture。

## 工作区跟踪检查

- 提交前看 `git status --short`、`git diff --cached --stat` 和 `git ls-files -c -i --exclude-standard`，区分“本次改动”“用户手工改动”和“生成物”。
- 已追踪但应忽略的文件用 `git rm --cached -- <file>` 移出版本控制，保留本地内容；不要 `git rm` 删除用户文件。
- 发现运行时数据库、日志、缓存、浏览器 profile 或可再生成产物被追踪时，先核对用途再处理，不无差别清理。
- 运行期数据被忽略后，工作区仍可能保留文件；这是有意为之，不代表提交遗漏。

## 挑战壳的 HTTP 状态不等于渲染后的状态

浏览器抓取时，`page.goto()` 返回的是首个主文档响应。站点可能在 403／429／503 壳里运行自己的 JS，随后重新导航到真实页面；此时首个响应仍是 503，但最终 DOM 已经可用。

可复用做法：

- 用明确的 DOM 就绪信号（真实标题、商品容器、`wait_selector`）判断内容是否渲染，不要只看首个 HTTP 状态。
- 渲染完成后读取 navigation timing 的 `responseStatus`，它通常反映最终文档；拿不到时回退到首个响应并在结果里标注。
- 不要因为“最终 200”就忽略挑战：如果没有就绪信号、标题仍是挑战文案或正文仍是壳，应按 `ACCESS_DENIED` / 失败流记录。
- 这类等待只给站点自己的验证留时间，不做点击、过验证码或绕过登录／付费；headless 通过也不等于站点长期稳定。
- 证据里同时写首个状态、最终状态、等待方式、渲染耗时和停止原因，避免把“浏览器能打开”写成“站点可全量采集”。

本项目的 mercerine 证据：首个响应 503，渲染后 `responseStatus=200`，3／3 商品页有效；见 `experiments/d07/browser-mercerine/`。
