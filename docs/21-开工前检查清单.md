## 用途与边界

本页把“可以开始实现”拆成可逐项核对的检查项，供项目方、技术负责人和承接方在正式开工前使用。它只汇总 [项目定位](00-项目定位与可行性.md)、[开发任务](04-开发任务与交付.md)、[实施路线](10-实施路线与交接.md)、[交接](15-交接.md)、[规则与运行时](19-采集规则与任务运行时.md)、[环境基线](20-构建环境与依赖基线.md) 和 [网址发现与分页策略](22-网址发现与分页策略.md) 已有的门禁，不新增业务口径；业务规则仍以 01～09 为准，当前状态仍以 [交接与继续](15-交接.md) 和 Git 为准。

只有存在可复核证据时才勾选；未勾选项写负责人、阻塞范围和截止条件。勾选不表示“讨论过”，也不把 Proposed 写成已实现。

## 技术选型覆盖

本条把“每个进入生产路径的技术层都有决策记录”变成可核对项。状态只写决策状态；验证状态单独记录，已实现不等于已验收。本文的 `Provisional` 指“方向已选定、验证未完成”，允许在登记范围内实现，不是未决；定义见[术语表](术语表.md)。

### 开写前必须确认

技术选型是开工前的硬门，不是实现中的可选项。前端、后端、数据存储、部署方式和构建工具等每个进入生产路径的层，都必须先有结论；没有结论时也必须给出基于现有信息的推荐、理由、风险和复审条件，不能留空后边写边选。

当前状态：批次工作台与任务控制台主路径见 ADR 0009（Vue 3 + TypeScript + Vite，阶段 1 已实现并验收）；任务控制台并入见 ADR 0010（Accepted，验证 partial）；样式层见 ADR 0011（手写 CSS + 令牌，不引入 CSS 框架／UI 组件库，验证 partial）；前端 v2 方向见 ADR 0012（React + Tailwind v4 + 自有组件层，Proposed，未进入生产）；旧 `/legacy` 原生页面见 ADR 0008，仅作技术兜底。后端 ADR 0001～0003 已定，0004／0006／0007 为受限 Provisional；FastAPI 与替代 Web 框架的对比见 ADR 0001。

- [ ] **前端已定**：框架或原生方案、构建方式、路由／状态／组件策略、测试方式，以及选择理由和未选方案。
- [ ] **后端已定**：语言／框架、API 形式、数据存储、任务与队列、部署方式，以及选择理由和未选方案。
- [ ] **每个候选都比过**：成功机会、开发效率、可维护性、可扩展性、团队／AI 熟悉度、运行与维护成本、主要风险。
- [ ] **不知道哪个更好时已有推荐**：按已知信息给出默认方向和判断依据，写明重选条件；没有“先做起来再说”。
- [ ] **并行路线有边界**：如采用多路线并行，已写清共享契约、各自预算、比较指标、停止条件、最终决策日期和负责人；到期必须选一条。
- [ ] **未确认的层不进入生产**：只能在 `experiments/` 做验证原型，不进入 `app/`；验证原型开始前限定时间、范围和通过标准。

“验证原型”指先限定时间、范围和通过标准的小规模试做，用于比较方案，不是正式产品代码。

每层决策记录至少写：选择及理由、候选与已知信息、成功机会、开发效率、可维护性、可扩展性、风险与回退、复审条件；并行路线另写共享契约、预算、指标、停止条件、决策日期和负责人。
