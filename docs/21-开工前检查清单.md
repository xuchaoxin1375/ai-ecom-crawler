## 用途与边界

本页把“可以开始实现”拆成可逐项核对的检查项，供项目方、技术负责人和承接方在正式开工前使用。它只汇总 [项目定位](00-项目定位与可行性.md)、[开发任务](04-开发任务与交付.md)、[实施路线](10-实施路线与交接.md)、[交接](15-交接.md)、[规则与运行时](19-采集规则与任务运行时.md)、[环境基线](20-构建环境与依赖基线.md) 和 [网址发现与分页策略](22-网址发现与分页策略.md) 已有的门禁，不新增业务口径；业务规则仍以 01～09 为准，当前状态仍以 [交接与继续](15-交接.md) 和 Git 为准。

只有存在可复核证据时才勾选；未勾选项写负责人、阻塞范围和截止条件。勾选不表示“讨论过”，也不把 Proposed 写成已实现。

- [ ] **ADR 状态已收口**：ADR 0001～0006 逐项标记已验证、接受或写明退出条件；未验证项不写成已定方案。
- [ ] **J04／J05 口径统一**：J04 部署形态按“基线已定、D01 验证”统一表述；J05 合规默认由法务／负责人确认。

## 契约门

- [x] **规则语义唯一**：`discovery.product_url_patterns`、`scope.include` 和 `scope.exclude` 已统一为正则，写入 [规则与运行时](19-采集规则与任务运行时.md) 和 [方案契约](08-采集方案与兼容契约.md)；`rule_*` 与 `plan_*` 映射已定。证据：`experiments/r06/tests/test_contract.py` 的 `test_scope_include_uses_regex` 与 `r06-run-004` 复核。
- [x] **Schema 可执行**：[方案 manifest JSON Schema](schema/manifest.schema.json) 同时覆盖 `rule_*` 与 `plan_*` 两种投影；`experiments/r06/tests/test_schema.py` 校验规则包和单次方案。`rule validate` 尚未调用 schema，跨字段约束仍由执行器校验。
- [x] **运行时差距有结论**：`failure_class`、`max_attempts`、结果原子写、按任务启动对账、取消迟到结果拒收和 `plan_*` 映射已实现；心跳过期扫描、孤儿浏览器／进程登记和跨进程恢复仍待补。证据：`experiments/r06/tests/test_runtime.py` 的 `RetryTests`／`RecoveryTests`／`ControlTests` 与 `runtime-demo` 复核。
- [x] **发现与分页模型已定**：[网址发现与分页策略](22-网址发现与分页策略.md) 定义来源、推进、判型、停止与证据四层模型，并明确 sitemap、分类分页、load more、无限滚动和公开 JSON 尚未进入运行时。证据：`22`、`08`／`19` 同步；当前运行时仍只有 `entry_links`，但 robots 已改为只探测 `Sitemap:` 行、不再拦截。
- [ ] **测试策略已落地**：R12 的必测清单（契约、状态不变量、CSV、安全边界）和样本口径已写；原型测试与生产测试分层。
- [ ] **依赖基线统一**：`pyyaml` 等跨项目版本已统一；Scrapling 固定版本、升级和回滚方式已记录；干净环境复现（R11）有结果。
- [ ] **Harness 前置已定**（如 v1 含构建会话）：`build-task` schema／样例、`HarnessAdapter`、`opencode serve` + HTTP/SSE 冒烟、pause-gate 和 `request_dependency` 已实现或明确后置；后置时在范围中写明。

## 使用方式

- 开工前或交接会前，按本页逐项核对；状态只写“已满足”“未满足”“不适用”，未满足项写负责人和截止条件。
- 证据位置写链接或命令，不复制证据全文；本页不替代 [交接与继续](15-交接.md) 的当前状态。
- 冲突时以 Git 状态、[交接与继续](15-交接.md) 和基准站实测为准；本页只做门禁汇总。
