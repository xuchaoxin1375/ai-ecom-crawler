## 项目目标

建立可靠、易用、可恢复、可审计(可选)且基于AI agent驱动的高度自动化的公开电商商品采集工具。**AI负责理解网站、生成和维护完整采集方案，成熟执行框架负责稳定重复执行，用户主要提供目标、管理任务、查看与导出结果。**

完整方案覆盖网址发现、分页／加载、内容获取、必要浏览器动作、字段提取和规范化。规则、程序、公开数据接口和浏览器均是可选方法；站点差异留在方案里，避免接一个网站就修改公共引擎。

方案生成允许分析、试跑和修订多次；“一次构建、重复执行”不要求模型首轮成功。通过验证的普通批次脱离Agent会话执行，不逐页调用大语言模型(LLM)。网站变化或新站接入时再回到AI构建维护。

## 目标用户与交付

| 角色 | 输入／操作 | 应获得什么 |
| --- | --- | --- |
| 业务用户 | 首页／分类／商品入口、目标市场与语言、业务归属 | 简明任务、真实进度、可核对商品和结果文件 |
| 方案构建Agent | 固定数据标准、实际工具、站点证据、试跑反馈 | 可保存、可修订、可复跑的方案及诊断 |
| 运行框架 | 已验证方案及任务条件 | 稳定执行、有效数据、进度、错误、停止原因和资源回收 |
| 维护者 | 失败与变化证据 | 可定位修复、复验和恢复，不靠用户拼接散落结果 |

角色只说明谁提供输入、谁获得结果；详细职责、关键决定、单用户兼任和构建到运行交接见[用户角色与职责](31-用户角色与职责.md)。

- **v1 目标用户**：懂业务、会选规则包和设预算、不写代码的采集运营／数据分析人员；业务用户可以是同一人，也可以是查看和验收结果的另一人。
- **单用户边界**：v1 不提供账号体系、多用户、独立只读账号或公网远程访问；业务用户与操作者分离时，通过同一台机器、同一会话或导出文件查看和验收。可信局域网可通过启动令牌临时开放给同一操作者，仍按单用户处理；需要并发多用户、独立只读账号或公网访问时，先评估权限模型。
- **构建与运行分离**：新站方案由技术操作者通过构建 harness 构建、复核并标记 `verified`，进入受管规则包；v1 Web UI 只消费受管规则包，不承担构建会话 UI。要求普通用户在 UI 内完成新站首次构建，属于范围变更，需要把构建会话 UI 提前。
- **“普通用户只需提供目标网站”**：这是产品目标，不是 v1 UI 的当前入口条件；v1 创建任务仍要求已存在受管规则包，新站首次接入由技术操作者完成。长期目标进一步细化为“用户提交一批站点，系统完成接入判断、构建、采集和交付”；目标工作流与当前任务控制台的差距见[用户工作流与前端信息架构](33-用户工作流与前端信息架构.md)。

一次交付同时包含**可复用方案、有效数据、执行说明**。模型自报、文件存在和测试全绿分别只是证据的一部分，不单独证明业务完成。

## 范围与投入尺度

- 不采账户、订单或个人数据，不绕过登录、付费、年龄门、地区限制和站点明确拒绝；挑战页按[合规检查清单](17-合规检查清单.md)和 [ADR 0022](adr/0022-挑战页处理边界.md) 有界尝试。
- 高度依赖自由定制、没有稳定商品／公开商品数据的站点可以不支持；没有sitemap或明显分页本身不是整站跳过依据。
- 默认以约定范围的全量为目标；全量是范围和路径目标，不要求先证明全站分母或覆盖率。结构清晰时按路径完成和停止依据交付。采样、灰度和数量限制需要明确区分；资源保护截断须如实报告。
- 复杂目录优先基本分类、商品入口、下一页和已有加载动作；不以零漏采、可信全站总量或自动补采证明为基础交付前提。
- 采集深度按业务字段确定：列表／型号层已能提供的字段不逐条下钻详情；全量详情需要单独预算、抽样验证增量字段，并标明未补字段。
- 默认交付先保证基础字段：身份与来源 URL、名称、价格与币种、状态、主图、描述存在性；完整正文与规格、兼容关系、选项变体、文档和全量覆盖属于进阶项，任务未要求时不作为默认目标。
- 任务不强制提取商品数据：只做网址发现时，输出 URL 清单，按[采集规则与任务运行时](19-采集规则与任务运行时.md)的 discovery 口径计数；不把 URL 数当商品数。
- 存在明确未访问分支或持续产出新商品的加载动作时，在任务边界内继续；固定页数／批数不能冒充自然结束。
- 大部分业务目标网站可用是规划尺度。用户经验判断“70%以上相对容易、困难站点可能不足10%”用来控制投入，**不是经本文档测得的统计分布**，也不是单站覆盖率或字段准确率。
- 难站有界诊断后允许暂不支持，保持原因与已有效结果，不无限消耗项目主线。



## 输入与默认业务口径

长期目标是普通用户只需提供目标网站，采集业务和数据标准记录在系统文档中，必要时可以附加补充和备注。方法、选择器、分页参数和等待条件由方案构建解决，不成为永久必填技术表单。v1 当前仍要求已存在受管规则包；新站首次接入由技术操作者构建并复核，界面入口见[用户角色与职责](31-用户角色与职责.md)。

| 输入 | 约定 |
| --- | --- |
| 批次／项目 | 一次提交或交付的一组站点，用于组织、筛选和导出；不是任务状态或计数单位 |
| 入口与范围 | 保留指定网址和子目录，不能只按域名合并不同任务 |
| 市场与语言 | 指定产品数据面向的国家和语言目标，包括货币单位 |
| 数据字段 | 统一采用[数据标准](02-数据标准与导出.md)，逐站只解决映射和例外 |
| 网络与资源 | 使用实际获准的出口和工具，明确请求／并发／重试等资源边界 |
| 留存 | 正式整页HTML／JSON默认不保存；必要开发证据有界保留 |
| 输出 | 结果文件及CSV、缺失／部分内容说明、任务与方案追溯、停止原因 |

## 实现自由与硬要求

| 必须兑现的结果 | 新团队可自主选择的实现 |
| --- | --- |
| AI构建、框架独立执行、方案可保存复跑 | 程序项目、声明式规则或混合方式；Agent工具与供应商 |
| 任务、结果、进度与操作真实且持久 | 数据库、文件存储、队列、进程模型和内部调度 |
| 字段语义、原站依据和例外可辨 | HTTP库、解析器、浏览器、字段来源与验证方法 |
| 自建程序和浏览器有实际权限边界与回收 | 隔离、执行账户、容器／进程及受管工具设计 |
| 原任务可解释、结果不丢不重 | 检查点、幂等键、事务及恢复粒度 |
| 方案可带走并在兼容端复用 | 包格式、启动方式、依赖和兼容检查 |
| 清楚易用的管理与查看入口 | 前端框架、现成面板、布局和交互结构 |
| Web 界面与执行服务通过本地 API 解耦，CLI／Web 共用同一任务服务 | 前端框架、组件库、桌面壳、部署方式 |
| v1 可查看任务、网址、商品、基础计数并导出结果 | 统计展示形式、筛选和布局 |

优先免费开源、可自托管、无必需厂商按页／任务配额的本地执行；模型构建、服务器和可选代理仍有成本。首个版本运行目标为单用户单执行机、多网站并发、Windows /Linux兼容环境(含WSL2)，暂不要求先实现分布式多机、所有操作系统原生执行。

## 开发优先级

1. 生成完整可执行方案；固定标准直接作为输入。
2. 框架无运行期LLM依赖地执行并输出合格结果文件，证明方案复跑与复用。
3. 逐步补必要任务控制、可信进度和恢复；首个核心证明可以用命令行／小启动器。
4. 完成用户可用的任务、网址／商品查看、导出与适当统计；高级商业分析后置。

完整目标仍包括控制和数据管理，但不让大面板、复杂暂停恢复或“万能动作语言”挡住首次核心证明。已提供的功能必须真实工作，不能用占位按钮伪装完成。

**v1 的数据管理范围**：至少包括任务、网址、商品的查看与筛选，已发现／有效／排除／失败等基础计数，CSV／JSON 导出和失败说明。图表、趋势、跨任务对比和商业分析可以后置；后置不等于可以用占位按钮伪装完成。

非核心功能先不做，否则会成为负担。不轻易写测试代码，低价值的测试代码也会成为维护负担，并且对开发效率产生深远的不利影响。除非有必要，在恰当的地方和时机编写有明显收益的测试代码。契约、状态不变量、CSV 和安全边界属于明显收益项，应纳入必测；提取正确性用真实样本和灰度验证，不做整页快照。

## 自动推进与异常人工参与

采集系统主要提供AI驱动的自动模式，在确定性验证及质量门禁通过后推进灰度和正式执行，不把逐站人工审批设为业务必经步骤。Agent生成的是候选规则，接纳与推进由实际框架控制，不能通过改样本绕过检查,规则编写后要求测采试运行数据符合标准才能定稿。人工采集模式的支持是可选的，市面上有许多现成的人工驱动采集方案，足够用来分析和采集大部分电商网站，或许可以提供采集系统设计方面的参考。
