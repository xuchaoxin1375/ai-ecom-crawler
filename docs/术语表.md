## 用途与使用方式

本文统一文档、方案包和交付报告里的高频术语，避免同一个词在不同章节指不同对象。定义只做索引和消歧，不替代业务规则；与主题正文冲突时以主题正文为准，并在本文补一句指向。

新增术语前先查这里是否已有近义词；只收录会影响理解或验收的词，不把普通词汇做成词条。本表只保留短定义、状态／操作速查和写法约定，不写项目状态；通俗解释、例子、常见误解和当前现状见[开发、界面与运行时概念说明](27-开发与运行时概念说明.md)。两页都不得覆盖[任务状态与计数契约](09-任务状态与计数契约.md)、[采集规则与任务运行时](19-采集规则与任务运行时.md)等正文。

## 状态与操作速查

本节给用户和实现共同查：状态值和操作语义以[任务状态与计数契约](09-任务状态与计数契约.md)为准，工作项细节以[采集规则与任务运行时](19-采集规则与任务运行时.md)为准。

### 任务操作

| 术语 | 用户意图 | 状态变化 | 能否恢复 | 不要混淆 |
| --- | --- | --- | --- | --- |
| 暂停 | 先停下，之后继续 | `RUNNING` → `PAUSING` → `PAUSED` | 能，从检查点继续 | 不是取消；在途未结清时不能显示“已暂停” |
| 恢复 | 继续暂停或崩溃中断的任务 | `PAUSED` → `QUEUED`／`RUNNING` | 有条件：方案版本、市场、环境兼容 | 不是重跑；不承诺恢复浏览器内存 |
| 取消 | 不打算继续 | `RUNNING` → `CANCELLING` → `CANCELLED` | 不能；只能新建任务 | 不是暂停；取消是终态 |
| 归档 | 从列表收起 | 终态任务移到回收区 | 还原只恢复显示 | 不是删除；不重新采集 |
| 永久移除 | 删除记录、结果和产物 | 独立操作 | 不能 | 不是归档；不删除共享方案和配置 |
| 重跑／再采 | 用新时点、新范围或新版本重新采 | 新 `task_id` | 不是恢复 | 旧任务结果和失败历史保留 |
| 崩溃恢复 | 进程或断电后的自动对账 | `RUNNING` → `RUNNING`／`PAUSED`／`FINISHED`；`CANCELLING` → `CANCELLED` | 自动对账后按条件恢复 | 不是用户取消；不把未知在途当成功 |

### 任务状态

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| `DRAFT` | 已保存，尚未提交执行 | 否 |
| `QUEUED` | 已提交，等待资源 | 否 |
| `RUNNING` | 正在执行 | 否 |
| `PAUSING` | 已请求暂停，在途未结清 | 否 |
| `PAUSED` | 已暂停，在途已结清 | 否 |
| `CANCELLING` | 已请求取消，在途处理中 | 否 |
| `CANCELLED` | 已取消，迟到结果拒收 | 是 |
| `FINISHED` | 已结束，结果见 `outcome` 和 `stop_reason` | 是 |

### 工作项状态

| 状态 | 含义 | 终态 | 重启处理 |
| --- | --- | --- | --- |
| `PENDING` | 待领取，包含等待重试 | 否 | 保留 |
| `IN_FLIGHT` | 已领取，尚未得到结果 | 否 | 回 `PENDING`；领取时已计 `attempts`，不重复加一；耗尽则 `FAILED` |
| `DONE` | 结果已接纳 | 是 | 跳过 |
| `EXCLUDED` | 业务排除，如范围外、重复；robots 不参与放行 | 是 | 跳过，保留原因 |
| `FAILED` | 终态失败，不再重试 | 是 | 跳过；需要时新建任务 |

### 失败分类

`failure_class` 是工作项结果字段，不是状态：

| 值 | 含义 | 典型 | 处理 |
| --- | --- | --- | --- |
| `transient` | 临时故障 | 超时、连接重置、5xx、429 | 尝试次数未耗尽时回 `PENDING`；耗尽后 `FAILED` |
| `permanent` | 明确无重试价值 | 404、410、内容不存在 | 直接 `FAILED`，保留原因 |
| `blocked` | 访问边界或挑战 | 401、403、挑战页 | 任务级停止或等待人工；不静默换出口绕过 |

### 决策与验证状态

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 决策状态 | 技术或架构方向是否已获准进入生产，按 Accepted／Provisional／Proposed 记录 | 不是实现进度，也不是验证结论 | ADR 各页、`21` |
| 验证状态 | 该决策已有多少可复核证据（partial／verified／not_run） | 不等于决策状态；代码合并不自动转 Accepted | `21`、`24` |
| Provisional（暂准） | 方向已确认、验证未完成，允许在限定范围内实现；必须写范围、负责人、回滚和复审条件 | 不是 Accepted；不得扩到未验证能力 | `21`、`24` |
| 技术选型决策 | 写生产代码前，对前端、后端、数据、部署等技术方向做候选比较并选定；记录理由、风险、回退和复审条件 | 不是实现后的补充说明，也不是“先写再改” | `04`、`21` |
| 验证原型 | 先限定时间、范围和通过标准的小规模试做，用来比较技术方案；不是正式产品代码 | 不是生产实现，也不是验收证据 | `21`、ADR 0008 |
| 多路线并行 | 同时试做两条候选路线，用统一指标比较后选定一条；必须有共享契约、预算、停止条件和决策日期 | 不是长期双轨开发，也不是把两套方案都带进生产 | `21`、ADR 0008 |

## 核心对象

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 商品 | 一次采集的业务对象，由实现定义身份并在交付说明中写明 | 同一商品的多网址、多变体和多次请求只算一个商品，不算多个 | `02`、`09` |
| 商品候选 | 按商品身份去重后、尚未得到终局结论的商品 | 不等于有效商品；`候选 = 待处理 + 在途 + 已处理` | `09` |
| 有效商品 | 满足数据标准、进入有效集的商品 | 部分描述可以进入有效集，但必须标记，不能混在无标识记录里 | `02`、`09` |
| 站点 | 一个采集目标网站 | 不是任务或规则包；一个站点可以有多个规则包版本和多个任务 | `01`、`33` |
| 批次（项目） | 一次提交或交付的一组站点和任务，用于组织、筛选和交付 | 不是任务状态或计数单位；批次汇总由成员任务派生，不把商品数简单相加 | `06`、`09`、`33` |
| 方案 | AI 构建的可保存、可执行、可复跑定义，覆盖发现、获取、提取、规范化和校验 | 不是临时脚本，也不依赖构建会话或本机路径 | `01`、`08` |
| 方案包 | 方案的交付外壳：manifest、规则或适配器、可选样本与说明 | 不包含任务进度、结果数据、审批状态、Cookie 或密钥 | `08` |
| manifest | 方案包入口文件，记录标识、版本、站点范围、各阶段引用、兼容信息和证据状态 | 不是任务结果文件；字段名是契约，序列化格式可变 | `08` |
| 任务 | 一次采集执行，有生命周期状态、计数和停止原因 | 不是开发任务 D01～D09，也不是构建会话 | `09` |
| 构建会话 | 构建 Agent 的会话，负责理解站点、写方案和试跑 | 不套用任务生命周期；有独立状态和工作区；可查看、暂停、取消和移除 | `06`、`09`、ADR 0005 |
| harness（Agent 宿主） | 构建期运行 Agent、模型、工具、权限和会话的环境 | 不是采集运行时，也不进入方案包 | `07`、ADR 0005 |
| 构建任务 | 给 harness 的一次构建输入，如站点、范围、预算、权限和输出目录 | 不是采集任务；不套用任务生命周期 | ADR 0005 |
| 工作区 | 构建会话的独立目录，分 `input/`、`work/`、`out/`、`logs/` | 不是方案包；不保存密钥、Cookie 或整页原文 | ADR 0005 |
| 会话事件 | 构建会话的阶段、工具调用、产物和错误记录 | 不是私有推理；不是采集任务事件 | ADR 0005 |
| 构建期 | AI 理解站点、生成和修订方案的阶段，允许多次试跑 | 不是执行期的运行依赖 | `01` |
| 执行期 | 框架按已验证方案执行采集的阶段 | 普通批次不逐页调用 LLM | `01`、`08` |

## 构建与集成

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| BuildService | 本地构建服务，持有构建任务、工作区、事件和产物 | 不是 harness；不是采集任务运行时 | ADR 0006 |
| harness 适配器 | BuildService 到具体 harness 的边界层，负责启动、提交指令、事件、审批、暂停／取消和产物 | 不是 harness 本身；不进入方案包 | ADR 0006 |
| sidecar | 由任务服务托管的独立 harness 进程或服务 | 不是采集运行时；不共享执行期状态 | ADR 0006 |
| 权限基线 | 构建会话默认 `allow`／`ask`／`deny` 的规则集 | 不是沙箱；不是任务状态 | ADR 0006、`20` |
| 暂停门 | 在工具执行前检查暂停标志并扣住权限请求的机制 | 不是取消；不承诺暂停模型推理 | ADR 0006、`20` |
| 依赖请求 | Agent 请求安装缺失依赖的结构化事件，含包、版本、原因和回退 | 不是普通 shell 安装；需记录和审批策略 | `20` |
| 预置环境 | 构建前已安装的运行时、采集库、浏览器和 CLI 基线 | 不是方案包；不随任务结果分发 | `20` |
| 安全沙箱 | OS／VM／容器级隔离，限制 Agent 可访问的文件、进程和网络 | 不是权限基线；v1 不作为前置 | ADR 0006 |
| ACP | Agent Client Protocol，OpenCode 等 harness 的 stdio JSON-RPC 控制协议 | 不是 HTTP API；不是方案包格式 | ADR 0006 |
| SSE | Server-Sent Events，服务器向浏览器单向推送事件的传输方式；用于构建事件流和任务事件 | 不是任务状态；事件需归一化 | ADR 0006、`26` |

## 界面与设计

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 线框（wireframe） | 页面的低保真结构表达：区域、信息层级、入口出口、主次操作和关键状态 | 不是视觉稿、可交互原型或最终页面；确认线框不等于确认颜色和像素 | `06`、`28`、`29`、`27` |
| 线框确认（wireframe review） | 写页面前由需求负责人确认页面结构、信息层级、关键流程、状态和取舍的决策点 | 不是最终 UI 验收，也不是技术评审；技术预览、截图或页面已实现都不等于确认 | `28`、`29`、`27` |
| 视觉稿（mockup） | 高保真表达颜色、字体、图标、间距和整体风格的稿子 | 不是线框；不负责证明任务流程和状态覆盖 | `28`、`27` |
| 原型（prototype） | 可交互的早期页面设计：低保真可点击线框或高保真交互稿，用于验证流程、交互和状态转换 | 不等于静态线框或视觉稿；不是最终实现；也不等于项目里的技术原型（R06／R16 等可运行实现） | `28`、`27` |
| 信息层级 | 页面上哪些信息优先、哪些折叠或进二级页的排序 | 不是 API 字段清单；不是把所有字段铺成列 | `28`、`29`、`27` |
| 状态矩阵 | 逐项列出加载、空、失败、数据过时、部分结果、禁用、已受理、已完成等状态及用户出口 | 不是任务状态表；不是只画正常路径 | `28`、`27` |
| 设计门（design gate） | 新增或改版页面前必须完成最小设计包并评审的关口 | 不是最终验收，也不是技术评审；页面已写不能反推设计合理 | `28`、`27` |
| 整体设计基线 | 在切片实现前确认的页面清单、导航、关键用户旅程、信息层级、状态矩阵和 1280 主规格线框 | 不是每个切片重复整套设计；切片只评审相对基线的增量 | `28`、`29`、`27` |
| 切片增量评审 | 每个切片开始前，只评审相对整体设计基线新增或变更的页面、状态、控件和契约映射 | 不是重新设计整套页面，也不是跳过设计门 | `28`、`26`、`27` |
| 设计系统（design system） | 令牌、基础组件、领域组件、页面模板和交互规范的集合 | 不是一套现成 UI 主题；也不等于单个组件库 | `35`、ADR 0012 |
| 设计令牌（design token） | 把颜色、字号、间距、圆角、阴影和动效写成有语义的变量，页面引用语义而不是具体值 | 不是原始色板；不是页面里的硬编码值 | `35`、ADR 0012 |
| 页面模板（page template） | 列表、详情、导入、技术控制台等页面的固定骨架；新页面先选模板再填内容 | 不是单页设计稿；不是每个页面重新发明布局 | `35` |
| 工作票头（job ticket header） | 每页顶部的紧凑标题区，包含对象身份、当前状态句、主操作和次要操作 | 不是 hero 或营销标题区；不占半屏 | `35` |
| 状态带（status band） | 用分段计数和状态词表达当前阶段，点击可筛选对应对象 | 不是百分比进度条；没有可靠分母时不显示完成率 | `35` |
| 单一工作表面 | 一屏最多一个主要白色工作区，其余内容用分隔线和留白组织 | 不是把所有区块都做成卡片；不是取消分组 | `35` |
| Strangler 模式 | 旧前端继续运行，新前端按页面逐步接管，达到功能对等后切换入口，最后退役旧实现 | 不是页面内混装两套框架；不是长期双轨维护 | `35`、ADR 0012 |

## 流程与位置

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 发现 | 从入口找出目录、分页和商品网址，并区分导航与商品 | 发现数不等于商品数 | `03` |
| 获取 | 取得商品页或公开数据，含必要的等待、动作和会话 | HTTP 200 不能单独证明拿到有效内容 | `03` |
| 浏览器 adapter | 任务级启动 Chromium/Chrome，把渲染后的 DOM 交给提取层；登记并回收进程和 profile | 不是交互脚本；不自动点击、滚动或绕过挑战 | `19` |
| 提取 | 按字段来源从内容中取值 | 与规范化分开：提取负责取到，规范化负责算对 | `02`、`08` |
| 规范化 | 价格、税价、币种、正文清洗、名称和选项的标准化 | 不猜缺失值，不把摘要当完整正文 | `02` |
| 校验 | 检查必需字段、正价、内容断言和失败分类 | 通过校验不等于用户业务验收 | `08` |
| 试跑 | 构建期用小范围真实输入验证方案，可多轮修订 | 不等于灰度，也不等于交付验收 | `01`、`03` |
| 灰度 | 正式执行前的质量步骤：固定真实样本对照，再走小范围实际链路 | 不是全量交付，不能拿几个样本冒充完整结果 | `03`、`04` |
| 正式执行 | 按承诺范围运行已验证方案 | 与试跑、灰度分开记录 | `03` |
| 基准集 | 原始需求提供的完整站点名单，用于广度评估和回归候选 | 不是逐站通过线，也不是已采结论 | `05`、`12` |
| 代表站 | D01 从基准集选出的 5～8 个阶段验收站点 | 一次成功不代表全站或长期可用 | `05`、`12` |
| 通过线 | D01 认定的达标条件，含硬门禁和核心闭环 | 不是加权总分 | `05`、`14` |
| 硬门禁 | 任一不满足即判不通过的条件 | 不能用速度、数量或其他优点抵消 | `13`、`14` |
| 证据 | 可复核的日志、结果、方案版本、环境和时间记录 | 模型自报、截图和测试全绿各只是证据的一部分 | `01`、`04` |

## 网页列表与推进

列表页如何拿到下一批条目，是分诊和方案设计的高频判断点。这里的短定义只用于查词；较长的通俗解释、例子和项目现状见[开发、界面与运行时概念说明](27-开发与运行时概念说明.md)的“列表推进：追加式与替换式虚拟列表”。

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 列表推进 | 从一个列表页取得下一批条目的方式，如页码、next 链接、load more、无限滚动、公开 JSON 分页 | 不是发现来源；同一个列表页可以更换推进方式 | `22`、`27` |
| 分页 | 用页码、next 链接或游标把列表切成多页，通常可直接请求某一页 | 不等于无限滚动，也不等于“全量页” | `22` |
| 追加式列表 | 加载新一批时保留旧条目，DOM 越来越长，最终通常含全部已加载条目 | 不是所有无限滚动；虚拟列表会移除或复用旧行 | `22`、`27` |
| 虚拟列表 | 只渲染当前视口附近少量行，滚动时创建新行并移除或复用旧行；页面上的行数基本不变 | 不是“没有数据”；最终 DOM 只含最后一批，必须逐批累积 | `22`、`27` |
| 替换式虚拟列表 | 本项目对“滚动时旧行从 DOM 消失、换成新行”的虚拟列表的写法；`recycled > 0` 是候选信号 | 不是一种新的分页协议；与追加式相对；真实站点尚未验证 | `19`、`22`、`27` |
| 无限滚动 | 滚动到底部自动加载下一批，通常没有页码按钮 | 不等于虚拟列表；很多站只是追加，旧条目仍在 | `22`、`27` |
| load more | 点击“加载更多”按钮再加载一批 | 可能追加也可能替换；先检查 URL 是否可寻址 | `22`、`27` |
| 稳定 ID | 条目在多次加载间不变的业务标识，如 SKU、商品 ID、canonical URL | 不是行号或 DOM 位置；排序和替换都会改变位置 | `22`、`27` |
| DOM | 浏览器把 HTML 解析成的页面节点树；脚本增删节点后，读取到的 DOM 会变化 | 不是原始 HTML 源码；渲染后的 DOM 才是浏览器里的当前页面 | `22`、`27` |
| `rendered`／`recycled` | adapter 的批次观测值：当前 DOM 条目数／上一批从 DOM 消失的 ID 数 | `recycled > 0` 只说明旧行消失，不等于一定采全；追加式应保持 0 | `19`、`27` |

## 开发与交付

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 开发切片（实施切片） | 范围受控、可独立运行和验收的开发增量，通常是端到端的最小闭环 | 不是数据分片或数组切片，也不是只做一层、页面或功能模块或占位页面；整体设计基线不按切片拆分；“两站切片”是用两个站验证同一条路径，不是把数据切两份 | `26`、`19`、`27` |
| worker（执行器） | 从任务账本领取任务或工作项并执行的进程或线程 | 不是任务本身；一个 worker 可以处理多个任务 | `19`、`26`、`27` |
| 线程池 | 进程内复用的一组线程，用来控制并发度 | 不是多进程，也不等于多机或分布式 | ADR 0003、`19`、`27` |
| 单实例锁 | 保证同一账本同一时间只有一个 worker 进程的锁 | 不是租约；不能按任务或工作项分配所有权，也不能跨机接管 | `26`、`27` |
| 租约 | 带有效期和续约机制的独占持有权；持有者失联或超时后可被接管 | 不是普通互斥锁、任务状态或队列；当前实现范围见 27／15 | `19`、`21`、`23`、`27` |
| WAL | SQLite 的预写日志模式，允许读写并发并支持崩溃恢复 | 不是队列、锁或分布式协调机制 | ADR 0003、`19`、`27` |
| fixture | 固定的本地测试页面、响应或数据，用于可重复、无网络的测试 | 不是真实站点证据；T2 通过不等于实站可用 | `23`、`27` |
| 测试分层 T1～T4 | T1 契约与单元、T2 fixture 集成、T3 有界实站、T4 生产验收 | 不是任务状态或优先级；T1／T2 不能替代 T3／T4 | `23`、`27` |
| adapter（站点适配器） | 为复杂站点交互或特殊获取方式写的适配层，受任务运行时约束 | 不是规则包本身；不等于 harness 适配器 | ADR 0002、ADR 0007、`27` |
| hybrid（混合方案） | 方案用声明式部分完成常规步骤，把虚拟列表等复杂交互交给包内 adapter | 不是新的任务类型；adapter 仍受运行时约束，不是 harness 适配器 | ADR 0007、`27` |

## 并行与调度

并行、并发和批次启动在计划和界面里经常混用；这里只给查词定义，运行细节见[采集规则与任务运行时](19-采集规则与任务运行时.md)和[开发、界面与运行时概念说明](27-开发与运行时概念说明.md)。

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 并发（concurrency） | 系统同时处理多个工作单元的能力或配置上限 | 不等于所有任务都在同一时刻实际执行；受任务槽位、浏览器槽位、限速和资源约束 | ADR 0003、`19`、`27` |
| 并行（parallelism） | 多个任务或工作项在同一时间实际执行 | 不是“已创建”或“已入队”；排队不算并行 | ADR 0003、`19`、`27` |
| 任务级并行 | 多个采集任务同时处于 `RUNNING` 并各自执行 | 不是单个任务内的多个工作项并行，也不等于批次全部站点同时跑 | `19`、`27`、ADR 0004 |
| 工作项级并行 | 一个任务内多个 navigation／product 工作项同时处理 | 不是任务级并行；受规则 `concurrency.navigation`／`product` 限制 | `19`、`27` |
| 任务槽位（`max_tasks`） | 一个 worker 进程同时运行的任务数上限；CLI 参数为 `--max-tasks` | 不是批次站点数、队列长度或浏览器实例数 | `26`、`27`、ADR 0004 |
| 浏览器槽位（`max_browser_tasks`） | 一个 worker 进程同时运行 browser／hybrid 任务的上限；SQLite `browser_slot` 协调同一账本上的多个 worker | 不是任务槽位；浏览器任务仍受任务槽位约束 | `19`、`26`、`27` |
| 批次启动（批量启动） | 为批次内可采站点批量创建任务并置为 `QUEUED` | 只保证入队，不保证同时运行；不是并行执行开关 | `26`、`33`、`27` |
| 排队原因 | 任务处于 `QUEUED` 时，界面根据 worker、槽位和任务状态给出的说明 | 不是失败，也不是停止原因；当前不是独立机器状态或持久字段 | `09`、`25`、`33` |
| A20 | 多任务并行验收场景：两个任务同时运行、至少一个同域、运行中暂停／取消其中一个 | 不是批次启动验收；A20 只覆盖两个任务的并行语义 | `05`、`19`、`23` |

当前口径：`run` 固定 `max_tasks=1`，`worker`／`serve` 默认也是 1；A20 同进程已通过，跨进程 A20 资源配额未闭合。因此 2 个以上任务并行是显式配置，不是当前默认；批次启动 3 个站点时，默认会按队列逐个执行。

## 进程、隔离与资源

v2 的“每任务进程／worker 池／故障隔离”涉及一组容易和线程、任务、浏览器 profile 混用的词；完整解释见[开发、界面与运行时概念说明](27-开发与运行时概念说明.md)的“v2：每任务进程、worker 池与故障隔离”。

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 进程 | 操作系统中的一个独立运行实例，有独立内存和资源 | 不是线程；进程崩溃通常不直接拖垮其他进程 | ADR 0003、`27` |
| 线程 | 进程内的一条执行流，共享进程内存 | 不是进程；一个线程出错可能影响同进程 | ADR 0003、`27` |
| 线程亲和（thread affinity） | 某些对象或库只能由创建它的线程使用，跨线程调用会报错或行为不稳定 | 不是线程安全；也不是把线程绑定到某个 CPU 核 | `19`、`27` |
| 进程池 | 一组可复用的进程，用来承载任务或工作项 | 不是线程池；进程间通信和启动成本更高 | ADR 0003、`27` |
| worker 池 | 一组 worker 执行单元的集合；v2 语境下通常是多个任务进程 | 不是线程池，也不是任务队列；队列决定“下一个做什么”，池决定“谁来执行” | ADR 0003、`27` |
| 每任务进程 | 一个采集任务在独立 OS 进程中运行，任务结束／取消／租约过期／崩溃时回收该进程及其子进程 | 不是每任务一个线程，也不是每个请求一个进程；v2 的具体形态在实现时定 | ADR 0003、`27` |
| 故障隔离 | 把单个任务／站点的崩溃、内存泄漏或浏览器挂起限制在局部，不拖垮主服务和其他任务 | 不是自动重试，不是业务容错，也不是安全沙箱；进程边界不等于权限边界 | ADR 0003、ADR 0006、`27` |
| 进程隔离／崩溃隔离 | 用独立进程边界把单个任务或站点的崩溃、内存泄漏和浏览器挂起限制在局部 | 不是安全沙箱，也不是自动重试；跨进程仍在同一台机器 | ADR 0003、`27` |
| 子进程 | 由主服务、worker 或 adapter 启动的独立 OS 进程，如 adapter、浏览器、harness | 不是 worker 池；也不自动等于安全隔离 | `19`、ADR 0006、`27` |
| 进程组 | 可一起终止的一组进程；超时或取消时按进程组回收子进程树 | 不是任务分组；Windows 用 `taskkill /T`，POSIX 用 `killpg` | `19`、`27` |
| 跨进程 | 多个 OS 进程在同一台机器上协调任务、锁、资源和结果 | 不是跨机；跨机还要共享账本、网络和队列 | ADR 0003、`27` |
| 浏览器实例 | 一个运行中的 Chromium／Chrome 进程及其 profile／context | 不是页面、任务或浏览器槽位；是资源配额单位 | `19`、`26`、`27` |
| 浏览器 profile | 浏览器保存 Cookie、缓存和本地状态的目录；任务级 profile 用来隔离不同任务的会话 | 不是浏览器实例；不是页面；也不是安全沙箱 | `19`、`27` |
| 浏览器上下文（context） | 浏览器内隔离 Cookie、缓存和页面的会话容器；同一浏览器实例可创建多个 context | 不是浏览器实例；不是 profile 目录；也不是任务上下文 | `19`、`27` |
| 任务上下文 | 传给 adapter 或任务进程的结构化输入，含任务 ID、规则版本、范围、预算和输出目录等 | 不是浏览器上下文；不是任务状态；不保存密钥 | `19`、ADR 0001 |
| 资源配额 | 对任务数、浏览器实例、内存、请求等设定的上限和准入条件 | 不是任务计数；配额不足时排队或等待 | ADR 0004、`19`、`27` |
| IPC | 进程间通信，用于传任务上下文、事件、结果和取消信号 | 不是 HTTP API，也不是任务账本 | ADR 0003、`27` |

## 规则与任务运行时

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 采集规则 | 方案中可执行的部分，覆盖网址发现、有效请求、产品提取、输出和限制 | 与“方案”同源，但强调运行时的规则形式；不是临时脚本 | `08`、`19` |
| 规则包 | 采集规则的运行目录：`manifest.yaml`、可选 adapter、样本和说明 | 与“方案包”同源；不保存任务进度、结果或密钥；不是站点或任务，业务用户主流程不应先选规则包 | `08`、`19`、`33` |
| 任务类型 | `discovery` 只发现 URL；`product` 继续提取商品数据 | 不是任务状态；discovery 不能用商品计数 | `19`、`09` |
| 阶段 | `discover`、`fetch`、`extract`、`validate`、`output` 等处理单元 | 阶段是控制单位，不一定是独立进程 | `19` |
| 工作项 | 任务内可检查点、可重试、可并行的最小单位，分 navigation／product | 不等于商品，也不等于一次 HTTP 请求 | `19` |
| 站点任务 | 一个任务默认对应一个站点、一个方案版本和一个市场 | 不等于一个 URL 或一个商品；同站多任务只用于复采、换版本或不同市场 | `09`、ADR 0004 |
| 终态 | 不再变化、不再被重试或迟到结果改变的状态 | 任务终态是 `CANCELLED`／`FINISHED`；工作项终态是 `DONE`／`EXCLUDED`／`FAILED` | `09`、`19` |
| 心跳 | 执行器定期写入的存活信号；过期表示进程可能已崩溃 | 不等于任务失败，也不等于在途项完成 | `19` |
| 删除标记 | 永久移除先写标记，再异步回收记录、结果和产物 | 不是归档；标记期间不再接纳新结果 | `06`、`09` |
| 对账 | 重启后把账本、在途项、输出和资源对齐的过程 | 不是重跑；不把未知当成功 | `09`、`19` |
| 原子写／原子提交 | 结果先持久化，再标记完成；文件写临时再替换，避免半截文件 | 不是“先标记后补结果” | `19`、`27` |
| 任务账本 | 保存任务、工作项、状态和计数的持久记录 | 不是 Scrapling 的 `crawldir`，也不是线程内存 | `19`、`09` |

恢复、重跑／再采和失败分类的短定义见“状态与操作速查”，批次（项目）见“核心对象”；本节不重复。

## 字段与范围

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 基础字段 | 默认完成商品取数必须核对的身份与来源 URL、名称、价格与币种、状态、主图和描述存在性 | 有值不等于可用；缺失、占位和冲突要留因 | `01`、`02`、方法01 |
| 进阶字段 | 完整正文与规格、兼容关系、选项变体、文档和全量覆盖等按任务要求再做的字段 | 不默认全量下钻，也不因未做而伪称完整 | `01`、`05` |
| 描述状态 | 商品描述是否完整、部分、仅摘要、仅适配／清单、原站未提供或提取失败 | 模板摘要、空标签、适配表、套装清单和产品名兜底都不算完整描述 | `02` |

## 结果与状态

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 排除 | 已处理但不进入有效集，如零价、范围外、重复或业务排除 | 与技术失败分开，必须保留原因 | `09` |
| 失败 | 已处理但因访问、提取、环境或方案错误没有结果 | 重试中的候选不算已失败 | `09` |
| 未处理 | 已发现但尚未处理的商品或导航，如预算停止后的剩余范围 | 不是失败，也不能说成全站完成 | `09` |
| 部分描述 | 正文存在难取区块，取得部分内容并标记缺失范围和限制 | 是有效商品的子集，`<= valid_products` | `02`、`09` |
| 摘要回退 | 未取得正文，用有来源的摘要替代 | 不能叫完整正文 | `02` |
| 覆盖 | 任务对已知范围的完成事实，分 `KNOWN`、`PARTIAL`、`UNKNOWN` | 没有可靠分母时不得显示百分比或剩余时间 | `09` |
| 停止原因 | 任务为什么停：自然结束、预算、访问受限、质量阻塞、环境或方案错误、用户取消 | 不替代计数，也不等于业务验收 | `09` |
| 预算停止 | 达到数量、时间或资源上限而停，属于保护性停止 | 保留未完成事实，不自行加预算 | `03`、`09` |
| 业务验收 | 用户认定本次范围是否够用，记录人、时间、理由和范围 | 不覆盖系统停止原因、待处理数量或覆盖未知 | `06`、`09` |
| 检查点 | 恢复所需的最小进度事实，如商品键、来源网址、状态和方案版本 | 不等于缓存里“看起来完成” | `09` |
| 幂等键 | 保证重试、重复提交和恢复不产生重复商品或计数的键 | 常见形式为 `(task_id, product_key)` | `09` |
| 迟到结果 | 取消后到达的执行结果 | 一律拒收，不进入有效集或计数 | `09` |
| 回收区 | 终态任务的可见性归档 | 不是生命周期状态；还原不重新采集 | `09` |

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| `schema_version` | 方案包契约版本 | 与站点方案版本无关；执行端不认识的版本应拒绝加载 | `08` |

## 写法约定

- **暂停、取消、崩溃、恢复**：暂停是“停止派发、在途结清、之后继续”，状态是 `PAUSING`／`PAUSED`；取消是“不打算继续”，状态是 `CANCELLING`／`CANCELLED`，取消后不能恢复。崩溃是进程或断电导致的非用户中断，不是状态；重启后先对账，再决定恢复或结束。恢复只用于暂停或崩溃中断的任务，重跑／再采用新任务。文档和界面不用“停止”代替其中任何一种；按钮写“暂停”和“取消任务”。
- **方案与规则包**：业务和对外契约统一写“方案”，字段用 `plan_id`／`plan_version`；运行设计写“规则包”时指同一对象的执行形态，字段 `rule_id`／`rule_version` 必须映射到 `plan_*`，不能对外暴露两套版本。
- **harness、适配器、构建会话与采集任务**：harness 是构建期宿主；构建会话是 harness 的一次受管运行；`HarnessAdapter` 是 BuildService 到 harness 的边界；采集任务是执行期对象。三者状态不互相映射，方案包是它们之间唯一的交付物。
- **任务与站点任务**：默认一个任务对应一个站点、一个方案版本和一个市场；需要强调粒度时写“站点任务”，不把单个 URL 或商品叫任务。
- **商品与产品**：采集对象统一写“商品”；“产品”只在引用原文或描述业务统称（如“产品数据采集应用”）时出现。
- **采集、抓取、爬取**：业务流程统一写“采集”；“抓取”只指获取页面这一层动作；“爬取”不单独使用。
- **站点与网站**：作为采集目标写“站点”；“网站”只用于一般描述。
- **切片**：统一指开发切片；数据切分写“分片”，数组或字符串操作写“截取／切片”并注明上下文。说“两站切片”时补一句“两个站验证同一条路径”，避免被读成数据分区。切片是交付单位，不是页面或功能模块；整体设计基线按用户旅程组织，不按切片拆分。
- **租约与锁**：默认单机单 worker 仍是“单实例锁”；讨论多进程所有权时写“租约”。当前实现范围见 27／15。
- **英文术语**：`sitemap`、selector、manifest、token 等首次出现给中文解释，之后可保留英文；字段名、状态值和文件名按原文书写。
- **线框、视觉稿与原型**：业务确认阶段写“线框”或“线框确认”，不要用“设计稿”笼统指三者；原型可以是低保真或高保真，不等于最终实现或项目里的技术原型；线框确认是设计评审中的一个决策点，不等于完整设计门或最终验收；页面已实现、截图或测试通过也不等于线框确认。
- **状态与计数**：写状态值时用反引号包住机器值（如 `RUNNING`），描述用中文；计数键名同样保留原文。
