## 用途与使用方式

本文统一文档、方案包和交付报告里的高频术语，避免同一个词在不同章节指不同对象。定义只做索引和消歧，不替代业务规则；与主题正文冲突时以主题正文为准，并在本文补一句指向。

新增术语前先查这里是否已有近义词；只收录会影响理解或验收的词，不把普通词汇做成词条。

## 状态与操作速查

本节给用户和实现共同查：状态值和操作语义以[任务状态与计数契约](09-任务状态与计数契约.md)为准，工作项细节以[采集规则与任务运行时](19-采集规则与任务运行时.md)为准。

### 任务操作

| 术语 | 用户意图 | 状态变化 | 能否恢复 | 不要混淆 |
| --- | --- | --- | --- | --- |
| 暂停 | 先停下，之后继续 | `RUNNING` → `PAUSING` → `PAUSED` | 能，从检查点继续 | 不是取消；在途未结清时不能显示“已暂停” |
| 恢复 | 继续暂停或崩溃中断的任务 | `PAUSED` → `QUEUED`／`RUNNING` | 有条件：方案版本、市场、环境兼容 | 不是重跑；不承诺恢复浏览器内存 |
| 取消 | 不打算继续 | `RUNNING` → `CANCELLING` → `CANCELLED` | 不能；只能新建任务 | 不是暂停；取消是终态 |
| 归档 | 从列表收起 | 终态任务移到回收区 | 还原只恢复显示 | 不是删除；不重新采集 |
| 永久移除 | 删除记录、结果和产物 | 独立操作 | 不能 | 不是归档；不删除共享方案和配置 |
| 重跑／再采 | 用新时点、新范围或新版本重新采 | 新 `task_id` | 不是恢复 | 旧任务结果和失败历史保留 |
| 崩溃恢复 | 进程或断电后的自动对账 | `RUNNING` → `RUNNING`／`PAUSED`／`FINISHED`；`CANCELLING` → `CANCELLED` | 自动对账后按条件恢复 | 不是用户取消；不把未知在途当成功 |

### 任务状态

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| `DRAFT` | 已保存，尚未提交执行 | 否 |
| `QUEUED` | 已提交，等待资源 | 否 |
| `RUNNING` | 正在执行 | 否 |
| `PAUSING` | 已请求暂停，在途未结清 | 否 |
| `PAUSED` | 已暂停，在途已结清 | 否 |
| `CANCELLING` | 已请求取消，在途处理中 | 否 |
| `CANCELLED` | 已取消，迟到结果拒收 | 是 |
| `FINISHED` | 已结束，结果见 `outcome` 和 `stop_reason` | 是 |

### 工作项状态

| 状态 | 含义 | 终态 | 重启处理 |
| --- | --- | --- | --- |
| `PENDING` | 待领取，包含等待重试 | 否 | 保留 |
| `IN_FLIGHT` | 已领取，尚未得到结果 | 否 | 回 `PENDING`；领取时已计 `attempts`，不重复加一；耗尽则 `FAILED` |
| `DONE` | 结果已接纳 | 是 | 跳过 |
| `EXCLUDED` | 业务排除，如范围外、重复、robots 禁止 | 是 | 跳过，保留原因 |
| `FAILED` | 终态失败，不再重试 | 是 | 跳过；需要时新建任务 |

### 失败分类

`failure_class` 是工作项结果字段，不是状态：

| 值 | 含义 | 典型 | 处理 |
| --- | --- | --- | --- |
| `transient` | 临时故障 | 超时、连接重置、5xx、429 | 尝试次数未耗尽时回 `PENDING`；耗尽后 `FAILED` |
| `permanent` | 明确无重试价值 | 404、410、内容不存在 | 直接 `FAILED`，保留原因 |
| `blocked` | 访问边界或挑战 | 401、403、挑战页 | 任务级停止或等待人工；不静默换出口绕过 |

## 核心对象

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 商品 | 一次采集的业务对象，由实现定义身份并在交付说明中写明 | 同一商品的多网址、多变体和多次请求只算一个商品，不算多个 | `02`、`09` |
| 商品候选 | 按商品身份去重后、尚未得到终局结论的商品 | 不等于有效商品；`候选 = 待处理 + 在途 + 已处理` | `09` |
| 有效商品 | 满足数据标准、进入有效集的商品 | 部分描述可以进入有效集，但必须标记，不能混在无标识记录里 | `02`、`09` |
| 方案 | AI 构建的可保存、可执行、可复跑定义，覆盖发现、获取、提取、规范化和校验 | 不是临时脚本，也不依赖构建会话或本机路径 | `01`、`08` |
| 方案包 | 方案的交付外壳：manifest、规则或适配器、可选样本与说明 | 不包含任务进度、结果数据、审批状态、Cookie 或密钥 | `08` |
| manifest | 方案包入口文件，记录标识、版本、站点范围、各阶段引用、兼容信息和证据状态 | 不是任务结果文件；字段名是契约，序列化格式可变 | `08` |
| 任务 | 一次采集执行，有生命周期状态、计数和停止原因 | 不是开发任务 D01～D09，也不是构建会话 | `09` |
| 构建会话 | 构建 Agent 的会话，负责理解站点、写方案和试跑 | 不套用任务生命周期；有独立状态和工作区；可查看、暂停、取消和移除 | `06`、`09`、ADR 0005 |
| harness（Agent 宿主） | 构建期运行 Agent、模型、工具、权限和会话的环境 | 不是采集运行时，也不进入方案包 | `07`、ADR 0005 |
| 构建任务 | 给 harness 的一次构建输入，如站点、范围、预算、权限和输出目录 | 不是采集任务；不套用任务生命周期 | ADR 0005 |
| 工作区 | 构建会话的独立目录，分 `input/`、`work/`、`out/`、`logs/` | 不是方案包；不保存密钥、Cookie 或整页原文 | ADR 0005 |
| 会话事件 | 构建会话的阶段、工具调用、产物和错误记录 | 不是私有推理；不是采集任务事件 | ADR 0005 |
| 构建期 | AI 理解站点、生成和修订方案的阶段，允许多次试跑 | 不是执行期的运行依赖 | `01` |
| 执行期 | 框架按已验证方案执行采集的阶段 | 普通批次不逐页调用 LLM | `01`、`08` |

## 构建与集成

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| BuildService | 本地构建服务，持有构建任务、工作区、事件和产物 | 不是 harness；不是采集任务运行时 | ADR 0006 |
| harness 适配器 | BuildService 到具体 harness 的边界层，负责启动、提交指令、事件、审批、暂停／取消和产物 | 不是 harness 本身；不进入方案包 | ADR 0006 |
| sidecar | 由任务服务托管的独立 harness 进程或服务 | 不是采集运行时；不共享执行期状态 | ADR 0006 |
| 权限基线 | 构建会话默认 `allow`／`ask`／`deny` 的规则集 | 不是沙箱；不是任务状态 | ADR 0006、`20` |
| 暂停门 | 在工具执行前检查暂停标志并扣住权限请求的机制 | 不是取消；不承诺暂停模型推理 | ADR 0006、`20` |
| 依赖请求 | Agent 请求安装缺失依赖的结构化事件，含包、版本、原因和回退 | 不是普通 shell 安装；需记录和审批策略 | `20` |
| 预置环境 | 构建前已安装的运行时、采集库、浏览器和 CLI 基线 | 不是方案包；不随任务结果分发 | `20` |
| 安全沙箱 | OS／VM／容器级隔离，限制 Agent 可访问的文件、进程和网络 | 不是权限基线；v1 不作为前置 | ADR 0006 |
| ACP | Agent Client Protocol，OpenCode 等 harness 的 stdio JSON-RPC 控制协议 | 不是 HTTP API；不是方案包格式 | ADR 0006 |
| SSE | Server-Sent Events，OpenCode 事件流传输方式 | 不是任务状态；事件需归一化 | ADR 0006 |

## 流程与位置

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 发现 | 从入口找出目录、分页和商品网址，并区分导航与商品 | 发现数不等于商品数 | `03` |
| 获取 | 取得商品页或公开数据，含必要的等待、动作和会话 | HTTP 200 不能单独证明拿到有效内容 | `03` |
| 提取 | 按字段来源从内容中取值 | 与规范化分开：提取负责取到，规范化负责算对 | `02`、`08` |
| 规范化 | 价格、税价、币种、正文清洗、名称和选项的标准化 | 不猜缺失值，不把摘要当完整正文 | `02` |
| 校验 | 检查必需字段、正价、内容断言和失败分类 | 通过校验不等于用户业务验收 | `08` |
| 试跑 | 构建期用小范围真实输入验证方案，可多轮修订 | 不等于灰度，也不等于交付验收 | `01`、`03` |
| 灰度 | 正式执行前的质量步骤：固定真实样本对照，再走小范围实际链路 | 不是全量交付，不能拿几个样本冒充完整结果 | `03`、`04` |
| 正式执行 | 按承诺范围运行已验证方案 | 与试跑、灰度分开记录 | `03` |
| 基准集 | 原始需求提供的完整站点名单，用于广度评估和回归候选 | 不是逐站通过线，也不是已采结论 | `05`、`12` |
| 代表站 | D01 从基准集选出的 5～8 个阶段验收站点 | 一次成功不代表全站或长期可用 | `05`、`12` |
| 通过线 | D01 认定的达标条件，含硬门禁和核心闭环 | 不是加权总分 | `05`、`14` |
| 硬门禁 | 任一不满足即判不通过的条件 | 不能用速度、数量或其他优点抵消 | `13`、`14` |
| 证据 | 可复核的日志、结果、方案版本、环境和时间记录 | 模型自报、截图和测试全绿各只是证据的一部分 | `01`、`04` |

## 规则与任务运行时

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 采集规则 | 方案中可执行的部分，覆盖网址发现、有效请求、产品提取、输出和限制 | 与“方案”同源，但强调运行时的规则形式；不是临时脚本 | `08`、`19` |
| 规则包 | 采集规则的运行目录：`manifest.yaml`、可选 adapter、样本和说明 | 与“方案包”同源；不保存任务进度、结果或密钥 | `08`、`19` |
| 任务类型 | `discovery` 只发现 URL；`product` 继续提取商品数据 | 不是任务状态；discovery 不能用商品计数 | `19`、`09` |
| 阶段 | `discover`、`fetch`、`extract`、`validate`、`output` 等处理单元 | 阶段是控制单位，不一定是独立进程 | `19` |
| 工作项 | 任务内可检查点、可重试、可并行的最小单位，分 navigation／product | 不等于商品，也不等于一次 HTTP 请求 | `19` |
| 站点任务 | 一个任务默认对应一个站点、一个方案版本和一个市场 | 不等于一个 URL 或一个商品；同站多任务只用于复采、换版本或不同市场 | `09`、ADR 0004 |
| 批次 | 多个站点任务的展示分组 | 不是任务状态，不合并计数 | ADR 0004 |
| 终态 | 不再变化、不再被重试或迟到结果改变的状态 | 任务终态是 `CANCELLED`／`FINISHED`；工作项终态是 `DONE`／`EXCLUDED`／`FAILED` | `09`、`19` |
| 失败分类 | 工作项失败的可重试性：`transient`、`permanent`、`blocked` | 不是工作项状态；`FAILED` 才是状态 | `19` |
| 心跳 | 执行器定期写入的存活信号；过期表示进程可能已崩溃 | 不等于任务失败，也不等于在途项完成 | `19` |
| 删除标记 | 永久移除先写标记，再异步回收记录、结果和产物 | 不是归档；标记期间不再接纳新结果 | `06`、`09` |
| 对账 | 重启后把账本、在途项、输出和资源对齐的过程 | 不是重跑；不把未知当成功 | `09`、`19` |
| 恢复 | 从暂停或崩溃中断的检查点继续同一任务 | 不是重跑；不承诺浏览器内存 | `09` |
| 重跑／再采 | 用新任务重新采集 | 不是恢复；旧结果保留 | `06`、`09` |
| 原子提交 | 结果先持久化，再标记完成；文件写临时再替换 | 不是“先标记后补结果” | `19` |
| 任务账本 | 保存任务、工作项、状态和计数的持久记录 | 不是 Scrapling 的 `crawldir`，也不是线程内存 | `19`、`09` |

## 字段与范围

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 基础字段 | 默认完成商品取数必须核对的身份与来源 URL、名称、价格与币种、状态、主图和描述存在性 | 有值不等于可用；缺失、占位和冲突要留因 | `01`、`02`、方法01 |
| 进阶字段 | 完整正文与规格、兼容关系、选项变体、文档和全量覆盖等按任务要求再做的字段 | 不默认全量下钻，也不因未做而伪称完整 | `01`、`05` |
| 描述状态 | 商品描述是否完整、部分、仅摘要、仅适配／清单、原站未提供或提取失败 | 模板摘要、空标签、适配表、套装清单和产品名兜底都不算完整描述 | `02` |

## 结果与状态

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| 排除 | 已处理但不进入有效集，如零价、范围外、重复或业务排除 | 与技术失败分开，必须保留原因 | `09` |
| 失败 | 已处理但因访问、提取、环境或方案错误没有结果 | 重试中的候选不算已失败 | `09` |
| 未处理 | 已发现但尚未处理的商品或导航，如预算停止后的剩余范围 | 不是失败，也不能说成全站完成 | `09` |
| 部分描述 | 正文存在难取区块，取得部分内容并标记缺失范围和限制 | 是有效商品的子集，`<= valid_products` | `02`、`09` |
| 摘要回退 | 未取得正文，用有来源的摘要替代 | 不能叫完整正文 | `02` |
| 覆盖 | 任务对已知范围的完成事实，分 `KNOWN`、`PARTIAL`、`UNKNOWN` | 没有可靠分母时不得显示百分比或剩余时间 | `09` |
| 停止原因 | 任务为什么停：自然结束、预算、访问受限、质量阻塞、环境或方案错误、用户取消 | 不替代计数，也不等于业务验收 | `09` |
| 预算停止 | 达到数量、时间或资源上限而停，属于保护性停止 | 保留未完成事实，不自行加预算 | `03`、`09` |
| 业务验收 | 用户认定本次范围是否够用，记录人、时间、理由和范围 | 不覆盖系统停止原因、待处理数量或覆盖未知 | `06`、`09` |
| 检查点 | 恢复所需的最小进度事实，如商品键、来源网址、状态和方案版本 | 不等于缓存里“看起来完成” | `09` |
| 幂等键 | 保证重试、重复提交和恢复不产生重复商品或计数的键 | 常见形式为 `(task_id, product_key)` | `09` |
| 迟到结果 | 取消后到达的执行结果 | 一律拒收，不进入有效集或计数 | `09` |
| 回收区 | 终态任务的可见性归档 | 不是生命周期状态；还原不重新采集 | `09` |

## 版本与兼容

| 术语 | 含义 | 不要混淆 | 出处 |
| --- | --- | --- | --- |
| `schema_version` | 方案包契约版本 | 与站点方案版本无关；执行端不认识的版本应拒绝加载 | `08` |
| `plan_id` | 方案标识，站点级稳定值 | 不是任务编号；对外统一用 `plan_id`，运行实现可映射 `rule_id` | `08`、`19` |
| `plan_version` | 站点方案版本，提取规则、范围、字段来源或校验条件实质变化时递增 | 不因新方案发布改写旧任务结果；运行时 `rule_version` 必须映射到此字段 | `08`、`19` |
| `rule_id`／`rule_version` | 运行时对方案标识和版本的字段名 | 不是第二套版本；任务记录和 `task-result.json` 必须映射为 `plan_id`／`plan_version` | `19`、ADR 0003 |
| 兼容环境 | 满足方案 `compatibility` 的操作系统、运行时、浏览器和依赖条件的执行端 | 导入成功不等于原历史结果自动有效 | `08`、`10` |
| `verified` | 方案成熟度标记，表示有可核对证据 | 不是用户验收状态，不能由模型自报 | `08` |
| 人工验收 | 用户确认范围够用的业务结论 | 与技术证据并列保留，不互相覆盖 | `09` |

## 写法约定

- **暂停、取消、崩溃、恢复**：暂停是“停止派发、在途结清、之后继续”，状态是 `PAUSING`／`PAUSED`；取消是“不打算继续”，状态是 `CANCELLING`／`CANCELLED`，取消后不能恢复。崩溃是进程或断电导致的非用户中断，不是状态；重启后先对账，再决定恢复或结束。恢复只用于暂停或崩溃中断的任务，重跑／再采用新任务。文档和界面不用“停止”代替其中任何一种；按钮写“暂停”和“取消任务”。
- **方案与规则包**：业务和对外契约统一写“方案”，字段用 `plan_id`／`plan_version`；运行设计写“规则包”时指同一对象的执行形态，字段 `rule_id`／`rule_version` 必须映射到 `plan_*`，不能对外暴露两套版本。
- **harness、适配器、构建会话与采集任务**：harness 是构建期宿主；构建会话是 harness 的一次受管运行；`HarnessAdapter` 是 BuildService 到 harness 的边界；采集任务是执行期对象。三者状态不互相映射，方案包是它们之间唯一的交付物。
- **任务与站点任务**：默认一个任务对应一个站点、一个方案版本和一个市场；需要强调粒度时写“站点任务”，不把单个 URL 或商品叫任务。
- **商品与产品**：采集对象统一写“商品”；“产品”只在引用原文或描述业务统称（如“产品数据采集应用”）时出现。
- **采集、抓取、爬取**：业务流程统一写“采集”；“抓取”只指获取页面这一层动作；“爬取”不单独使用。
- **站点与网站**：作为采集目标写“站点”；“网站”只用于一般描述。
- **英文术语**：`sitemap`、selector、manifest、token 等首次出现给中文解释，之后可保留英文；字段名、状态值和文件名按原文书写。
- **状态与计数**：写状态值时用反引号包住机器值（如 `RUNNING`），描述用中文；计数键名同样保留原文。
