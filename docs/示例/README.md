## 示例的用途

除[旧格式导出样例](法国运动用品数据导出样例.csv)和[旧工具规则参考](<火车头采集器单站点规则(局部)导出示例.xml>)外，这里其余文件全部是**合成数据**，网址使用保留的`.example`域名，时间、价格、数量和人名均为示意；没有访问这些地址或执行采集。两个旧文件由用户提供，仅用于格式、描述和旧工作形式参考，不代表本项目访问过该站点。字段是沟通示例，团队可以采用其他内部Schema，只需完整映射业务含义。

| 文件 | 内容 |
| --- | --- |
| [商品记录](商品记录.json) | 两条正价有效商品的内部完整记录；一条完整正文，一条明确部分提取 |
| [排除记录](排除记录.json) | 一个零价候选，保留网址和明确原因，不进入有效商品CSV |
| [商品CSV](商品导出.csv) | 对应两条有效记录的最终业务导出，只含9列核心字段 |
| [任务结果](任务结果.json) | 三个商品候选已处理，两个有效／一个排除；仍有目录分支，状态为已结束但结果为部分，覆盖未知，用户已验收；`quality_exceptions`列出部分描述；品牌等可空字段缺失不进入质量异常 |
| [旧格式导出样例](法国运动用品数据导出样例.csv) | 用户提供的旧12列导出，只用于描述和属性参考；SKU、Regular/Sale价格、Tags、Images文件名等不进入系统标准合同 |
| [旧工具规则参考](<火车头采集器单站点规则(局部)导出示例.xml>) | 用户提供的火车头单站规则导出（局部），只用于理解旧工作形式；不解析、不执行，不作为新规则格式或兼容输入 |

旧格式样例的`Description`包含营销正文和`Informations complémentaires`规格表。系统标准导出保留同样的描述范围，但只输出9列；规格表留在`description_html`中，`attributes`只表示可购买选项。旧格式的其余列由后期独立程序转换。

## 旧工具规则参考

`火车头采集器单站点规则(局部)导出示例.xml` 是用户提供的旧工具单站规则导出，只用于理解旧工作形式：单站、正则／XPath／C# 过滤器、本地路径和插件耦合。它不进入 Agent 输入，不被 harness 或运行时解析，也不是新规则格式或兼容输入。文件保留旧工具的本地路径和代理设置，用于理解工作形式；不含密钥，也不应作为新配置模板。

新方案按[采集方案与兼容契约](../08-采集方案与兼容契约.md)和[采集规则与任务运行时](../19-采集规则与任务运行时.md)的 manifest 和规则包表达；旧文件中的本地绝对路径、代理、插件和站点专用代码不复制到新方案。旧工具对照仍按[项目定位与可行性](../00-项目定位与可行性.md)的 J07 处理。

## 对照检查

第一商品的S码含税价29.00、未税价24.17，M码更高，最低项缺货仍有效。示例取24.17英镑，注明未税，保留公开Size／Color选项，不输出完整变体报价矩阵。

商品记录是内部完整数据，保留`description_format`、市场／语言、库存、税价口径、方案标识和提取时间；最终CSV只导出9列业务字段，`description_html`统一为清洗后HTML。`attributes`是内部`options`的序列化；`missing_reasons`和`partial_reason`在任务结果的`quality_exceptions`中按`source_url`列出，但品牌等可空字段缺失不进入质量异常，空对象为`{}`。

第二商品部分复杂适配表未能取得，有可用产品说明并标记部分。它仍可进入有效商品集，但预览、任务报告和`quality_exceptions`均不能把它算成完整正文；最终CSV不逐行携带质量标记。

第三个候选原站展示价为零，不满足本文档正价要求，进入排除记录。三个已处理商品不表示目录已经全部探索完；例中的两个待访问目录和预算停止仍保留，人工验收另记为业务结论。

任务结果的状态、计数和覆盖字段按[任务状态与计数契约](../09-任务状态与计数契约.md)解释。

所有文件采用UTF-8。CSV属性串是兼容表达；内部选项保持结构化。示例没有覆盖全部边界，真实测试仍须实现[验收场景](../05-验收场景与比较方法.md)。
