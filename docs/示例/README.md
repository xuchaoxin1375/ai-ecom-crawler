## 示例的用途

这里全部是**合成数据**，网址使用保留的`.example`域名，时间、价格、数量和人名均为示意；没有访问这些地址或执行采集。字段是沟通示例，团队可以采用其他内部Schema，只需完整映射业务含义。

| 文件 | 内容 |
| --- | --- |
| [商品记录](商品记录.json) | 两条正价有效商品；一条完整正文，一条明确部分提取 |
| [排除记录](排除记录.json) | 一个零价候选，保留网址和明确原因，不进入有效商品CSV |
| [商品CSV](商品导出.csv) | 对应两条有效记录，保留HTML、选项、税价口径及部分描述说明 |
| [任务结果](任务结果.json) | 三个商品候选已处理，两个有效／一个排除；仍有目录分支，状态为已结束但结果为部分，覆盖未知，用户已验收 |

## 对照检查

第一商品的S码含税价29.00、未税价24.17，M码更高，最低项缺货仍有效。示例取24.17英镑，注明未税，保留公开Size／Color选项，不输出完整变体报价矩阵。

第二商品部分复杂适配表未能取得，有可用产品说明并标记部分。它仍可进入有效商品集，但预览、CSV和任务报告均不能把它算成完整正文。

第三个候选原站展示价为零，不满足本文档正价要求，进入排除记录。三个已处理商品不表示目录已经全部探索完；例中的两个待访问目录和预算停止仍保留，人工验收另记为业务结论。

任务结果的状态、计数和覆盖字段按[任务状态与计数契约](../09-任务状态与计数契约.md)解释。

所有文件采用UTF-8。CSV属性串是兼容表达；内部选项保持结构化。示例没有覆盖全部边界，真实测试仍须实现[验收场景](../05-验收场景与比较方法.md)。
