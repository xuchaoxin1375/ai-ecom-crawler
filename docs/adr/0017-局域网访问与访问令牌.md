## 状态与适用范围

**Accepted**（2026-11-25）。本 ADR 扩展[D08 任务服务与界面设计](../26-D08任务服务与界面设计.md#安全边界)的回环绑定边界：允许在可信局域网内，通过显式启动参数和访问令牌，从另一台设备查看和操作 Web UI。运行期的局域网开关、令牌轮换和系统设置页见 [ADR 0018](0018-系统设置页与运行时局域网控制.md)；本 ADR 的启动边界仍然有效。

不改变单用户、单机 SQLite、单 worker、无 CORS 和构建 Harness 回环边界；不提供 TLS、多用户、独立账号、公网暴露或反向代理鉴权。需要公网、HTTPS 或多人权限时另做安全设计，不把本令牌当成多用户模型。

## 背景

- 当前 `serve` 默认绑定 `127.0.0.1`，CLI 拒绝非回环地址，中间件也拒绝非回环 `Host`；这是有意的 v1 安全边界，不是漏配。
- 实际使用中需要在同一可信局域网的另一台电脑启动、暂停、取消任务或发起构建；只读预览不足以覆盖该场景。
- 服务没有账号、会话或权限模型；直接绑定 `0.0.0.0` 会让同网段任何人获得写权限，可能触发采集、构建和模型费用。
- [D08 设计](../26-D08任务服务与界面设计.md)原先写明“除非显式增加启动参数（v1 不提供）”；本 ADR 提供该参数，同时要求令牌和 Host 校验。

## 决策

- **默认边界不变**：不传 `--host` 时仍绑定 `127.0.0.1`，不要求认证。
- **非回环绑定必须带令牌**：`--host` 为 `localhost`／回环地址以外的地址时，必须同时提供 `--access-token` 或 `ECOM_SERVE_TOKEN`，令牌至少 16 个字符；缺失或过短时拒绝启动。不自动生成令牌，避免重启后凭据静默变化。
- **认证方式**：HTTP Basic，用户名忽略，密码为访问令牌；所有请求（页面、API、SSE、导出和静态资源）都要求认证。缺失或错误返回 401，并带 `WWW-Authenticate: Basic realm="ecom-crawler"` 触发浏览器认证框。令牌只保存在进程内，不写入账本、日志或 `app.state`；从环境变量读取后立即从服务进程环境移除，避免构建子进程继承。
- **Host 允许列表**：只接受回环、本机检测到的 IP／主机名，以及 `--allow-host` 追加的名称；不按任意 `Host` 放行。自动检测失败或使用 mDNS 名称时用 `--allow-host` 补充。
- **写保护保持**：写请求仍要求 `Origin` 与 `Host` 完全一致，并带 `X-Requested-With: XMLHttpRequest`；不引入 CORS。`--read-only` 与局域网组合时，认证通过后写接口仍返回 403 `READ_ONLY`。
- **启动输出**：只打印可用地址和认证方式，不打印令牌本身；无法检测局域网地址时提示使用 `--allow-host`。
- **信任边界**：只用于可信局域网。HTTP 明文传输，Basic 凭据可被同网段嗅探；不做端口映射、公网反向代理或跨不可信网络使用。令牌换发需要重启服务。

## 实施

- `app/src/ecom_crawler/cli.py`：`--access-token`、`--allow-host`、令牌长度与非回环绑定校验、本机地址检测和启动地址输出。
- `app/src/ecom_crawler/web/app.py`：`create_app(access_token=..., allowed_hosts=...)`、Basic 认证中间件、Host 允许列表和同源写校验。
- `app/tests/test_cli.py`：非回环无令牌、短令牌、环境变量、`--allow-host` 和 URL 形式拒绝。
- `app/tests/test_web.py`：缺失／错误／正确令牌、局域网 Host、拒绝未知 Host、同源写、回环也需认证、只读与认证顺序。
- 文档：`26` 安全边界、`25`／`01`／`31` 的单用户与远程访问表述、`app/README.md` 的局域网启动说明。

## 后果

- 用户不必改回环绑定或使用 SSH 隧道，即可在另一台电脑操作；默认本地使用不受影响。
- 设置令牌后，本机浏览器同样会弹出认证框；这是有意的统一保护，避免依赖来源地址区分权限。
- 令牌通过环境变量传入时不会进入 shell 历史；通过 `--access-token` 传入时会出现在 shell 历史和进程列表，文档优先推荐环境变量。
- Host 允许列表依赖启动时检测；网络切换、IP 变化或使用未登记的主机名时需要重启或加 `--allow-host`。
- HTTP 明文和单令牌意味着同网段嗅探、共享令牌和无法审计到人；这些限制在“可信局域网、单用户”前提下接受。
- 不解决公网暴露、TLS、多用户、只读账号、令牌轮换和按操作审计；需要时另立 ADR。

## 验证与证据

- 后端：`app/tests/test_web.py` 覆盖 401 认证挑战、错误令牌、局域网 Host、未知 Host 403、同源写 201／跨源 403、回环也需认证、`allowed_hosts` 缺少令牌时报错，以及只读模式下认证先于写拒绝。
- CLI：`app/tests/test_cli.py` 覆盖默认回环无需令牌、环境变量令牌、非回环无令牌拒绝、短令牌拒绝、`--allow-host` 校验和 `--allow-host` 只用于非回环绑定。
- 临时服务：从本机局域网地址访问 `/api/health` 验证 401／200、未知 Host 403、写请求缺少自定义头 403；真实 Chromium 带 Basic 凭据加载 `/next/`，页面和 `/api/health` 均正常。
- 未覆盖：真实另一台设备的浏览器认证、Windows 防火墙规则、mDNS 名称、HTTPS／反向代理、多用户和令牌轮换。首次实际使用时需在目标局域网补一次端到端走查。

## 替代方案

- **保持只读回环，用 SSH 隧道或远程桌面**：不新增攻击面，但无法满足另一台电脑直接操作，且对非技术用户门槛高；不采用。
- **只绑定 `0.0.0.0`、不加认证**：改动最小，但同网段任何人可发起采集和构建，风险和费用不可接受；不采用。
- **Bearer 令牌或查询参数**：EventSource 和下载链接不便加请求头，查询参数容易进入日志；认证覆盖不完整，不采用。
- **登录页 + HttpOnly Cookie**：体验更自然，但需要新增前端路由、Cookie 生命周期和 CSRF 处理，超出本轮“配置入口”的范围；暂不采用。
- **自动生成并打印令牌**：省一步配置，但重启后令牌静默变化，远端保存的凭据失效且不易排查；不采用。
- **TLS／反向代理鉴权**：适合公网或多用户，但需要证书、代理信任和权限模型；本轮明确不做。
