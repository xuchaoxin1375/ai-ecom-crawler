## 状态与适用范围

**Accepted**（2026-11-27，验证 partial）。本 ADR 决定把工作台底部的“运行事件”和“原始日志”合并成一个终端式单行日志查看器，并为 `events.ndjson` 增加历史游标、准确总数和 SSE 增量加载；秒级时间、跟随最新、详情查看和大日志加载是同一套能力。单行查看器、秒级时间、可选年月日、历史游标、SSE 增量、前端虚拟列表和服务端尾部读取已实现，当前待项目方验收。

本 ADR 只覆盖任务运行日志。构建时间线仍按[构建会话时间线设计](../46-构建会话时间线设计.md)执行；任务状态机、计数口径、事件写入格式和导出契约不变。现有 `tail=200` 实现已由单行查看器替换，旧 `tail` 参数保留兼容。

## 背景

任务运行日志来自 `out/<task_id>/events.ndjson`，每行一个 JSON 事件，追加写入并 fsync。真实日志样本显示了三个问题：

- 一个完整任务就有 5,015 条事件、约 994 KB；证据库 139 个 `events.ndjson` 共 19,629 条，约 96.8% 是 `item_finished`，单行中位数约 197 字节。
- `GET /api/tasks/{task_id}/events/history` 只返回 `tail` 指定的最后 N 行（默认 200，最大 500），`total` 实际是返回条数而不是文件总行数；5,015 条任务在界面上只能看到最后 200 条，且“显示 200 / 200 行”会误导读者。
- 接口每次请求都用 `read_text()` 读取并拆分整个文件，前端每 3 秒轮询一次；文件增长后，网络和解析成本会随文件大小线性增加。界面没有“加载更早”、没有稳定序号、没有虚拟列表。
- 现有“运行事件”是拼接字段的多列摘要，“原始日志”是整行 JSON；两者同源但不能同时阅读。原始日志使用 `whitespace-pre-wrap break-all`，一条事件可能折成很多视觉行；筛选后的行号是数组索引，不是稳定序号。运行事件的时间目前只显示到分钟，不满足日志排障需要的秒级精度。

结论：现有实现适合短日志查看，不构成完整的大日志方案；需要先确认展示形态，再补游标、增量传输和虚拟渲染。

## 决策

### 展示形态

- 只保留一个“运行日志”视图，取代“运行事件”和“原始日志”两个标签；“原始 JSON”作为行的详情或切换视图，不再维护第二套查询。
- 一条事件固定一行，使用等宽字体、固定行高、默认不换行；长 URL 和长字段截断，完整内容进入详情弹窗。用户显式开启“换行”时才允许折行。
- **时间必须精确到秒**。行内固定显示本地 `HH:mm:ss`；`YYYY-MM-DD` 通过工具栏“显示日期”复选框控制，默认关闭，勾选后行内显示 `YYYY-MM-DD HH:mm:ss`，选择写入浏览器本地偏好。完整日期和原始 ISO 时间始终放在 `title`、详情和复制内容中；不再用分钟或“刚刚”等相对时间承担日志判读。
- 主列固定为序号、时间、级别、事件类型、对象／URL、结果／失败分类。级别由 `event + state + failure_class` 派生，必须同时用文字或图标表达，不能只靠颜色。
- 行详情使用页内弹窗，显示完整 JSON、复制原始行、复制 URL、打开来源页；不把详情展开进列表，避免行高变化和滚动跳动。

### 跟随与阅读

- 运行中默认开启“跟随最新”；只有在用户位于列表底部时才自动滚动。
- 用户向上滚动、拖选文本或打开详情时暂停跟随，显示“有 N 条新事件 · 回到最新”，不抢滚动位置。
- 加载更早日志时保持当前阅读位置；任务结束后停止增量并保留全部已加载行。
- SSE 断线显示“轮询回退”，保留旧行并继续用带游标的轮询补齐；不整块重载，不闪空。

### 数据与接口

- 保留 `/api/tasks/{task_id}/events/history`，增加 `before` 游标和 `limit`，返回稳定 `seq`、准确 `total`、`has_more`、`oldest_seq`、`newest_seq`。
- 首屏取最近 500 条；历史按 500 条一页向前加载；前端内存窗口上限 20,000 条，超出时按滚动方向丢弃另一端，不无限增长。
- `GET /api/tasks/{task_id}/events` 增加 `after` 参数和 `id: <seq>`，支持 `Last-Event-ID` 重连；没有 `after` 时保持现有的从文件末尾开始行为，避免影响任务详情页的既有调用。
- 服务端不重新读取整个文件取尾部；用反向分块读取完成 tail，用流式换行计数缓存准确总数，按文件大小和 mtime 失效。`before` 分页按行号或字节游标读取。
- 前端增量按 100–200 ms 批量合并，追加而不是重建；按 `seq` 去重；SSE 失败回退到 `after_seq` 轮询，过期或文件被截断时重置游标。

### 渲染与依赖

- 采用固定行高的虚拟列表，只渲染可视区及少量 overscan；不引入 xterm.js 或终端模拟器。
- 优先使用 `@tanstack/react-virtual`（MIT，和现有 TanStack Query 技术栈一致）；如果原型验证显示收益不足，则退回 `content-visibility: auto`，但目标仍是虚拟化，不是把所有行都留成 DOM。
- “换行”模式会改变行高；首版限制在已加载的较小窗口或关闭虚拟化时使用，避免动态测量把复杂度带进主路径。
- 不引入新的后端服务、数据库表或日志存储；日志继续以 `events.ndjson` 为唯一真源。

## 备选方案

- **xterm.js 或纯终端模拟器**：适合超大 ANSI 输出，但结构化筛选、复制、URL 打开、详情查看和可访问性都更弱，包体和集成成本更高；拒绝作为主视图。
- **一次加载全部事件**：5,000 条尚可，50,000 条会同时拖慢网络、解析、内存和渲染；拒绝。
- **保留两个标签各自轮询**：继续重复查询、重复状态和两套阅读方式，且原始 JSON 仍会折行；拒绝。
- **继续只取最后 200 条**：实现简单，但历史不可见、总数不真实，故障排查会缺失上下文；拒绝作为最终方案。
- **引入专用日志服务或数据库表**：当前任务规模和数据生命周期不需要第二套存储；先把文件游标和虚拟列表做好，超过约定规模再评估。

## 后果

- `/api/tasks/{task_id}/events/history` 的响应增加字段，OpenAPI 快照和前端类型需要同步；旧客户端忽略新字段仍可用。
- 前端新增虚拟列表依赖和日志查看器组件，需要补充单元测试、浏览器走查和大日志夹具。
- 准确总数依赖行数缓存；文件被重写或截断时必须失效并让前端重置游标。
- 客户端只搜索已加载窗口；全量搜索、归档和跨任务检索不在本 ADR 范围，界面必须明确标注搜索范围。
- 事件级别目前从字段派生，不写入 `events.ndjson`；如果以后需要稳定级别，需单独迁移事件格式。

## 回退

前端回退到现有“运行事件／原始日志”两个标签即可；后端新增字段和 `before`／`after` 参数是增量的，旧调用保持兼容。无需迁移任务数据或账本；删除新组件不会影响事件文件、导出和任务状态。

## 验证

- API：`test_workbench` 覆盖 tail、`before` 分页、准确 total、`seq` 稳定性、SSE `after` 与 `Last-Event-ID`、空日志和追加后的总数刷新；api 组 97 项通过，ruff 通过。真实 5,015 条任务实测 tail 500 约 18ms、`before` 500 约 12ms。
- 前端：新增 `useTaskEventLog`、`taskLog` 测试和页面回归，覆盖单行渲染、秒级时间、日期复选框、跟随／暂停、SSE 增量去重、加载更早和终态；前端 169 项测试、lint、typecheck、format、build 通过。
- 浏览器：8765 真实 5,015 条任务首屏 500 条、total 5,015；加载更早后已加载 1,000 条，滚动位置保持；DOM 只保留约 27 行。真实运行任务验证实时追加、暂停跟随后“2 条新事件 · 回到最新”、点击后回到底部；390 视口无页面级横向溢出；浏览器控制台无应用错误；日志面板 axe 0 violations／0 incomplete。
- 尚未验证：20,000 条合成 fixture、换行模式的大窗口性能、完整页面与读屏、长时间 SSE 重连。不得把这些写成已验证。

## 未决问题

- 首版搜索只覆盖已加载窗口；全量搜索和跨任务检索后续再评估服务端 `q`。
- 换行模式仍使用虚拟列表动态测量，20,000 条时的滚动性能待补测。
- 事件级别目前由前端按 `event + state + failure_class` 派生；是否在写入时持久化另议。
- `@tanstack/react-virtual` 已引入并登记依赖；如果后续移除虚拟化，需重新验证大窗口 DOM 和滚动。
