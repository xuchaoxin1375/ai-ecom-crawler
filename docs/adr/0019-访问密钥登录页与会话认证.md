## 状态与适用范围

**Proposed**（2026-11-25）。本 ADR 修订 [ADR 0017](0017-局域网访问与访问令牌.md) 的浏览器认证交互和 [ADR 0018](0018-系统设置页与运行时局域网控制.md) 的令牌管理部分：浏览器不再使用 HTTP Basic 弹窗，改为固定用户名 `ecom` + 访问密钥的登录页和会话 Cookie；Basic 保留给命令行脚本。实现并通过 `V-01`～`V-05` 后转 Accepted。

> 实现状态（2026-11-25）：已实现并通过 `V-01`～`V-05` 自验，待用户验收后转 Accepted；证据见[设计文档](../43-访问密钥登录与会话认证设计.md#当前实现与证据2026-11-25)和仓库外 `workbench/access-key-login-2026-11-25/`。

局域网信任边界、Host 校验、单用户和 HTTP 明文限制不变；TLS、多用户、公网暴露和逐设备会话撤销仍不在本轮范围。

## 背景

ADR 0017 的 HTTP Basic 方案在技术上可用，但首次使用不成立：

- 浏览器 Basic 框强制填写用户名，服务端只校验密码；页面没有说明用户名该填什么。
- 访问令牌只能由服务端生成，最短 16 位，用户无法设置自己记得住的简单密钥。
- 没有登录页、会话和退出登录；浏览器原生弹窗无法承载错误、限流和深链接跳转。

用户明确要求“允许我自己设置简单密钥，懒人方便”，并选择固定用户名 `ecom` 加访问密钥的登录页，让浏览器密码管理器能够保存和填充。本 ADR 记录该方向的取舍，详细机制、时序图和状态图见[访问密钥登录与会话认证设计](../43-访问密钥登录与会话认证设计.md)。

## 决策

- **登录页**：新增 `/#/login` 前端路由，显示只读用户名 `ecom` 和访问密钥输入框；用户名不参与服务端校验，只用于浏览器密码管理器保存和填充。登录成功回到 `next` 指定的原页面。
- **密钥**：支持用户自定义或服务端随机生成；长度 1–256 字符，去掉首尾空白，拒绝空、纯空白和控制字符；不强制大小写、数字或符号。
- **存储**：继续使用 `app_settings.serve_token` 的随机 salt + SHA-256，不保存明文；自定义密钥不回显，随机密钥只显示一次。
- **会话**：登录成功设置 `ecom_session` Cookie，`HttpOnly`、`SameSite=Lax`、`Path=/`、30 天；服务端用当前密钥哈希做 HMAC-SHA256 签名，不新增会话表。
- **轮换失效**：会话负载绑定当前密钥哈希前缀；轮换密钥后旧会话立即失效，所有设备需要重新登录。
- **退出登录**：清除当前浏览器 Cookie；无状态会话不能逐设备撤销，需要让所有设备退出时轮换密钥。
- **失败限流**：同一 IP 60 秒内 5 次失败后锁 30 秒，返回 `429` 和 `Retry-After`；登录和 Basic 错误共用计数，成功清除。
- **公开边界**：根路径和 `/assets/` 静态资源对 `GET`／`HEAD` 公开，API 仍需会话或 Basic；登录页依赖静态外壳加载，API 数据不公开。
- **401 行为**：401 JSON 不再带 `WWW-Authenticate`，避免浏览器弹出 Basic 框；SPA 收到 401 跳转登录页并保留 hash 深链接。
- **Basic 兼容**：保留 `Authorization: Basic` 供 curl／脚本使用，用户名仍被忽略；浏览器主路径不再使用 Basic。
- **只读模式**：登录和退出不受只读写保护影响；密钥轮换、局域网开关和其他写接口仍返回 403。
- **Token 接口**：`POST /api/system/access/token` 请求体可选 `{token?: string}`；无体或 `null` 随机生成，带值则保存自定义密钥。
- **本地重置**：新增 `reset-access-key` CLI 命令，需本地账本文件访问，停止服务后写入新 salt + hash；不提供远程“忘记密码”端点。

## 后果

- 浏览器首次使用只需要输入访问密钥；固定用户名 `ecom` 让密码管理器可以保存和填充，但用户名本身不是第二凭据。
- 简单密钥的在线猜测风险由限流降低，但 HTTP 明文嗅探风险仍在；可信局域网边界不变。
- 无状态会话不新增表、不迁移数据库，重启后仍有效；代价是无法逐设备撤销，退出只清当前浏览器。
- 密钥轮换会让所有会话失效，需要用户重新登录；随机密钥对话框和设置页必须清楚说明。
- 忘记密钥时可停止服务后用本地命令重置，不需要知道旧密钥；重置后必须重启服务。
- 根路径静态外壳公开，知道地址的人可以加载登录页，但看不到任务、路径或系统数据。
- 新前端和旧后端不能混跑：旧后端没有登录接口，新前端登录会 404；发布时构建并重启同一服务实例。
- 回滚不涉及数据迁移；旧 Basic 认证可用，会话 Cookie 被旧代码忽略。

## 替代方案

- **只放密码字段的登录页**：少一个字段，但部分浏览器不提示保存或不填充；不采用固定用户名 `ecom` 之外的简化。
- **Bearer Token + localStorage**：实现简单，但 XSS 可直接读取；HttpOnly Cookie 更稳。
- **查询参数传密钥**：便于 SSE／下载，但会进入日志、Referer 和历史记录；不采用。
- **服务端会话表**：可逐设备撤销和审计，但当前单用户阶段需要新表、清理和并发设计；保留为升级路径。
- **只允许 16 位以上随机令牌**：安全默认更强，但与“简单密钥”要求冲突；用限流和可信局域网补偿。
- **不做限流**：短密钥可被在线暴力尝试；不采用。
- **服务端 302 到登录页**：会丢失 URL fragment 深链接；改用 SPA 内 401 跳转。
- **删除 Basic**：浏览器体验更单一，但破坏现有脚本；保留兼容路径。
