## 状态与适用范围

**Provisional（方向已选定，阶段 1 已实现并验收）**。这不是“等以后再说”：批次工作台按本文的 Vue 3 + TypeScript + Vite 推进，只有出现本文列明的阻断条件才回退，回退需要新增或修订 ADR。2026-11-23 项目方确认批次阶段 1 进入 v1 用户界面；`validation: partial` 表示阶段 1、任务控制台和真实批次 E2E 已通过，跨浏览器／读屏和更大规模真实批次仍未覆盖。

**2026-11-23 v2 方向**：项目方接受 React 作为新版本前端，设计基线见[前端设计系统与 v2 视觉方向](../35-前端设计系统与视觉方向.md)，技术决策见 [ADR 0012](0012-前端v2技术栈与设计系统.md)（Provisional，v2 已设为默认入口）。旧 Vue 应用降级为直访兜底并标注弃用；站点详情、构建、任务页、任务 SSE 和站点任务历史均已迁入 v2，本文由 ADR 0012 取代的过程进入退役演练阶段。

本文只决定批次工作台的前端技术栈和迁移边界，不改变任务状态、计数、API 和界面行为。v1 任务控制台仍按 [ADR 0008](0008-前端技术栈与本地Web形态.md) 的原生方案，不在本文范围内重写。

### 术语说明

- Vue 3：用于构建交互页面的前端框架，页面由可复用组件组成。
- TypeScript：带类型检查的 JavaScript，能在构建时发现字段和参数错误。
- Vite：前端构建工具，把源码打包成 FastAPI 可以托管的静态文件。
- Vue Router：页面路由；hash 模式用 `#/...` 切换页面，不需要服务端为每个页面加路由。
- Pinia：Vue 的共享状态管理库，保存跨页面状态。
- Vitest／Playwright：分别用于组件测试和浏览器端到端测试。
- OpenAPI：FastAPI 自动生成的接口描述，可据此生成 TypeScript 类型。
- Provisional（暂准）：方向已选定、验证未完成，允许在限定范围实现；不是“以后再说”。

## 背景与约束

- v1 任务控制台已经用原生 ES modules 实现，页面数量和状态有限；重写 v1 会打断当前交付，收益不足。
- 下一阶段目标是批次工作台：批次列表、导入站点与匹配预览、批次详情、站点详情、技术详情、全部任务，可能还有构建会话。页面、状态、表格、筛选、弹窗和批量操作明显多于 v1。
- 用户工作流和对象模型见[用户工作流与前端信息架构](../33-用户工作流与前端信息架构.md)；2026-11-23 项目方确认批次阶段 1 进入 v1，范围见[ v1 界面范围](../25-v1界面范围.md) 的 2026-11-23 节。实现前仍需同步 `26` 的 API／账本和 `29` 的设计基线。
- 构建环境已有 Node（OpenCode 和前端工具链共用），终端用户不需要 Node；前端构建产物由 FastAPI 静态托管。
- 代码主要由 AI 生成，需要标准模式、类型约束、可测试结构和可回滚的依赖治理。

## 决策

- **框架与语言**：Vue 3 + TypeScript，使用 `<script setup lang="ts">` 和 Composition API。
- **构建工具**：Vite；锁文件入库，构建产物不手改。
- **路由**：Vue Router，使用 hash 模式，避免为每个页面增加 FastAPI 路由。
- **状态**：Pinia 管理跨页面共享状态；页面局部状态留在组件内，不把全部状态塞进全局 store。
- **API 类型**：用 `openapi-typescript` 从 FastAPI 的 OpenAPI 生成 TypeScript 类型，不手写第二份接口契约；请求仍走现有 REST／SSE。
- **测试**：Vitest + Vue Test Utils 覆盖组件和状态逻辑；Playwright／patchright 覆盖关键用户路径；API 契约仍以 `app/tests/test_web.py` 为准。
- **样式与组件**：沿用项目现有 CSS 令牌和浅色主题；先自建轻量表格、表单、弹窗和状态组件，不引入大型 UI 组件库，避免第二套视觉语言和额外依赖。若自建成本被实际页面证明过高，再按 ADR 修订引入 headless 组件库，不在实现中临时混用。样式层的当前方案、备选和重新评估条件已单列为 [ADR 0011](0011-样式层与CSS框架.md)。
- **代码位置**：Vue 源码放 `app/frontend/`；构建产物由 FastAPI 在 `/batch` 下托管。v1 原生页面继续在 `/`。
- **迁移边界**：批次工作台达到功能对等前，v1 原生页面保留；批次工作台稳定后替换主页，再退役原生页面。两套前端共用同一 API／SSE 契约，不各自维护任务状态。

## 为什么选 Vue 3 + TypeScript + Vite

这是基于已知信息的当前最优选择，不是“等验证原型做完再决定”：

| 维度 | 判断 |
| --- | --- |
| 发展空间 | 批次工作台页面和状态明显增长，组件化框架比继续手写 DOM 更能支撑后续页面 |
| 扩展性 | Vue 组件、路由、Pinia 状态和 TypeScript 类型提供标准扩展点；表格、筛选、弹窗、导入预览可复用 |
| 可维护性 | 单文件组件把模板、逻辑和样式放在一起；TypeScript 约束字段和状态；Vitest／Playwright 有成熟测试方式 |
| 开发效率 | Vue 模板和响应式状态减少重复 DOM 代码；Vite 启动和构建快；AI 有大量可核验的 Vue 3 模式 |
| 交付与运行 | 构建产物仍是静态文件，由 FastAPI 托管；Node 只在开发／构建期使用，不增加终端用户运行时依赖 |
| 团队与 AI | Vue 3 是主流栈，资料和示例密度高；TypeScript 让 AI 生成和人工复核都更容易发现字段错误 |

不选 React 作为默认，是因为本项目是表格、表单、筛选、弹窗为主的后台控制台，Vue 的模板和组合式 API 样板更少；React 生态更大，作为备选保留。不选 Preact 作为默认，是因为它的生态和现成方案更小，当前项目更需要稳定的后台组件模式。不选原生作为批次工作台的默认，是因为页面和状态增长后，手写 DOM 与状态收敛会成为主要维护成本。

## 备选与不选理由

| 备选 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Vue 3 + TypeScript + Vite | 后台控制台模板简洁、组件化、类型和测试生态完整 | 增加构建链、依赖升级和前端工程维护 | **采用** |
| React + TypeScript + Vite | 生态最大、AI 资料最多、组件和状态方案成熟 | 样板和状态选择更多，后台表格／表单代码通常更多 | 备选；Vue 遇到阻断时回退 |
| Preact + TypeScript + Vite | 运行时小、React 风格 | 生态较小，复杂后台组件要更多自建 | 不作为默认 |
| 模块化原生 ESM | 无构建链，短期成本低 | 页面和状态增长后组件复用、类型和测试成本上升 | 只保留 v1；批次工作台不默认使用 |
| 服务端模板（Jinja2 等） | 无前端构建链，首屏简单 | 批量交互、局部更新和状态收敛不自然 | 不采用 |

## 2026-11-23 最小端到端路径结果

- `app/frontend/` 已建立 Vue 3 + TypeScript + Vite 应用，`npm run build` 通过，`npm test` 的组件用例通过。
- 构建产物由 FastAPI 在 `/batch/` 托管；`/api/health`、`/api/tasks` 使用真实本地服务，未使用 mock 数据。
- hash 路由从批次占位页进入批次详情占位，Playwright 1280×900 冒烟通过，无控制台错误。

- 2026-11-23 阶段 1 与任务控制台已落地：`/batches`、`/batches/new`、`/batches/{id}`、`/batches/{id}/sites/{site_key}` 与 `/tasks`、`/tasks/{id}` 共用同一外壳；真实批次 `b-586052683409`（2 站点、14 有效商品、0 失败）和分段截图验收通过。任务控制台并入的决策、旧 `/legacy` 兜底和回退条件见 [ADR 0010](0010-任务控制台并入批次工作台外壳.md)。
- 真实批次 E2E 已通过；跨浏览器、读屏和更大规模批次仍未测，因此继续保持 `validation: partial`，不因阶段 1 验收自动写成 `Accepted`。

## 风险与回退

- **构建链和依赖治理**：Vite、Vue、Pinia、测试工具都需要锁版本和 CI；用锁文件、依赖审计和固定 Node 版本控制。
- **两套前端并存**：迁移期 v1 原生和批次 Vue 同时存在；用 `/` 与 `/batch` 分开，API 契约共用，功能对等后退役原生，避免长期双轨。
- **TypeScript 学习成本**：先对新代码启用严格类型；不为旧原生页面补类型，不把类型问题带进运行期。
- **组件库缺口**：自建基础组件会增加初期工作量；如果实际页面证明成本过高，按 ADR 修订引入 headless 组件库，不在页面里零散引入多套 UI 库。
- **回退条件**：如果最小端到端路径无法在现有 FastAPI 托管方式下稳定构建、路由或测试，或 Vue 生态出现阻断性许可／维护问题，回退到 React + TypeScript + Vite；如果批次工作台最终缩小为两三个简单页面，回退到模块化原生。回退必须新增或修订 ADR，不在实现中临时换栈。

## 实施边界

- 本文的决定在批次工作台编码前生效；不允许先按原生写页面、遇到问题再换框架。
- 实现前先做一条最小端到端路径：构建产物由 FastAPI 在 `/batch` 托管，Vue Router 能切换页面，API／SSE 能连通，Vitest 和一条 Playwright 关键路径能运行。
- 这条路径用于验证已选栈的集成风险，不是重新选型；验证通过后更新 `validation: partial`，批次工作台达到交付条件后再评估是否转 `Accepted`。
- 批次阶段 1 已确认进入 v1；实现前仍须按 `25`／`26`／`29` 落范围、API／账本和设计基线，不能只做技术脚手架。
