## 状态与适用范围

**Accepted**（2026-11-27，验证 partial）。本 ADR 决定在 `GET /api/system` 增加 `resources` 快照，用 `psutil` 采样服务所在主机的 CPU、内存和服务进程 RSS；完整仪表放在系统设置页「资源与运行」，全局页眉只显示 CPU／内存简化胶囊；任务工作台不内嵌资源面板。

本 ADR 修订 [ADR 0018](0018-系统设置页与运行时局域网控制.md) 中“CPU／内存暂不采集”的边界。任务状态机、worker 调度、计数口径、磁盘/数据库统计和现有设置页写操作不变。真实 8765 已加载工作台与资源采样构建，验收仍待项目方确认。

## 背景

工作台在任务较少时有大片空白，项目方先提出显示系统资源状态，随后明确要求把详细内容放到系统资源区，只在页眉保留简化元素。`GET /api/system` 已有 worker、队列、数据库、磁盘和运行时长，但没有 CPU 与内存；ADR 0018 当时以“无新依赖、先交付应用级资源”为由暂缓。

本轮需要回答的是“服务所在主机现在是否吃紧”，而不是做通用主机监控。CPU 和内存必须来自服务端进程所在主机，不能使用浏览器 `navigator` 或 `performance.memory` 代替。

## 决策

### 采样库与范围

- 使用 `psutil>=7,<8`，Windows／Linux／macOS 通用，许可证 BSD-3-Clause；不引入后台监控进程、时序数据库或新的服务。
- 采样对象是服务所在主机和当前 Python 服务进程；浏览器子进程的完整内存不细分。
- CPU 使用率按两次 `cpu_times()` 的总量／空闲量增量计算，表示“自上次采样以来”的平均值；`cpu_window_ms` 记录实际窗口。第一次没有基线或窗口短于 50ms 时返回 `null`，前端显示“采样中”，不把 0 当成真实值。
- 内存使用率取 `(total - available) / total`，与仪表盘一致；`process_rss_bytes` 只表示服务进程 RSS。
- 采样按请求触发，服务启动时先取一次基线；不启动后台线程。`psutil` 缺失或调用异常时 `available=false`，其余字段为 `null`，不阻断 `/api/system` 的其他字段。

### 接口

`GET /api/system` 增加：

```json
{
  "resources": {
    "available": true,
    "cpu_percent": 12.3,
    "cpu_count": 8,
    "cpu_window_ms": 15000,
    "memory_used_bytes": 8589934592,
    "memory_total_bytes": 17179869184,
    "memory_percent": 50.0,
    "process_rss_bytes": 104857600,
    "sampled_at": "2026-11-27T04:10:11Z"
  }
}
```

页面每 15 秒刷新。没有新增写接口，采样不需要额外认证或权限；认证仍沿用 `/api/system` 现有边界。

### 展示

- 系统设置页「资源与运行」顶部显示 CPU、内存、磁盘三个环形仪表，并在仪表下方保留 Worker、活动任务、构建、数据库、磁盘和运行时长统计；CPU／内存达到 70% 用警告色、90% 以上用危险色，颜色之外给出文字或 `aria-valuetext`。
- 全局页眉在服务状态旁显示 `CPU x% · 内存 y%` 胶囊，磁盘只放在 `title`／`aria-label`；点击进入 `/settings?focus=resources` 并滚动到资源区。胶囊在 `md` 以下隐藏，读取中、不可用或字段为空时隐藏。
- 任务工作台不再内嵌资源面板，避免占用最近任务和运行事件窗格。

## 备选方案

- **平台专属实现，不引入 psutil**：Windows、Linux、macOS 各写一套内存/CPU 读取，维护和测试成本高于一个成熟依赖；拒绝。
- **后台线程高频采样**：能让 CPU 更接近瞬时值，但要管理线程生命周期、锁和关闭；首版按请求采样已足够，拒绝。
- **独立 `/resources` 页面**：资源监控还不是独立工作流；先把完整仪表放在系统设置资源区并用页眉胶囊直达，减少新导航和新页面维护；未来资源监控成为独立工作流时再拆分。
- **浏览器端 CPU/内存**：显示的是浏览器所在设备，不是服务主机；拒绝。

## 后果

- 新依赖 `psutil`，`uv sync --frozen` 需要更新锁文件；旧环境升级时需重新同步依赖。
- CPU 是区间平均值，不是瞬时峰值；第一次请求可能没有值。页面必须支持“采样中”和“不可用”，不能显示假 0。
- 服务进程 RSS 不包含 Chromium 子进程；排障需要结合系统内存和进程列表。
- `/api/system` 的响应多一个只读 `resources` 对象；未使用该字段的客户端保持兼容。

## 回退

移除 `psutil` 依赖、`SystemMetricsSampler`、`/api/system` 的 `resources` 字段和前端仪表/胶囊即可回退到 ADR 0018 的应用级资源视图。旧客户端不依赖 `resources`，回退不需要迁移账本或任务数据；删除字段会让新前端隐藏胶囊和仪表，但不影响其他系统状态。

## 验证

- 后端：`test_system_metrics` 覆盖 CPU 增量、首次短窗口、连续采样、缺失 psutil、内存异常回退；`test_web` 覆盖 `/api/system` 字段与范围；api 组 89 项和 ruff 通过。
- 前端：`SystemSettingsPage.test.tsx` 覆盖三个仪表；全量 187 项 Vitest、lint、typecheck、format、build 通过。
- 浏览器：1280 设置页资源区、1280／768 页眉胶囊、390 窄屏无页面级横向溢出；点击胶囊滚动到资源区。证据在仓库外本机临时预览目录 `p1-workbench-ui/`。
- 未覆盖：真实 8765 重启加载、全量后端回归、真实低内存/高 CPU 场景和浏览器子进程明细。
