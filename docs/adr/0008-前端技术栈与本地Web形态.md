## 状态与适用范围

**Accepted（方向）**，验证状态为 **partial**。本 ADR 确认 v1 本地 Web UI 的前端技术方向和边界，不把已落地的 D08 技术预览写成完整验收。任务状态、计数和控制语义仍以[任务状态与计数契约](../09-任务状态与计数契约.md)为准，界面行为以[界面与任务管理](../06-界面与任务管理.md)和[v1 界面范围](../25-v1界面范围.md)为准，服务/API 设计见[D08 任务服务与界面设计](../26-D08任务服务与界面设计.md)。

本 ADR 的 `status: accepted` 只表示方向已确认；`validation: partial` 表示方向已有实现证据，但 A16 实机确认尚未完成。决策状态与验证状态分开记录，避免把“已实现”当成“已验收”。批次工作台已由 [ADR 0009](0009-批次工作台前端技术栈.md) 单独选定 Vue 3 + TypeScript + Vite；本文只保留 v1 原生方案。

## 背景与约束

- v1 是单机、单用户的本地 Web UI，默认只绑定回环地址；目标是任务控制台，不是面向多用户的远程产品。
- 页面规模有限：任务列表、创建、详情、控制、归档／导出；批次工作台是下一阶段目标，未进入 v1。
- 代码主要由 AI 生成，需要接口简单、可观察、可回滚；不希望在 v1 引入额外的 Node 构建链和前端依赖治理。
- 前端只通过本地 HTTP API／SSE 访问任务、商品、方案和事件，不直接读 SQLite、不启动采集进程；CLI 与 Web 共用同一服务层。
- 开发期主规格为桌面 1280、浅色主题；768 窄屏和深色主题在交付前适配阶段处理。

## 决策方法

技术选型在写生产代码前完成，不把选择留到实现中。前端、后端及每个进入生产路径的层都要有结论；如果信息不足，也要按已知信息给出推荐，并记录成功机会、开发效率、可维护性、可扩展性、风险和复审条件，不能以“先做起来再说”代替决定。

候选至少包含当前方案和 1–2 个可行替代。无法判断哪个更好时，默认选当前团队和 AI 更熟悉、回退成本更低、能支撑下一阶段的方案，同时写明未选方案和重选条件。允许两条路线并行验证，但必须先写清共享契约、各自预算、比较指标、停止条件、最终决策日期和负责人；到期必须选一条或明确继续条件，不把两套方案都带进生产。

本文的“验证原型”指先限定时间、范围和通过标准的小规模试做，用于比较方案，不是正式产品代码。

## 决策

- **适用范围**：本决策只覆盖 v1 任务控制台；批次工作台、构建会话 UI 和后续产品形态不自动继承，批次工作台按 [ADR 0009](0009-批次工作台前端技术栈.md) 执行。
- **前端形态**：原生 ES modules + CSS，不使用 React、Vue、Svelte 等 SPA（单页应用，页面切换不整页刷新）框架，不引入打包器。
- **托管方式**：FastAPI 直接托管 `/api/*` 和 `/static/*`，页面与 API 同源；`GET /` 返回 `index.html`。
- **路由**：使用 hash 路由（`#/tasks`、`#/tasks/new`、`#/tasks/{id}`），不为每个页面增加服务端路由。
- **代码位置**：`app/src/ecom_crawler/web/static/` 下的 `index.html`、`app.js`、`style.css`；不新增 `package.json` 或前端构建产物目录。
- **数据访问**：浏览器用 `fetch` 调用本地 API，用 `EventSource` 订阅任务事件；断线重连先拉快照，再订阅增量。
- **模块边界**：按页面/职责拆分 ES module，共享请求、格式化、状态收敛等小工具；不引入全局状态框架。
- **浏览器范围**：目标为现代常青浏览器（桌面 Chrome／Edge／Firefox／Safari 的当前稳定版）；不承诺旧版浏览器。当前只实测 Chromium／无头 Chromium，Firefox／Safari 未验证。
- **测试**：API 行为由 `app/tests/test_web.py` 覆盖；页面用 1280 截图和后续 Playwright／patchright 冒烟验证，不把截图当作完整 UI 验收。

## 备选与不选理由

| 备选 | 优点 | 代价 | 当前结论 |
| --- | --- | --- | --- |
| React／Vue／Preact + Vite | 组件生态、状态管理和构建工具成熟；复杂页面更易复用，Preact 运行时更轻 | 增加 Node 构建链、依赖升级、构建产物、CI 和前端工程维护；对当前任务控制台收益不足 | v1 暂不采用；批次工作台已由 ADR 0009 选定 Vue 3 + TypeScript + Vite |
| 服务端模板（Jinja2 等） | 无前端构建链，首屏简单 | 交互和局部更新要整页刷新或额外脚本，任务状态收敛不自然 | 不采用 |
| htmx／Alpine 等轻量库 | 比原生 DOM 少写一些胶水代码 | 仍引入额外依赖和心智模型；当前页面规模不足以抵消 | 暂不采用 |
| 桌面壳（Tauri／Electron） | 托盘、通知、系统集成 | 打包、签名、自动更新成本高；v1 本地 Web 已够用 | 后置，见 ADR 0004 |

不选 SPA 框架的核心理由不是“框架不好”，而是当前产品边界下，引入构建链和组件体系的成本高于收益。单机单用户、页面数量有限、API 与页面同源，原生 ES modules 足以支撑，并且让 AI 生成的代码更容易被人工检查和回滚。

## 成长性评估

本 ADR 不能用“当前任务控制台页面少、单机单用户”直接证明原生方案适合长期。按可预见范围评估：

| 维度 | 当前 v1 | 批次工作台及后续 | 对原生方案的含义 |
| --- | --- | --- | --- |
| 页面与状态增长 | 列表、创建、详情、控制、归档／导出 | 批次列表、导入匹配、批次详情、站点详情、技术详情、构建会话；状态和错误分支明显增加 | 原生可以支撑，但手写 DOM 与状态收敛会成为主要成本 |
| 扩展性 | 少量页面和共享工具 | 表格、筛选、状态徽标、弹窗、导入预览、批次级操作等组件复用增加 | 需要自建组件、路由和状态约定；没有现成组件生态 |
| 可维护性 | `app.js` 约 868 行、CSS 约 573 行 | 多页面和多交互后，单一 `app.js` 会继续膨胀 | 必须按页面／领域拆分模块、统一请求和渲染；否则容易出现重复代码和旧值残留 |
| 开发效率 | 无构建链，修改后直接刷新 | 组件复用和状态管理能减少重复劳动 | 短期更快；中长期若没有架构约束，新增页面的成本会上升 |
| 测试与协作 | API 测试、截图和少量浏览器冒烟 | 更多用户路径、批量操作、错误状态和并行 agent 修改 | 需要自建浏览器测试和模块边界；多人或多 agent 协作成本上升 |
| 交付与运行 | FastAPI 静态托管，终端用户不需要 Node | 构建产物仍可由 FastAPI 托管 | “不引入 Node”是开发期成本优势，不是终端用户运行时优势；构建环境本身已有 Node |
| AI 协作 | 小文件、直接 DOM，局部修改容易 | 大文件和隐式状态更容易生成不一致代码 | 原生需要更强的模块边界和测试；框架提供标准模式，但也会增加生成样板 |

结论：原生方案适合当前 v1 任务控制台，但**不足以仅凭“单机单用户”证明适合批次工作台和长期产品**。不把“无构建链”当成长期优势；它主要是当前交付成本优势。

## 与批次工作台的关系

- 本 ADR 的 Accepted 只覆盖 v1 任务控制台；批次工作台已由 [ADR 0009](0009-批次工作台前端技术栈.md) 单独选定 Vue 3 + TypeScript + Vite，不继承本文的原生方案。
- 批次工作台实施前按 ADR 0009 的最小端到端路径验证构建、路由、API／SSE、测试和 FastAPI 托管；这是验证已选栈，不是重新选型。
- 如果出现 ADR 0009 列明的阻断条件，按该 ADR 回退并在新 ADR 中记录；不在实现中临时换栈。
- 如果项目确认长期只做本地单用户任务控制台，且不进入批次工作台，可继续原生；这个前提变化时重新评估。

## 后果与风险

- 需要手写 DOM 更新和页面状态收敛，容易出现重复代码、旧值残留和事件监听泄漏；用模块拆分、统一请求封装和页面级清理降低风险。
- 没有现成组件库，表格、表单、弹窗和状态提示需要自己维护；样式以 CSS 令牌和现有页面为基线，不另起视觉体系。
- 前端测试主要依赖 API 测试、截图和少量浏览器冒烟；交互状态覆盖不足时，不能只用“页面能点”证明验收通过。
- 如果 v1 任务控制台自身出现大量共享组件、复杂局部状态或多角色视图，原生方案可能变成维护负担；届时按本 ADR 的退出条件回到选型，不静默加框架。
- 前端可以独立替换：只要保持 API／SSE 契约，换框架不需要改任务层和账本。

## v1 原生方案的退出条件

出现以下情况时重新评估 v1 任务控制台的原生方案，并新增或修订 ADR：

- v1 页面和交互组件数量明显超过当前任务控制台，原生 DOM 同步成为主要缺陷来源。
- 需要跨页面共享的复杂状态、撤销／重做、虚拟列表或大量实时更新，原生模块难以保持一致性。
- 需要成熟组件库、设计系统或多前端开发者协作，构建链和组件复用的收益超过维护成本。
- 需要服务端渲染、SEO、桌面壳或远程多用户访问，当前同源静态托管形态不再匹配。
- 现有前端测试无法覆盖关键用户路径，且引入构建工具能显著改善可验证性。

批次工作台不在本 ADR 的退出条件内，按 [ADR 0009](0009-批次工作台前端技术栈.md) 执行。重选时优先保留 API／SSE 契约和任务层，不在旧页面上叠加第二套状态真源。

- D08 任务控制台已按本方案实现：`index.html`、`app.js`、`style.css`，`<script type="module">` 加载，FastAPI 同源托管；`app/tests/test_web.py` 覆盖主要 API 行为。

- 窄屏完整矩阵、深色主题和跨浏览器矩阵仍按交付前适配阶段处理。
