## 状态与适用范围

> 浏览器认证交互、自定义密钥和会话 Cookie 已由 [ADR 0019](0019-访问密钥登录页与会话认证.md) 修订；本 ADR 的系统设置页、局域网开关和运行时控制仍然有效。
>
> 2026-11-27 修订：CPU／内存采样已由 [ADR 0026](0026-系统资源采样与页眉胶囊.md) 加入；本 ADR 中“CPU／内存采集不做”的表述保留为当时的决策边界。

绑定地址、端口、允许的 Host 和多用户权限仍不在页面内修改；CPU／内存采集已由 ADR 0026 修订；TLS、公网暴露、独立账号和按操作审计仍需新的安全设计。

## 背景

- ADR 0017 已让 `serve` 支持局域网访问，但开关和令牌只能通过启动参数或环境变量决定；用户需要在页面查看当前访问状态并做日常调整。
- `uvicorn` 启动后监听地址和端口固定，页面无法安全地把只监听 `127.0.0.1` 的进程改成局域网可访问；在请求中重启/重绑会中断连接、SSE 和运行中的任务。
- 用户还需要一个集中入口查看 worker、任务/构建队列、数据库、磁盘、路径和版本，而不是在多个页面和日志之间拼接。
- 直接绑定 `0.0.0.0` 但没有令牌会让同网段任何人获得写权限；同网段伪造 `Host: 127.0.0.1` 也不能成为绕过认证的理由。

## 决策

- **页面与路由**：新增 `/settings`“系统设置”，侧栏“规则与设置”分组增加入口；页面只读展示系统配置，编辑范围限定为局域网开关和访问令牌。
- **启动建立能力**：只有 `serve --host` 为非回环地址时，页面才能开关局域网。以回环地址启动时，页面显示“当前仅监听回环地址”，提供可复制的 `--host 0.0.0.0 --port <port>` 重启参数，不伪造一键开启。
- **持久化**：局域网开关写入 `app_settings.serve_lan_enabled`；令牌以随机 salt + SHA-256 哈希写入 `app_settings.serve_token`，不保存明文。启动时优先使用 `--access-token`／`ECOM_SERVE_TOKEN` 并刷新哈希；没有明文令牌时读取已存哈希。
- **令牌轮换**：`POST /api/system/access/token` 生成新令牌并返回一次；旧令牌立即失效，所有设备需要重新认证。轮换在回环模式下也可用，用于准备下一次以 `0.0.0.0` 重启。
- **局域网开关**：`PUT /api/system/access` 立即更新内存策略并持久化。关闭后，非回环 Host 一律拒绝；由于监听地址仍是 `0.0.0.0`，令牌认证继续对所有请求生效，避免伪造回环 Host 绕过。
- **启动令牌缺失**：`--host` 为非回环地址且没有 `--access-token`／`ECOM_SERVE_TOKEN` 时，允许读取账本中已有的令牌哈希；没有哈希仍拒绝启动。首次开放仍需要一次显式令牌。
- **系统状态**：`GET /api/system` 返回绑定与能力、局域网/认证状态、访问地址、允许的 Host、worker 槽位、任务/构建计数、数据库大小、磁盘使用、线程数、运行时长、路径和版本。路径中用户主目录折叠为 `~`。
- **不做的内容**：不在页面内重绑地址或端口，不修改允许的 Host 列表，不采集系统 CPU／内存（2026-11-27 由 ADR 0026 修订），不展示或回显令牌明文，不提供多用户、HTTPS 或公网暴露。
- **写保护**：两个写接口沿用同源 `Origin`、`X-Requested-With` 和只读 403；`--read-only` 下只能查看系统状态。

## 实施

- `app/src/ecom_crawler/web/access.py`：Host 判定、令牌哈希/校验、持久化解析和已存令牌检测。
- `app/src/ecom_crawler/web/app.py`：可变访问策略、系统状态接口、局域网开关、令牌轮换和系统资源汇总。
- `app/src/ecom_crawler/cli.py`：非回环绑定允许使用已存令牌；传入绑定地址、端口和访问地址。
- `app/frontend/src/features/settings/SystemSettingsPage.tsx`：系统设置页、开关、轮换确认、一次性令牌对话框、资源和路径展示。
- `app/frontend/src/app/router.tsx`、`AppShell.tsx`：`/settings` 路由、侧栏入口和页面标题。
- 文档：本 ADR、[系统设置页设计](../42-系统设置页设计.md)、`26` 安全边界和 `app/README.md`。

## 后果

- 用户不必为每次开关局域网重启；切换和令牌轮换立即生效并跨重启保留。
- 首次从纯回环环境开放局域网仍需重启一次；这是监听地址不可变的安全边界，不是页面缺陷。
- 令牌只存哈希，页面无法找回旧令牌；丢失时可用启动参数/环境变量覆盖，或在仍可认证的本机轮换。
- 关闭局域网后，加载中的局域网页面会在下次请求断开；页面会暂停自动刷新并提示回到本机。
- 允许的 Host 和绑定地址仍由启动时检测决定；网络切换、mDNS 或新 IP 需要重启或 `--allow-host`。
- 系统页不采集 CPU／内存（2026-11-27 由 ADR 0026 修订为采集），资源状态只覆盖应用级队列、数据库和磁盘；需要主机级监控时另做。
- 页面能查看的路径已折叠用户主目录，但仍暴露运行目录结构；仅对已认证用户可见。

## 验证与证据

- 后端：`app/tests/test_web.py` 覆盖系统状态字段、局域网开关持久化与 LAN 阻断、令牌轮换使旧令牌失效、回环能力限制、只读 403 和非回环无令牌拒绝；`app/tests/test_cli.py` 覆盖已存令牌检测和非回环绑定。
- 前端：`SystemSettingsPage.test.tsx` 覆盖状态展示、关闭局域网确认、令牌轮换与一次性展示、回环重启说明和只读禁用；全量 Vitest、lint、typecheck、format 和 build 通过。
- 浏览器：真实 Chromium 经 `127.0.0.1:8876` 和 Basic 凭据打开 `/next/#/settings`，关闭/开启局域网、轮换令牌、390 窄屏无横向溢出；重启时**不传令牌**，CLI 从账本读取哈希，旧令牌 401、新令牌 200，局域网开关保持开启。
- 证据在仓库外 `workbench/system-settings-2026-11-25/`（1440/390 截图、令牌对话框、重启日志和 `ui-smoke.json`）。
- 未覆盖：真实另一台物理设备、Windows 防火墙、mDNS、HTTPS／反向代理、多用户和页面内重绑。CPU／内存已由 ADR 0026 覆盖。

## 替代方案

- **只读系统页**：改动最小，但用户仍需改启动参数并重启；不满足本轮“允许修改局域网设置”。
- **只在本次运行内生效**：实现简单，但设置页会出现“改了但重启丢失”的预期落差；不采用。
- **页面触发的进程重启/重绑**：能覆盖纯回环启动，但会中断请求、SSE、构建和任务，且失败恢复复杂；本轮明确不做。
- **令牌明文入库**：实现简单，但扩大静态凭据暴露；采用盐 + 哈希，只显示一次新令牌。
- **关闭局域网时跳过认证**：本地体验更轻，但绑定 `0.0.0.0` 时同网段可伪造 `Host: 127.0.0.1` 绕过；不采用。
- **本轮加入 psutil 和 CPU／内存**：用户明确暂缓；保持无新依赖，先交付应用级资源。（2026-11-27 已由 ADR 0026 改为加入 psutil 和 CPU／内存。）
