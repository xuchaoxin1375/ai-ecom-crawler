## 状态与适用范围

**Accepted**（2026-11-28）。本架构决策记录(Architecture Decision Record, ADR)决定在工作台为批次加入保留可恢复的加入意图，并提供待接入目标清单和构建入口。设计细节见[待接入目标与批量加入恢复设计](../58-待接入目标与批量加入恢复设计.md)。

实现状态：加入意图、清单接口、生效规则优先解析、结果步骤、逐站构建入口和忽略已落地；真实 8765 已加载，待项目方验收。临时实例验证使用 8899，已停止。

本 ADR 不改变批次、任务定义、规则版本、构建验证、激活门禁、任务运行和导出语义；也不恢复已退役的批次列表、批次详情或站点详情页面。

## 背景

工作台的“新建批次”和“添加已有批次”由两次请求组成：先创建批次并匹配站点，再把可加入站点建成任务定义。加入失败或部分成功时，批次已经存在，但界面不保留批次 ID 和目标目录；刷新后没有恢复入口。规则未匹配的站点留在批次中成为待接入，工作台也没有清单或构建入口。

同时，构建成功会把批次站点标为 `ready`，但不会回填批次站点的 `rule_id/rule_version`；现有加入逻辑只读取这两个字段，导致激活规则后仍可能无法加入。

## 决策

- **新增加入意图表**：`workbench_batch_imports` 按批次保存目标目录、首次请求时间、最近尝试、最近错误和忽略时间。只有存在未忽略加入意图的批次才进入待接入清单，历史批次不会被动出现。
- **待接入清单派生**：实时比较批次站点、任务定义、生效规则和最近构建，不复制站点状态，不新增批次站点状态字段。
- **加入以生效规则为准**：工作台加入复用站点生效规则解析；批次站点保存的规则只作兼容回退。市场、目标入口和规则可用性仍在加入时校验。
- **站点身份不用 `site_key` 直接比较**：`site_key` 是批次内部键，无范围批次是域名，带范围批次是 `domain--hash`。待接入和重复判断使用 `(domain, target entry, market)` 规范身份；规则解析按原键、规范范围键和域名键依次尝试，避免同一站点被误判为待接入或重复创建定义。
- **构建入口放在待接入清单**：待接入站点可直接启动现有站点构建；首版逐站确认，使用默认预算和模型，不自动激活、不自动加入、不自动启动运行。
- **结果保留**：新建批次和添加已有批次在结果步骤显示已加入、待接入、重复、无效和失败计数与原因；加入失败保留批次 ID 和目标目录，可重试。
- **幂等重试**：同一批次同一站点最多一个任务定义；重试只补缺失。部分加入、刷新、重复点击和并发请求都不产生重复定义。
- **忽略不等于删除**：忽略只隐藏待接入提醒，不取消构建、不删除批次、站点、定义或运行；再次添加同一批次时恢复。
- **目标目录缺失不静默回退**：保留待接入并要求重新选择目标目录，避免把定义放到错误位置。
- **创建事务**：工作台创建批次时，批次和加入意图在同一事务内写入；站点匹配和写入沿用现有批次导入并返回逐项报告。批次或加入意图写失败则整个创建回滚。

## 备选与取舍

| 方案 | 结果 | 未采用原因 |
| --- | --- | --- |
| 扫描所有批次和未加入站点 | 实现最小 | 会把历史批次和从未打算加入工作台的批次重新翻出，产生长期噪音 |
| 给 `batches` 增加工作台字段 | 少一张表 | 把工作台加入语义耦合进批次对象；批次仍可能被其他入口使用 |
| 只在前端保留失败状态 | 不改后端 | 刷新、换浏览器或另一个 agent 后丢失，无法满足找回和重试 |
| 加入时继续读批次站点规则字段 | 改动最小 | 构建成功后字段为空，激活后仍无法加入；规则指针和批次快照容易分叉 |
| 构建成功后自动加入、自动启动运行 | 摩擦最少 | 激活和采集预算应由用户确认；自动启动会消耗真实预算 |
| 新增独立待接入页面 | 空间充足 | 与任务树添加动作割裂；首版用工作台内弹窗更轻 |
| 待接入清单 + 加入意图表 | 可找回、可忽略、历史批次不噪音 | 需要新表、接口、结果步骤和测试；采用 |

## 后果

- 新增一张小表和三个接口入口；不迁移历史数据。旧批次在用户显式添加前不出现在清单。
- 加入逻辑从“只看批次站点规则字段”改为“以生效规则为准”，这是有意的行为变化；已激活规则、构建后站点和跨入口加入的结果更一致。
- 工作台增加待接入数量、清单弹窗和批量结果步骤；390 布局、键盘和读屏需要新增验收。
- 忽略只隐藏提醒，用户仍可能在构建记录中看到继续运行的构建；界面文案必须说明。
- 逐站接入在待接入很多时摩擦较高；批量接入留待后续按构建并发和预算另设计。
- 回滚只需停用新表、接口和入口；批次、站点、定义、构建和运行不受影响。

## 实施与验证

> 实现状态（2026-11-28）：P1～P3 已落地。后端全量 528 项（含 `test_workbench` 34 项）通过，前端 222 项、类型、lint、格式和构建通过；临时 8899 实例走查待接入弹窗，真实 8765 已重启，待项目方验收。

实施顺序：

- P1：加入意图表、创建事务、加入解析切换到生效规则、幂等重试和接口测试。
- P2：待接入清单接口、构建入口、忽略；后端覆盖市场、停用、目标缺失和并发。
- P3：新批次结果步骤、待接入弹窗、窄屏与可访问性；真实 8765 走查。

验证至少覆盖：

- 混合批次的部分成功、刷新找回、重试无重复。
- 未匹配站点构建、激活后加入原目录，再启动运行。
- 规则停用、市场不匹配、目标入口不覆盖时保留待接入并说明原因。
- 目标目录删除、忽略与恢复、只读和构建不可用。
- 390 宽度、键盘、读屏和 axe；不把临时端口或 mock 通过当作常驻入口验收。
