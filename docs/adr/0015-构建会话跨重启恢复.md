## 状态与适用范围

**Accepted**（2026-11-24）。本 ADR 扩展 [ADR 0006](0006-构建Harness选型与集成方式.md) 的崩溃恢复行和 [ADR 0014](0014-构建队列与单并发调度.md) 的重启语义：构建会话在服务重启或正常停止后保留，活跃构建进入可继续的中断态，而不是一律标记失败。

不改变单 worker、单出口、单用户和一次一个运行构建的边界；不实现自动续跑、多 worker、跨机器会话迁移或 OpenCode 数据目录之外的会话存储。

## 背景

OpenCode 会话和消息保存在本机 OpenCode 数据目录，`opencode serve` 重启后仍可按 `session_id` 重新加载。此前 `reconcile` 只把这些会话当作内存对象，重启后把所有活跃构建标成失败，导致：

- 已经完成的 Agent 工作无法继续，只能重新构建并重复模型费用。
- 用户无法判断是“Agent 真的失败”还是“主机重启把会话弄丢了”。
- 手动 continue 只在同一个服务进程内可用，正常重启后失效。

同时，主机验证和规则安装已经由 `out/plan/rule.yaml`、`out/result.json` 和工作区证据驱动，适合在重启后无模型复验。

## 决策

- **中断不等于失败**：`FINISHED` 新增 `outcome=interrupted`。它表示会话被服务重启或停止中断，但会话和工作区仍存在，可从构建详情显式继续。它不占用全局构建槽位，`QUEUED` 继续按 FIFO 调度。
- **不自动续跑**：恢复过程不主动发送模型指令。运行中的构建标为 `interrupted`，由用户决定是否继续；避免重启循环反复产生模型费用，也避免把未知在途工具当成成功。
- **按需重载会话**：用户点继续时，`OpenCodeHttpAdapter.adopt_build()` 用 `session_id` 调用 `GET /api/session/{id}` 验证会话仍在，检查 `location.directory` 与构建工作区一致，拒绝上一轮遗留的权限请求，然后注册本地 `BuildSession` 并发送用户指令。会话缺失、工作区缺失或 OpenCode 不可用时返回 `BUILD_SESSION_UNAVAILABLE`，不伪造会话。
- **已完成 Agent 自动复验**：如果工作区 `out/result.json` 为 `FINISHED/succeeded`，或构建停在 `VALIDATING`，`reconcile` 直接用工作区重建本地会话并启动原有 watcher，重新跑主机验证和安装。这个过程不调用模型，也不自动开启修复轮次；验证失败后由用户决定是否继续。
- **正常停止同样保留**：`shutdown` 对活跃构建调用 `BuildService.detach()`：中断远程 turn、拒绝陈旧权限、停止 server，但不删除 OpenCode 会话；随后写 `FINISHED/interrupted` 和 `error_class=service_stop`。只有显式取消才删除会话。
- **状态恢复范围**：`CANCELLING` 完成取消；没有 `session_id` 或工作区缺失的构建仍标失败，并明确提示重新构建；已终止的 `CANCELLED` 不恢复。
- **前端语义**：构建列表和详情把 `interrupted` 显示为“已中断”，使用 warning 而非 success/danger；详情提供“继续构建会话”，对中断构建给出默认的续跑说明，并明确发送会产生模型费用。

## 实施

- `app/src/ecom_crawler/harness/adapter.py`：`adopt_build()`、`detach()`、`shutdown()`、会话目录一致性检查和陈旧权限清理。
- `app/src/ecom_crawler/harness/service.py`：`adopt()` 恢复事件日志和权限集合；`detach()` 在不删除会话的情况下释放本地会话。
- `app/src/ecom_crawler/builds.py`：`reconcile()` 中断／自动复验分支、`_restore_local_session()`、`_ensure_build_session()`、`_workspace_events()`、`_recovered_finalize` 和 continue 的会话恢复。
- `app/src/ecom_crawler/web/app.py`：continue 接受 `outcome=interrupted`。
- 前端：`buildTone()`、构建详情“继续构建会话”、站点“最近构建已中断”、中断后的 SSE 重连。
- 验证：`app/tests/test_builds.py` 覆盖正常停止后重载会话继续、Agent 已完成工作区自动复验、会话型活跃构建标中断；真实 OpenCode 适配器探测覆盖 stop server 后按 session id 接管；真实模型构建在工具执行中杀进程，重启后显示已中断并从页面继续，模型识别到上次抓取被中断并继续检查。

## 后果

- 服务重启不再丢失已创建的会话，已完成但未验证的 Agent 工作可以无模型复验。
- 中断构建不阻塞队列；但用户在继续前不会自动推进，可能停留较久。
- 恢复依赖同一台机器的 OpenCode 数据目录、同一工作区和兼容的 OpenCode 版本；数据目录清理、会话删除或工作区丢失后不可恢复。
- 陈旧权限请求会被拒绝；如果原 turn 已经产生副作用，恢复时仍以工作区实际文件和主机验证为准，不把未知在途工具当成功。
- 不自动续跑意味着“服务重启后构建自动完成”仍不是承诺；需要该能力时另行设计尝试次数、费用上限和幂等边界。

## 验证与证据

- `app/tests/test_builds.py`：`test_shutdown_marks_build_interrupted_and_continue_reloads_session`、`test_reconcile_finalizes_finished_agent_workspace_without_prompt`、`test_reconcile_marks_session_backed_build_interrupted`、`test_reconcile_interrupts_stale_build`；`app/tests/test_harness.py` 覆盖会话接管、陈旧权限拒绝和 detach 不删除会话。后端 276 个测试通过。
- 真实 OpenCode 2.4.1：`opencode serve` 停止后重新启动，同一 `session_id` 可在不同 server cwd 下 `get_session`；生产适配器 `adopt_build()` 返回 `FINISHED/interrupted` 并记录 `build_recovered` 事件。
- 真实模型：`build-fc66334cd8a2` 在工具执行中杀进程，重启后 `reconcile` 标为 `interrupted`、`recoverable=true`，站点保留原规则；从构建详情继续后模型重新加载同一会话，识别到上次抓取被中断并继续分析，最终主机验证 PASSED、候选 `2026.11.24-4` 安装但未自动激活。

## 替代方案

- **重启后自动续跑**：体验更顺滑，但重启循环会持续产生模型费用，且无法可靠判断在途工具是否完成；本轮不采用。
- **只恢复宿主收尾**：只对 Agent 已完成的工作区复验，其他构建仍失败；实现最小，但无法继续中途构建。
- **把中断构建保留为 `RUNNING`**：会让队列和站点一直显示运行中，实际没有进程推进；不采用。
- **把 OpenCode 会话导出到构建账本**：可以跨机器恢复，但会把对话正文和凭据风险带入 SQLite，且需要处理导入兼容性；留到独立证据归档或迁移能力。
