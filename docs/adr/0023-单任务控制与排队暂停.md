## 状态与适用范围

**Provisional**（2026-11-27）。本 ADR 决定单任务控制和排队任务暂停的接口与界面语义，适用于 `app/` 的采集任务状态机、批次控制接口和 React v2 工作台。实现已通过本地状态机、批次接口、前端组件和完整后端回归；真实账本页面走查完成后转 Accepted。设计与验收见[单任务控制与排队暂停设计](../47-单任务控制与排队暂停设计.md)。

本 ADR 不改变取消、归档、恢复、导出、交付保护和构建会话控制，也不新增任务状态或数据库迁移。

## 背景

批次工作台已经有单任务控制：批次站点行和任务列表行的「⋯」菜单可以暂停、继续和取消，任务详情和站点详情有页头主按钮。但这些入口不显眼，批次页头只有整批操作，用户从批次页面看会以为只能成批控制。

同时，`TaskStore.request_pause()` 只允许 `RUNNING`，批次暂停会把 `QUEUED` 任务作为跳过项，worker 仍会继续领取这些任务。结果是“暂停批次”不能真正挡住后续排队工作，只能取消排队任务。批次继续也没有服务端接口，批次列表由前端逐任务调用，失败时无法在一次响应中汇总。

## 决策

### 排队任务直接暂停

`QUEUED` 暂停直接进入 `PAUSED`，不经过 `PAUSING`：

- 排队任务没有在途工作，不需要结清阶段。
- `PAUSED` 已经表达“不再派发新工作、可从原进度恢复”，复用现有状态和计数，不引入 `QUEUED_PAUSED`。
- 恢复仍是 `PAUSED` → `QUEUED`，沿用任务原有 `created_at` 排队顺序。
- `DRAFT` 不允许暂停；草稿任务用启动或取消处理。

状态转移在 SQLite `BEGIN IMMEDIATE` 事务内按当前状态判断。暂停先提交时 worker 领取不到；worker 先领取时任务已是 `RUNNING`，暂停走 `PAUSING`。两种顺序都不会产生“已暂停但仍被领取”的状态。

### 批次控制覆盖排队任务

- `POST /api/batches/{batch_id}/pause` 受理 `QUEUED` 和 `RUNNING`；`PAUSING`／`PAUSED` 重复请求幂等；`DRAFT` 跳过并说明可取消；终态跳过。
- 新增 `POST /api/batches/{batch_id}/resume`，只恢复 `PAUSED`；`PAUSING` 等待自行结清，其他状态跳过并说明。响应沿用 `accepted`／`skipped`／`batch`，不新增请求字段。
- 批次继续不再由前端逐任务调用，避免只完成一部分且缺少统一汇总。

### 行内主控制与批次任务控制区

- 批次站点清单和任务列表的操作列改为「主控制按钮 + ⋯」，按状态显示启动、暂停或继续；取消、导出和归档仍在菜单。
- 批次详情在摘要与站点清单之间增加任务控制区，列出运行中、暂停中、已暂停、排队中和取消中的任务，逐任务操作，并提供整批暂停／继续。
- 批次详情页头在只有已暂停任务时把「继续」作为主操作；批次列表的继续改用批次接口。
- 批次页头的整批启动、暂停、取消和导出优先级保持现有行为。

## 契约变化

- `docs/09` 的操作表和状态转移表增加 `QUEUED` 暂停到 `PAUSED`；`PAUSING` 仍只由 `RUNNING` 进入。
- `POST /api/tasks/{task_id}/pause` 的行为变化，路径和响应结构不变。
- 新增 `POST /api/batches/{batch_id}/resume`，OpenAPI 快照和前端 API 同步。
- 数据库 schema、任务状态枚举、批次派生状态和导出结构不变。

## 备选方案

- **新增 `QUEUED_PAUSED` 状态**：表达最直接，但任务计数、筛选、状态徽标、系统设置和旧客户端都要认识新值；收益只是区分暂停前是否运行过，`PAUSED` 已足够表达控制语义。
- **用暂停标志位阻止 worker 领取**：需要新增列和迁移，且状态仍显示为 `QUEUED`，用户无法从状态判断是否已暂停；与现有状态机重复。
- **只改界面，排队任务保持不可暂停**：改动小，但“暂停批次”仍挡不住排队任务，用户必须逐个取消，正是本轮要解决的问题。
- **批次继续继续由前端循环调用**：不需要新接口，但请求数随任务数增长，部分失败没有统一响应，批次列表和详情会各自实现一套逻辑。

## 后果与验证

- 暂停批次现在会真正停下排队工作；恢复后按原排队顺序重新进入队列。代价是暂停状态不再区分“运行过”和“未运行过”。
- 旧版本读取 `PAUSED` 任务不受影响；回退应用版本不需要账本迁移。
- 验收覆盖排队暂停、暂停后 worker 不领取、运行中暂停仍经过 `PAUSING`、批次暂停包含排队、批次继续只恢复已暂停、行内按钮和任务控制区的浏览器走查。
- 派生批次状态「已暂停」、强制中止在途和优先级队列不在本 ADR 范围。
