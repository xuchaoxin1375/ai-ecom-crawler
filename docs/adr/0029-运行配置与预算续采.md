## 状态与适用范围

**Accepted**（2026-11-27，验证 partial）。本 ADR 决定在采集工作台提供按运行调整采集限额的入口，并允许 `FINISHED / BUDGET_EXHAUSTED` 且仍有剩余工作的运行原地续采。它修订 [ADR 0003](0003-任务运行时与并行模型.md) 中“终止后只能新建任务”的部分表述，但只针对预算耗尽和发现截断；`CANCELLED` 仍然是不可续采的终态。

本 ADR 只覆盖任务级采集预算和参数。模型 token 预算、金额预算、规则修复和站点速率策略的存储结构不在范围内。设计细节见[运行配置与预算续采设计](../53-运行配置与预算续采设计.md)。

## 背景

正式采集的 `BUDGET_EXHAUSTED` 来自任务入队时快照的限额：商品数、时长、URL 数和规则发现上限。额度在入队后冻结，系统设置和任务定义编辑只影响新运行。用户看到“预算耗尽”时既不知道具体是哪一个上限，也无法在不新建运行、不丢失已采结果的情况下继续。

账本中的两条正式记录说明了不同原因：`web-04d8694573fe` 是 sitemap 子项上限截断发现，已处理完全部 2,333 件；`web-b3817b78a895` 是 60 分钟时长到顶，仍有 4,364 件待采。后者的入队并发是 1，而站点速率策略存的是 4 并发；工作台启动路径没有应用站点策略，放大了时长压力。服务重启还会重置进程内的时长计时。

## 决策

- 在采集工作台底部面板增加“运行配置”页签；最近任务行和任务树节点菜单把选中的运行切到该页签。
- 页签显示状态、进度、`stop_reason`、`stop_detail` 和实际限额；正式采集默认不设限，用“启用有限预算”开关渐进披露，关闭时隐藏预算字段并显示当前入队限额，开启后可修改商品数、时长和 URL 数；重试、并发、每域 RPS、请求间隔、最大导航数和最大 sitemap 数始终可见。
- 预算和发现上限可对排队、暂停和运行中的任务写入；runner 在工作项边界刷新。并发、RPS 和请求间隔需要暂停后继续才生效。
- 保存默认同步任务定义，可在页签取消。已结束运行的历史限额不改写，只同步定义。
- 新增受控状态转换：`FINISHED / BUDGET_EXHAUSTED` 且存在待采项或发现截断时，可显式续采为 `QUEUED`，沿用同一 `task_id`、已采结果和账本。
- 续采清除 `outcome`、`stop_reason`、`finished_at`、`discovery_limit` 和本次时长计数；`reset_discovery` 时把导航项重置为 `PENDING`，不改已完成商品项。
- `CANCELLED`、已归档和不存在的运行拒绝续采；正常完成且没有剩余工作的运行也不提供续采。
- 工作台启动合并 `collection_policy` 和 `site_rate_policies`；定义显式值优先，正式采集缺失值按系统正式策略，试采保留 100／20／180 默认。
- `max_products`／`max_urls` 增加处理数硬上限；`max_seconds` 改为跨重启累计，每约 15 秒写入检查点。
- `stop_detail` 进入任务摘要和工作台，界面不再只显示笼统的“预算耗尽”。

## 备选与取舍

| 方案 | 结果 | 未采用原因 |
| --- | --- | --- |
| 只提供“编辑任务定义” | 实现最小 | 不能调整当前运行，也不能延续已采结果 |
| 已结束运行只允许新建重跑 | 状态机最简单 | 重复请求已完成的商品，4,364 个待采项无法利用 |
| 原地续采沿用同一任务 | 保留结果和账本 | 需要新增受控状态转换、导航重置和预算累计；采用 |
| 复制剩余工作项到新任务 | 不改状态机 | 结果和导出分裂到两个任务，用户需要合并；未采用 |
| 在运行中热改并发和线程池 | 体验最好 | 线程池和 fetcher 已初始化，动态扩缩容风险高；首版只提示暂停后继续 |
| 续采时重置全部商品项 | 实现简单 | 会重复请求已采商品，违背保留已采结果的承诺；未采用 |

## 后果

- 任务状态契约新增预算续采例外，`docs/09` 和测试需要同步；取消仍不可续采。
- 续采会重新请求入口、分类或 sitemap（当 `reset_discovery=true`），产生新的站点请求；页签必须说明。
- 已采结果在续采期间来自上一段；结束时整体重写 CSV 和任务结果，`task-result.previous.json` 保留上一段。
- 运行中降低商品数或时长可能在下一个工作项边界立即结束任务；已发出的请求不会中断。
- 工作台启动正式任务会遵循站点速率策略，可能比旧运行更快、并发更高；站点级速率仍是保护边界。
- 时间预算跨重启累计后，反复重启不再无限续命；需要更多时间时用户显式调整或续采。
- 旧账本没有 `run_seconds` 时从 0 开始，不伪造历史用量。

## 验证

- 后端：`test_run_config.py` 覆盖配置读取、部分更新、定义同步、续采转换、导航重置、拒绝取消／完成续采、启动策略合并、预算硬上限和跨重启累计；api 组 116 项、runtime 组 108 项、全量 492 项和 ruff 通过。
- 前端：全量 192 项、lint、typecheck、format、build 通过；运行配置页签覆盖加载、校验、保存、续采、只读、错误、入口菜单和“启用有限预算”默认关闭／开启后显示字段；jsdom axe 0 violations（color-contrast 关闭）；390 视口字段两列堆叠，无页面级横向溢出。
- OpenAPI 快照重新生成并通过快照测试；文档 96 个文件、1,380 条链接通过；导出 106 个文件，导出包复核通过。
- 8765 已重启加载新后端和新前端；真实账本只读回显 `web-b3817b78a895` 的 4,364 待采和 3,600 秒上限、`web-04d8694573fe` 的 sitemap 上限和默认“重新发现”。未在正式账本点击续采，未用正式站点验证续采后的 CSV 合并；该部分由后端测试和临时账本覆盖。
