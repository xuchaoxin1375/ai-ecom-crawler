## 状态与适用范围

**Proposed**（2026-11-27）。本 ADR 决定新增“任务工作台”页面：任务树只有目录和任务定义两类节点；任务定义是长期实体，运行产生 `tasks` 执行记录；批次只是批量添加动作；最近任务来自运行列表，只有终止运行可以移除。设计、接口和验收见[任务树与最近任务工作台设计](../49-任务树与最近任务工作台设计.md)。

本 ADR 不改变现有任务运行状态机、计数口径、worker 调度、采集规则、交付快照和批次目录树，也不替代 [ADR 0024](0024-批次目录树管理.md)。若后续把任务树与批次树合并，需要先修订 ADR 0024 并补充递归汇总、导出和迁移论证。

## 背景

批次目录树首版把任务留在批次内容区，理由是批次已有站点、任务、交付和导出的稳定归属，且一次批次可能有几十个站点和多次执行。这个选择适合批次生命周期管理，但日常操作仍然需要在批次、站点、任务和构建页面之间跳转；项目方还提出了更自由的组织方式：

- 左侧要显示到具体任务，可自由命名和任意层级；
- 可以新建目录、任务批次和单个任务；
- 批次只是方便一次性添加一批同国家/语言/市场/品类站点，最终任务落在目录里；
- 目录不决定任务属性，任务自身属性可覆盖批次默认值；
- 任务可以独立存在，不强制有批次；
- 一个具体网站可以建一个长期任务定义，运行不增加树节点；
- 最近任务按最近添加/启动排序，非终止状态不允许移除。

这些要求已经超出“把批次目录树扩展到任务叶子”的范围，需要把“目录”“任务定义”“运行”“批次”分开。

## 决策

### 独立任务工作台

新增 `/workbench` 页面，作为日常任务操作入口；保留 `/batches` 批次目录树，继续服务批次导入、启动、导出和归档。任务树是独立组织层，不替换批次树。

### 目录与任务定义两类节点

任务树只有：

- **目录**：自由命名、任意层级，只组织，不携带国家/语言/市场/品类/规则属性；
- **任务定义**：长期实体，绑定站点 URL/域名、规则、任务类型、采集模式、国家、语言、市场、品类、限制和代理。

目录可包含目录和任务定义；任务定义是叶子。目录移动和任务定义移动只改组织位置，不改批次来源、规则、市场或导出。

### 任务定义与运行分离

`workbench_task_defs` 保存长期定义；启动/重试时用定义属性创建现有 `tasks` 运行，并通过 `workbench_task_runs` 映射。树节点显示当前/最近运行摘要，重复运行不增加树节点，运行历史从任务详情和最近任务查看。

- 定义属性只影响之后创建的运行；运行入队后锁定规则、市场、限制和代理。
- 任务定义可以没有 `batch_id`，即独立任务；独立运行不进入批次 ZIP，使用任务导出。
- 有 `batch_id` 只表示来源；批次批量添加时写入，之后移动目录不改变。带批次来源的定义启动时，运行写 `batch_id` 并在同一事务更新 `batch_sites.task_id`／交付指针，批次详情、ZIP 和任务详情保持一致。

### 批次只是批量添加动作

“添加已有批次”和“新建批次”都在树中选一个目标目录，把批次站点任务定义放进去：

- 批次复用现有创建/导入/规则匹配流程；
- 批次不成为长期树节点，目录也不因批次而获得语义；
- 同一批次同站点默认跳过重复定义，返回新增/跳过清单；
- 已有当前任务的站点在添加时建立运行映射；没有任务的定义显示“未启动”；
- 批次 ZIP 继续按 `batch_id` 聚合运行；独立任务走任务导出。

### 任务级属性覆盖批次默认值

任务定义的国家、语言、市场、品类、规则、模式和限制可在创建后编辑；批次只提供创建时的默认值。目录不参与属性推断，不能根据目录认定任务同类。

### 最近任务从运行派生

右侧列表查询 `tasks` 运行，按 `COALESCE(started_at, created_at) DESC, task_id DESC` 排序；跨定义、跨批次，默认 100 条，上限 200。

移除只写 `workbench_recent_dismissals(task_id, dismissed_at)`：

- 不改任务状态、不删定义、不影响树；
- 恢复就是删除隐藏记录；
- 新运行是新 `task_id`，自然回到最近列表；
- 未加入任务树的运行显示“未加入任务树”，可显式加入。

### 只有终止运行可以移除

只有 `TERMINAL_TASK_STATES`（`FINISHED`、`CANCELLED`）允许写隐藏记录。其他状态：

- 前端禁用移除按钮并说明原因；
- 菜单显示“结束后才能移除”的禁用项；
- 批量移除在所选含非终止运行时禁用；
- API 返回 409 `NON_TERMINAL_TASK`；
- 批量移除全量校验，任一非终止整体拒绝。

### 初始树不隐式种子

首版任务树为空，显示“新建目录 / 新建任务 / 添加已有批次 / 新建批次”；最近任务仍显示已有运行。用户显式添加批次或把运行加入任务树。这样可以避免把历史批次结构解释成用户未确认的目录，也避免新增站点自动挂载的隐式同步。

### 数据模型与迁移

新增：

- `workbench_nodes`：目录/任务定义节点、父子关系、排序。
- `workbench_task_defs`：任务定义属性。
- `workbench_task_runs`：定义与现有 `tasks` 运行的映射。
- `workbench_recent_dismissals`：运行级最近列表隐藏记录。

迁移为纯增量，不修改 `tasks`、`batches`、`batch_sites`、`batch_folders` 的现有列。只读服务不建表、不写隐藏记录。

## 备选方案

- **任务叶子直接复用 `tasks`**：每次运行一个树节点，树会随运行增长；无法表达长期定义的属性覆盖。选择定义/运行分离。
- **批次长期作为树节点**：批次节点会同时承担目录、规则、市场和导出语义，目录移动和批次归属冲突。选择批次仅批量添加。
- **强制所有任务有批次**：实现改动小，但无法满足独立任务和任务级属性。选择 `batch_id` 可空。
- **自动种子现有批次**：打开即有内容，但会把历史批次组织解释成用户目录，新增站点还产生隐式同步。选择空树 + 显式添加。
- **最近任务用独立快照表**：查询快但需要同步状态/计数，产生第二套口径。选择从 `tasks` 派生 + 隐藏记录。
- **移除用 localStorage**：换设备丢失，无法服务端验收。选择账本记录。

## 后果与验证

- 用户可以在一个页面完成目录组织、任务定义、启动和最近运行管理；批次仍用于批量添加和批次 ZIP。
- 现有任务状态机、计数、任务详情和批次页不变；新增定义和运行映射是并行层。
- 代价是新增任务定义实体、运行映射、独立任务导出边界，以及目录移动/定义属性/最近移除的多套校验；任务定义和批次站点可能出现属性不一致，需要以定义和入队信息为准。
- 验收覆盖：定义 CRUD、目录移动/防环/解散、独立任务、批次批量添加去重、运行创建/映射、最近排序、终止移除/恢复/批量拒绝、只读、1280/768/390、8765 账本副本。
- 未覆盖：多人权限、十万级节点、运行历史树、真实触屏拖拽、读屏全流程。

## 复审条件

出现以下情况时重新评估本决策：

- 任务定义需要物理删除、归档或跨设备审计；
- 任务定义属性需要影响批次详情/导出以外的更多链路；
- 批次需要重新成为长期树节点；
- 同一站点需要多个定义或跨批次移动；
- 树节点规模超过首版性能目标，需要懒加载/虚拟化；
- 最近任务需要用户级/团队级隐藏记录。
