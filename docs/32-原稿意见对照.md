## 用途与边界

本页把外部原稿《商品爬虫业务说明(原稿)》与当前文档基线逐条对照，记录已采纳、已改变、未采纳、待确认和不适用。原稿是技术型采集员的第一人称操作手册，不是当前产品需求；本页不复制原稿全文，也不另立业务标准。

字段、流程、状态和验收仍以 `01`～`09` 为准；角色与职责见[用户角色与职责](31-用户角色与职责.md)。原稿路径在仓库外，不在文档包内；本页只引用其标题和意见，不依赖原路径可读。原稿更新时先比对差异，再改本页。

## 状态口径

| 状态 | 含义 |
| --- | --- |
| 已采纳 | 当前正文有对应规则，语义基本一致 |
| 已改变 | 当前正文有意采用不同口径，需要记录原因和影响 |
| 部分采纳 | 当前正文覆盖部分语义，仍有未落实项或角色缺口 |
| 未采纳 | 当前基线明确不做，或原稿场景不适用 |
| 待确认 | 涉及业务取舍，尚未由项目方确认 |
| 不适用 | 原稿是旧流程或单站经验，不进入当前产品范围 |

## 已确认口径

以下四项按项目目标和数据真实性在 2026-11-22 确认；`02` 的现有标准不变。

### 描述缺失与合格商品页

- 决定：保持当前口径。`description_html` 为空时标“原站未提供”；部分描述可以进入有效商品集，但必须在预览、任务报告和 `quality_exceptions` 中可辨；不用产品名填空。
- 理由：数据真实性优先；产品名兜底会让下游误以为存在描述。展示层可以用商品名兜底，但不回写字段。
- 影响：有效商品门槛和下游对空描述的判断与旧流程不同；任务报告必须保留缺失原因。
- 关联：`02`、`11` 的“描述缺失兜底”。

### 换汇与目标市场

- 决定：目标市场报价优先；换汇只作为有标注的补充，保留原币、目标币、汇率来源和时点，不单独证明满足目标市场。
- 理由：价格和币种必须绑定目标市场；仅换汇会把市场不符伪装成合格报价。
- 影响：站点只按 IP 本地化时，需要目标市场出口或标未达标；不能把换汇结果写成目标市场原价。
- 关联：`02` 价格与币种、`11` 多市场币种。

### 整页 HTML 留存

- 决定：v1 默认不保存正式整页 HTML／JSON；开发样本和必要诊断按任务有界保留；没有原文时不承诺离线重新提取。
- 理由：最小留存、版权和存储边界优先；现有任务结果、描述 HTML、质量异常和证据摘要足以支持结果核对。离线复采是维护便利，不是 v1 业务前提。
- 影响：不能对正式任务承诺事后离线重跑；需要时按任务申请有界证据留存。若未来出现明确的离线复采或审计需求，再评估任务级可选留存，并设保留期限和访问控制。
- 关联：`01` 留存、`02` 导出与留存、`03` 离线提取。

### 目录组织

- 决定：保持每任务独立输出目录，由任务 ID、站点、市场和方案版本定位；不复制国家／分类／日期／域名目录。
- 理由：UI 和任务账本是检索入口；复制旧目录会增加路径规则和第二套元数据，且与一站一任务、方案版本化的模型不一致。
- 影响：如果下游仍按文件目录消费，需要增加导出目录映射或命名规则，而不是改运行时存储布局。
- 关联：`19` 任务隔离、ADR 0003。
