## 用途与边界

本页把外部原稿《商品爬虫业务说明(原稿)》与当前文档基线逐条对照，记录已采纳、已改变、未采纳、待确认和不适用。原稿是技术型采集员的第一人称操作手册，不是当前产品需求；本页不复制原稿全文，也不另立业务标准。

字段、流程、状态和验收仍以 `01`～`09` 为准；角色与职责见[用户角色与职责](31-用户角色与职责.md)。原稿路径在仓库外，不在文档包内；本页只引用其标题和意见，不依赖原路径可读。原稿更新时先比对差异，再改本页。

## 状态口径

| 状态 | 含义 |
| --- | --- |
| 已采纳 | 当前正文有对应规则，语义基本一致 |
| 已改变 | 当前正文有意采用不同口径，需要记录原因和影响 |
| 部分采纳 | 当前正文覆盖部分语义，仍有未落实项或角色缺口 |
| 未采纳 | 当前基线明确不做，或原稿场景不适用 |
| 待确认 | 涉及业务取舍，尚未由项目方确认 |
| 不适用 | 原稿是旧流程或单站经验，不进入当前产品范围 |

## 需要项目方确认的冲突

### 描述缺失与合格商品页

- 原稿口径：前 4 个字段必须非空；描述为空时复制产品名，否则不是合格商品页。
- 当前口径：`description_html` 保持为空并标“原站未提供”；部分描述可以进入有效商品集，但必须在预览、任务报告和 `quality_exceptions` 中可辨。
- 影响：当前做法更诚实，但“有效商品”的门槛和下游对空描述的判断会变化；用产品名兜底会让下游误以为存在描述。
- 选项：保持当前口径；恢复原稿口径；或保持当前数据字段，仅在下游展示时兜底。当前实现已采用第三种展示兜底，建议保持，但需要项目方确认。

### 换汇与目标市场

- 原稿口径：如果站点按 IP 返回不同币种，按汇率换算成目标市场币种。
- 当前口径：先取目标市场上下文；换汇只作为独立结果保留原币、目标币、汇率来源和时点，不覆盖采集原值；仅有换汇不能证明满足目标市场。
- 影响：原稿的英国市场场景，如果站点只按 IP 本地化，当前需要目标市场出口，或者把结果标为未达标；换汇可以作为补充，但不能单独作为合格报价。
- 选项：优先目标市场出口；允许换汇作为有标注的补充；两者并存并按任务声明。需要项目方确认业务可接受哪一种。

### 整页 HTML 留存

- 原稿口径：可以保存产品页 HTML 到本地，再采集本地页面内容。
- 当前口径：正式整页 HTML／JSON 默认不保存；开发样本和必要诊断按任务有界保留；没有原文时不承诺离线重新提取。
- 影响：不保存原文会限制事后审计、离线复采和早期问题复查；保存原文会增加存储、版权和留存风险。
- 选项：保持默认不保存；增加任务级可选留存并设保留期限和访问控制；始终保存。建议先评估任务级可选留存，需合规和存储确认。

### 目录组织

- 原稿口径：任务根目录按国家／分类／创建日期／域名组织。
- 当前口径：每任务独立输出目录，由任务 ID、站点、市场和方案版本定位；UI 和账本承担检索。
- 影响：如果业务用户仍按文件目录浏览、交接或归档，当前目录不直观；如果 UI 和导出文件承担检索，则不必复制旧目录。
- 选项：保持当前目录；增加导出目录映射；改成原稿目录。建议先确认下游是否真的按目录消费。
