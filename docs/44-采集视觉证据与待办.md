# 采集视觉证据与待办

## 用途与边界

产品采集不能只核对字段是否存在、CSV 是否有行。每个站点至少留一份**视觉基线**：一个代表性商品页截图、一张本地商品图、预期字段，以及试采后的对比。它用于发现整批同名、同图、占位图、错误商品、价格或币种不符、描述缺失等结构校验不容易发现的问题。

- 无论站点简单还是挑战站、模型是否支持图像输入，都执行。
- 模型能看图时先做一次预期核对；不能看图时标记待人工复核，不把“没有看图”写成通过。
- 视觉对比不替代结构化提取、计数、导出和页面层级核对，也不做全站像素回归。
- 证据默认放仓库外私有证据库，不提交截图、商品图、整页原文或运行期数据库。
- 当前按**软要求**执行：缺失视觉证据记录警告和原因，不直接判构建失败；积累 2–3 个站点后再评审是否升级为硬门禁。

## 证据结构

```text
workbench/<site>-<date>/visual/
  product-<slug>.png          # 商品页截图
  product-<slug>-image.<ext>  # 商品图原字节，或渲染后的元素截图
  baseline.json               # 预期字段、截图和图片路径
  compare.md                  # 试采结果与基线的差异
```

`baseline.json` 的最小字段：

```json
{
  "schema_version": "1.0",
  "site": "example.com",
  "captured_at": "2026-11-26T10:49:00Z",
  "product_url": "https://example.com/product/example/",
  "viewport": { "width": 1704, "height": 903 },
  "capture": {
    "screenshot": "product-example.png",
    "product_image": "product-example-image.jpg",
    "product_image_source_url": "https://example.com/image.jpg",
    "product_image_capture": "original",
    "tool": "browse.screenshot + browser download"
  },
  "expected": {
    "name": "Example Product",
    "price_amount": 1.75,
    "price_currency": "GBP",
    "primary_image_url": "https://example.com/image.jpg",
    "description_contains": ["key fragment"]
  },
  "review": {
    "vision_supported": "unknown",
    "status": "completed",
    "notes": "截图和商品图已检查；固定构建模型是否支持图像输入未验证。"
  }
}
```

- `product_image_capture` 使用 `original` 表示原始图片字节，使用 `rendered` 表示只能保存浏览器里的可见图片元素。
- `review.status` 使用 `completed`、`pending_manual` 或 `blocked`；`blocked` 必须写原因。
- 本地文件路径相对 `visual/`，不写机器绝对路径。

## 采集与对比流程

1. **选样**：在构建或试采前选一个代表性商品页，优先包含真实价格、主图、描述和购买状态；挑战站选已放行会话里能稳定打开的一页。
2. **截图**：用浏览器保存首屏，确保商品名、当前价格、币种和主图可见；有 Cookie 弹窗时先处理再截。
3. **保存商品图**：优先保存原始图片字节；静态请求被 403 或挑战挡住时，用同一浏览器会话下载，仍不行则截图主图元素并标记 `rendered`。不另起静态客户端反复重试挑战。
4. **写基线**：记录商品 URL、截图、商品图、图片来源、预期名称、价格、币种、主图 URL、描述关键片段、视口和采集方式。
5. **试采**：规则写入后运行小样本任务，至少覆盖基线条目；构建场景至少覆盖主机验证样本。
6. **对比**：逐项核对名称、价格、币种、主图、描述和 URL；把差异写入 `compare.md`，说明是原站差异、价格浮动、规则缺陷还是数据缺陷。
7. **判定**：出现整批同名或同图、占位图、review widget 图、错误商品、价格或币种不符时，按数据缺陷处理，不因主机验证 `PASSED` 而豁免。

对比至少覆盖：

| 项 | 核对点 | 典型缺陷 |
| --- | --- | --- |
| 商品身份 | 名称、URL、canonical | 整批同名、取到店铺名、取到推荐商品 |
| 价格与币种 | 当前价、促销价、币种 | 划线价当现价、币种不符、单位错误 |
| 主图 | 本地文件、来源 URL、画面内容 | 占位图、Trustindex 头像、同图不同商品 |
| 描述 | 状态、长度、关键片段 | 只有摘要、空描述、混入政策或推荐文案 |
| 系统一致性 | 多个样本之间 | 全部相同名称或图片、复制错误的模板字段 |
