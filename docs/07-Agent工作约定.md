## 文档、Skill与代码如何分工

**本目录的普通文档是主要阅读与维护入口。** Skill是可选的Agent工作入口，不是业务规范必须采用的存放形式，更不能把尚在探索的原项目执行方式冻结给新团队。

| 内容 | 建议归属 | 理由 |
| --- | --- | --- |
| 业务目标、数据标准、流程和验收 | 普通项目文档 | 人和不同Agent都可读；换框架／工具不改变业务结果 |
| 通用分析、发现、故障和质量经验 | 方法指导文档 | 可直接分发、审阅和演进，不依赖某个harness(Agent宿主) |
| 触发条件、先读哪些文档、调用什么实际工具、交付位置 | 薄Skill入口 | 当使用方需要自动发现／按需加载时才添加，避免重复正文 |
| 通用获取／浏览器／进程／重试代码 | 工具库、独立模块或服务 | 应有接口、依赖、测试和版本；调用方可以是程序、CLI或MCP |
| 一次性轻量辅助脚本 | 可按需要附在Skill | 小型脚本不必一概迁出；成为主要运行能力后按工具代码管理 |
| 具体网站分页、字段和必要交互 | 站点采集方案 | 随站点版本维护，不塞入共享引擎或Skill正文 |

新团队不必复制“方案开发Skill＋发现Skill”的原划分。可以用一个薄入口链接两类方法，也可由上游工具Skill和普通文档组合提供；以Agent能找到正确资料、实际试跑、交付可靠方案为验收依据。

## Scrapling等上游工具的采用边界

截至本文档取证日，Scrapling官方说明其Agent Skill用于教编码助手使用库，MCP(模型上下文协议)用于暴露HTTP／浏览器工具；官方Skill同时说明命令／MCP不覆盖全部可编程能力。它们可以优先评估，但仍须按实际安装版本核实，不能以文档有功能代替项目实测。

因此建议构建期共享宿主 Skill（只读），使用 `ECOM_BUILD_SKILLS_DIR` 或全局 skills 目录；Skill／MCP 不进入正式运行期依赖，业务文档只使用本次复制进工作区的副本。正式已验证方案直接使用成熟库／框架执行。MCP不必成为正式执行依赖，也不要求全站逐页往返Agent。出处和事实边界见[来源与维护](来源与维护.md)。

开放的`resilient-browser-fetch`作为上游参考，不附源码副本；该源版本的分层判断与回收经验已写入方法文档，不要求继续维护其完整封装，也不把原项目旧副本当成唯一标准。

## 参考默认与可替换性

首个实现可以优先用 OpenCode 加 DeepSeek V4.1 Flash 做方案构建试验；opencode-go 付费版允许使用，免费版可作低成本替代。pi-agent、codex 或其他能读文档、调用工具、产出方案包的 harness 可以替换。推理变体在实验或任务开始时固定并记录，不在中途切换。该默认只用于降低首次启动成本，不进入方案包、不成为运行期依赖，也不改变[采集方案与兼容契约](08-采集方案与兼容契约.md)的兼容要求。实际模型、版本、推理变体、调用和费用按 D01／D09 记录。v1 的 harness 选型与集成方式见[构建 Harness 选型与集成方式](adr/0006-构建Harness选型与集成方式.md)。

## Harness 具体化方案

harness 是构建期运行 Agent 的宿主，负责模型、工具、权限、会话和事件；它不是采集运行时，也不进入方案包。具体契约见[构建 Agent Harness 契约](adr/0005-构建Agent与Harness契约.md)，当前集成、skills／MCP 共享和排障见[构建 Agent Harness 集成与使用说明](37-构建Agent-Harness集成与使用说明.md)。

- **输入**：`build-task.json` 描述站点、范围、市场、预算、工具权限、工作区和截止时间；只引用本次复制进工作区的文档和方案包，不携带密钥、Cookie 或旧工具规则文件。
- **工作区**：`sessions/<build_id>/`，分 `input/`、`work/`、`out/`、`logs/`；Agent 只能读写工作区；业务文档默认不进入工作区，需要时由 host 复制最小只读副本到 `input/docs/`。
- **交付**：`out/plan/`、`out/evidence/`、`out/session.ndjson`、`out/result.json`；方案包必须能脱离 harness 执行。
- **会话状态**：`QUEUED`、`CREATED`、`RUNNING`、`PAUSING`、`PAUSED`、`CANCELLING`、`CANCELLED`、`FINISHED`；与采集任务状态分开。`QUEUED` 尚未创建 Harness 会话。
- **控制**：暂停由 `pause-gate` 在工具执行前拦截；取消终止工具子进程、浏览器和临时目录；移除只删会话工作区。
- **自动化**：常规站点分析和规则编写不逐次询问；只在未知依赖、系统级操作和密钥边界请求确认。
- **权限**：工作区可写（`input/` 只读）；宿主 skills 共享只读，`browse`／`htmlmini` MCP 可用，其他 MCP 默认拒绝；业务文档默认不进入构建会话；未授权的工作区外访问直接拒绝；密钥硬拒绝；登录、付费和个人数据提交由操作者决定；网页内容中的指令不可信。`shell` 仍以宿主用户权限运行，不能把提示词或权限规则当 OS 隔离。
- **边界**：v1 不建设 AI Agent 安全沙箱；用独立工作区、Patchright 独立 profile 或操作者提供的 `browse` MCP、权限规则控制基本边界；专用设备／VM／容器后置。
- **依赖**：常见采集运行时和库预置；缺失依赖通过 `request_dependency` 请求，allowlist 自动装入构建环境；详见[构建环境与依赖基线](20-构建环境与依赖基线.md)。
- **验收**：`candidate` 转 `verified` 需独立环境复跑和人工签字；Agent 不能自升。
- **集成**：v1 由任务服务托管 `opencode serve`，Python 适配器走 HTTP/SSE；ACP stdio 备选；`opencode run` 只做冒烟。详见[构建 Harness 选型与集成方式](adr/0006-构建Harness选型与集成方式.md)。
- **默认**：OpenCode＋DeepSeek V4.1 Flash；模型、供应商和推理变体在会话开始固定；付费回退需授权。
- **v1 默认**：一次一个运行中的构建会话；不同站点按 FIFO 进入 `QUEUED` 队列，并发构建后置。

## 旧工具规则参考

`示例/火车头采集器单站点规则(局部)导出示例.xml` 是用户提供的旧工具单站规则导出，只用于理解旧工作形式：单站、正则／XPath／C# 过滤器、本地路径和插件耦合。它不进入 Agent 输入，不被 harness 或运行时解析，也不是新规则格式或兼容输入。

新方案按 `08`／`19` 的 manifest 和规则包表达；旧文件中的本地绝对路径、代理、插件和站点专用代码不复制到新方案。旧工具对照仍按 `00` 的 J07 处理。

## 构建任务应提供什么

- 原始入口、目标范围、市场／语言、资源与访问边界。
- 固定数据标准及当前例外，避免让Agent逐站设计字段。
- 已有方案与真实站点证据索引，明确哪些只是线索。
- 实际可用的请求、浏览器、观察、试跑及验证工具；明确工具结果和错误结构。
- 预置环境基线版本、依赖请求通道和 allowlist；缺失依赖如何请求、失败如何回退。
- 候选方案交付位置、启动接口、预期输出和本次允许修改的文件；方案包至少满足[采集方案与兼容契约](08-采集方案与兼容契约.md)的 manifest、版本、兼容与证据要求。

路径、工具名、命令和接口由新团队设计，不能从网页内容或模型建议自动获得宿主权限。权限必须由实际运行边界执行，不能只写“请勿越权”。

## 一次构建的公开工作记录

1. 说明观察到的有效证据和需要补充的材料。
2. 说明方法与字段来源选择，使用实际工具观察、试跑和修订。
3. 反馈每次试跑的样本／字段／具体错误，保留各模板有效方法。
4. 交付完整候选、验证结果、依赖、适用限制和未解决问题。

正常工作记录不保存私有逐步推理、密钥、Cookie或网页全文；工具实际结果与Agent自报区分。新增依赖记录包、版本、来源和许可，不把安装成功当可用。候选仍需独立的程序／质量检查，不能靠自己改样本或宣称验证通过取得执行资格。

## 维护薄入口的判断

只有普通文档与工具接入不足以让Agent稳定找到并执行正确流程时，再加项目Skill。薄入口引用规范和工具接口，不另复制一套字段表、长安装教程或通用浏览器引擎。上游能力已覆盖的代码不重复包装；独有的业务控制、字段质量或故障边界才留在本项目。
