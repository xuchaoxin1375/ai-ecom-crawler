## 用途与边界

本页细化[业务需求与范围](01-业务需求与范围.md)中的角色表，回答“谁对什么负责、谁批准、如何交接、v1 单用户如何兼任”。它不新增产品功能，也不改变 `01`～`09` 的业务规则、[v1 界面范围](25-v1界面范围.md)和[任务状态与计数契约](09-任务状态与计数契约.md)。

出现冲突时，业务规则以 `01`～`09` 为准，界面范围以 `25` 为准；本页只负责角色、职责、交接和权限边界。原稿意见的逐条对照见[原稿意见对照](32-原稿意见对照.md)。

## 角色清单

`01` 的“业务用户”在本页按职责拆成项目方、业务验收人和采集运营；只查看和验收结果时使用业务验收人角色。

### 人类角色

| 角色 | 目标 | 主要输入 | 关键决定／输出 |
| --- | --- | --- | --- |
| 项目方／负责人 | 决定项目目标、预算、范围和最终业务取舍 | 业务目标、成本、风险、验收结论 | 批准范围与预算；接受或拒绝业务结果；决定是否进入多用户／生产阶段 |
| 技术负责人 | 对技术方案、构建与运行边界和方案质量负责 | 站点证据、方案包、运行诊断、资源约束 | 批准技术路线；复核 `verified`；决定维护与复用策略 |
| 采集运营／数据分析 | 把业务目标变成可执行任务，拿到可用结果 | 受管规则包、市场／语言、预算、任务结果 | 选择规则包；创建、启动、暂停、取消任务；查看异常；导出；提出修复需求 |
| 业务验收人 | 判断本次范围是否满足业务需要 | 任务结果、覆盖、停止原因、质量异常、抽样 | 记录业务验收结论、范围、理由和时间；不覆盖系统事实 |
| 维护者 | 让失败和站点变化可定位、可修复、可复验 | 失败分类、事件、方案版本、样本、运行日志 | 定位问题；修方案或环境；复验；提出复用或停用建议 |
| 合规批准人／复核人 | 判断站点、数据用途、留存和分发边界 | 站点、ToS、robots、市场、数据类别、用途 | 逐站 go／no-go；批准例外；记录条件和复审触发 |
| 本机环境操作者 | 让运行时、浏览器、代理和服务可用 | 设备、依赖、浏览器、网络出口、服务配置 | 安装和升级；启动服务；处理权限和凭据；回收资源 |
| 下游数据消费者 | 使用导出的商品数据和描述 HTML | 9 列 CSV、任务结果、质量异常、字段说明 | 核对字段语义；反馈缺失或错误；判断下游渲染或分析是否可用 |

### 系统参与者

| 参与者 | 是什么 | 不能做什么 |
| --- | --- | --- |
| 方案构建 Agent | 在构建 harness 中分析站点、生成和修订方案 | 不能自升 `verified`；不能替代人工复核；不能批准合规或业务验收 |
| 运行框架 | 按已验证方案执行 discovery／product 任务，写账本和结果 | 不能把失败写成成功；不能绕过权限和访问边界；不能替用户做业务验收 |
| 任务账本 | 保存任务状态、计数、停止原因和结果索引 | 不是方案；不保存审批结论；不被页面缓存替代 |
| 构建 harness | 提供模型、工具、权限、会话和事件 | 不是采集运行时；不进入方案包；不替代任务服务 |

**角色与系统参与者分开。** 人类角色可以兼任，系统参与者没有批准权。

## 关键决定与责任

表中“负责”是做工作并承担结果，“批准”是有权同意或叫停，“参与”是提供输入或被咨询，“知会”是事后同步。v1 单用户时多个角色由同一人兼任，表中仍写角色，不写人名。

| 决定／产物 | 负责 | 批准 | 参与 | 知会 |
| --- | --- | --- | --- | --- |
| 站点准入与合规 | 合规批准人 | 项目方 | 采集运营、维护者 | 技术负责人 |
| 构建任务启动与预算 | 技术负责人 | 项目方 | 采集运营 | 合规批准人 |
| 方案复核与 `verified` | 技术负责人 | 独立复核人；无独立人员时由技术负责人记录自审 | 构建 Agent、维护者 | 采集运营 |
| 规则包发布与复用 | 技术负责人 | 项目方 | 维护者、采集运营 | 业务验收人 |
| 任务创建与启动 | 采集运营 | 技术负责人确认规则包适用性 | 业务验收人 | 维护者 |
| 运行监控与暂停／取消 | 采集运营 | 采集运营按任务授权 | 维护者 | 业务验收人 |
| 早期质量抽查 | 采集运营 | 业务验收人决定范围是否继续 | 维护者 | 技术负责人 |
| 业务验收 | 业务验收人 | 项目方；验收人即项目方时记录自审 | 采集运营、维护者 | 技术负责人 |
| 失败修复与复验 | 维护者 | 技术负责人 | 采集运营 | 业务验收人 |
| 导出与下游交付 | 采集运营 | 业务验收人 | 下游消费者 | 技术负责人 |
| 本机安装与升级 | 本机环境操作者 | 技术负责人 | 维护者 | 采集运营 |

## v1 单用户映射

| 角色 | v1 默认承担者 | 说明 |
| --- | --- | --- |
| 项目方／负责人 | 项目方本人 | 最终范围、预算和业务取舍 |
| 技术负责人 | 项目方或受委托技术代理 | 当前 D01 由用户授权代理签字；生产阶段建议明确 |
| 采集运营／数据分析 | 目标用户本人 | v1 UI 的主要使用者 |
| 业务验收人 | 项目方或采集运营 | 与操作者同一人时记录自审，不写成独立验收 |
| 维护者 | 技术负责人或技术代理 | 失败修复、复验和复用建议 |
| 合规批准人／复核人 | 项目方；必要时外部法务 | 逐站记录；不把技术可行当授权 |
| 本机环境操作者 | 技术负责人或技术代理 | 安装、启动、权限和资源回收 |
| 下游数据消费者 | 导出文件接收方 | 不是 v1 UI 角色；通过 CSV 和任务结果核对 |

v1 默认**单机、单用户、同一会话**。上表多个角色由同一人兼任时，仍要在验收、合规和 `verified` 记录中写明兼任关系和独立性限制。角色分离但需要同时使用时，当前没有登录、只读账号或远程访问；只能同一台机器、同一会话或导出文件交接。需要并发多用户、远程访问或独立只读验收时，进入多用户评估，不把回环绑定加同源校验当成多用户安全模型。

## 构建到运行交接

当前基线是**构建与运行分离**：

- 新站或站点变化由技术操作者在构建 harness／OpenCode 中发起构建任务，产出方案包、证据和诊断。
- 技术负责人按方案契约复核，必要时在独立环境复跑；通过后标记 `verified`，进入受管规则包。
- 采集运营在 v1 UI 中从受管规则包选择站点、市场／语言和预算，创建并启动任务；v1 UI 不包含构建会话 UI。
- 构建会话的暂停、取消和移除按 ADR 0005／0006 单独管理，不进入采集任务状态。
- 如果要求普通用户在 UI 内完成新站首次构建，需要把构建会话 UI 提前，并重新确认 `25` 的范围；这是范围变更，不是现有 v1 的隐含能力。

交接至少记录：入口与范围、市场／语言、方案版本、`verified` 证据、已知限制、构建者与复核者、适用任务类型。

## 质量与失败闭环

- **早期抽查**：任务开始产出首批商品后，采集运营按任务风险抽取样本，核对名称、价格与币种、主图、描述状态、分类和选项；发现系统性错误时先暂停或取消，再交维护者定位。样本量和分层方式按 `05`／`16`／`18` 的任务要求确定，不固定为某一个数量。
- **失败分流**：维护者按 `03` 的故障分流区分访问、环境、方案、站点变化和数据语义；修复后按原目标复验，保留失败样本。
- **失败记录**：任务失败和排除保留原因分类；维护者补充可执行的修复建议或下一步，供人工复查；建议不替代系统事实，也不要求系统自动生成。
- **业务验收**：业务验收人只判断“本次范围是否够用”，记录 `accepted_by`、时间、理由和范围；不覆盖 `stop_reason`、`coverage`、待处理数量或质量异常。
- **复用与停用**：规则包跨任务复用时，技术负责人确认兼容性和证据；站点长期不可用、合规变化或方案失效时，记录停用原因，不删除历史。

当前 v1 UI 已有计数、停止原因和 `quality_exceptions`，但没有单独的“首批抽样放行”门；早期抽查目前是流程要求，界面支持待补。若要把该门做成产品能力，需在 `25`／`26` 增加相应范围。

## 多用户与权限触发条件

v1 不建设登录和权限系统；回环绑定加同源校验只保护本机单用户，不是多用户安全模型。出现以下任一情况时，先评估登录、角色权限和审计，再扩大使用范围：

- 业务验收人、采集运营和维护者需要同时访问，或需要独立只读账号。
- 需要远程访问、多人共用一台执行机，或跨团队交接。
- 任务包含敏感数据、客户数据、受版权内容或对外分发。
- 需要独立审计、职责分离或合规签字。
- 多个项目共享同一服务，且需要按项目隔离规则包、任务和导出。

## 待确认

v1 默认同一人兼任、构建由 OpenCode／构建 harness 完成，这两项按当前基线执行；以下问题留待生产化或多人使用时确认：

- 业务验收是否必须与构建／执行分离？单人阶段可以记录自审，但生产或对外交付前需要项目方或法务确认。
- 维护者是否长期由项目方或技术代理承担？如果后续交给独立技术运营，按本页角色表交接。
- 下游数据消费者是否就是业务验收人？如果不是，9 列 CSV 和描述 HTML 的下游验收责任需要指定。
