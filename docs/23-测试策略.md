## 用途与边界

本页落实 R12 的测试口径：说明哪些行为必须测、在哪一层测、用什么证据判断通过，以及哪些验证不能放进默认 CI。它不新增业务规则；字段、状态、计数和验收仍以 `01`～`09` 为准，当前完成状态以[交接与继续](15-交接.md)为准。

本页是生产应用测试的起点，不替代 D01／D09 的实站验收，也不把原型测试写成生产测试已完成。

## 测试分层

| 层 | 证明什么 | 不证明什么 | 运行方式 |
|---|---|---|---|
| T1 契约与单元 | manifest／Schema、正则语义、CSV、计数、状态转移、原子写、浏览器配置／路由 | 真实站点行为、浏览器渲染正确性、并发资源回收 | 开发时按改动选跑，合并前跑完整集合 |
| T2 fixture 集成 | discovery 来源、并行、暂停／取消、恢复、重试分类、静态与 JS 渲染 fixture | 真实站点覆盖、反爬、长期漂移 | 开发时跑受影响场景，合并前跑完整集合；缺 Chromium 时真实浏览器用例会跳过，不算完整通过 |
| T3 有界实站验证 | 声明范围内的真实响应、字段来源、停止原因 | 全站覆盖、长期稳定、跨环境 | 手工，按预算和证据要求 |
| T4 生产验收 | 合约、状态、CSV、安全边界和用户旅程在最终制品上成立 | 未测站或未声明范围 | D01／D09，独立记录与签字 |

T1／T2 是开发侧证据；T3／T4 是独立验证与验收，不能用前者的通过替代后者。

## 必测清单

- **契约**：`08` 的 manifest 结构、序列化、入口和版本兼容；`09` 的状态转移、计数、取消和迟到结果；`19` 的规则包与任务字段。
- **状态不变量**：重复提交、暂停／恢复、取消、崩溃对账、重试耗尽、原子替换、迟到结果拒收；检查点必须能解释“为什么重排、为什么失败”。
- **数据与导出**：9 列业务 CSV、公式注入保护、价格与币种、缺失与部分描述、零价变体、任务结果计数。
- **安全边界**：不登录、不付费、不绕过访问控制；所有阶段 robots 只探测 `Sitemap:` 行，失败不阻塞，不解析其他规则；密钥、Cookie、浏览器 profile 不入库、不进日志；URL 与文件路径按允许范围处理。
- **提取正确性**：用真实页面样本和分层抽样核对字段来源；不以整页快照、测试名含 AC 编号或“能跑通”替代正确性判断。

### 后端测试怎么跑

**测试分层**说明结果能证明什么；**运行分组**说明这次要跑哪些用例。一个分组可以同时包含规则单测和临时 SQLite 集成测试；分组可能重叠，不是分片，不能把各组用例数直接相加。合并前使用**不带筛选的 `all`**，由 `unittest` 自动发现用例，不依赖分组名单；持续集成(Continuous Integration, CI)继续运行原有完整发现命令。

从仓库根目录运行，先准备 Python 3.11+、`uv` 及应用开发依赖。首次或锁文件变化后运行 `python -m uv sync --project app --extra dev --frozen`；后续示例中的 `--no-sync` 复用已准备好的环境。若运行 `browser` 或 `all`，还需要 Patchright Chromium；安装命令见下方。`build` 和 `all` 里的依赖桥插件测试需要 Node.js，不需要启动真实 OpenCode 或调用模型。测试仅使用临时文件、临时账本及本地模拟服务，不访问真实站点。

| 分组 | 什么时候用 | 范围 |
| --- | --- | --- |
| `quick`（默认） | 日常开发先获取反馈 | Schema、字段规范化、业务 CSV、规则差异与批次接口；不启动 Chromium |
| `api` | 改了批次、任务接口、反馈或迁移 | 真实 FastAPI 测试客户端和临时 SQLite，不启动常驻 Web 服务 |
| `build` | 改了构建、验证、激活或依赖审批 | 假构建适配器、队列、权限与依赖桥、本地集成测试 |
| `runtime` | 改了任务执行、租约、存档或恢复 | 本地 HTTP、临时 SQLite、任务状态、适配器子进程及清理 |
| `parallel` | Windows 本地，要同时验证构建与运行时 | 两个独立进程各跑一组，只覆盖 `build` 和 `runtime`；不启动 Chromium |
| `browser` | 改了浏览器抓取或列表推进 | 配置与路由测试、真实 Chromium 访问本地页面；不是工作台界面验收 |
| `all` | 合并前／需要完整后端自动化回归 | 自动发现 `app/tests` 下全部 `test_*.py` 用例；不包含实站或正式发布验收 |

```powershell
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py build -k price_regression
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py parallel -q
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py all
```

用 `--help` 查看入口；`-k`／`--match` 按用例名片段或通配表达式筛选，可重复传入，命中任一表达式即选入。默认显示用例进度，`-q` 只隐藏逐例进度。Python 3.12+ 打印最慢用例，3.11 仍报告整组时间。只有所选用例全部执行且通过才返回 `0`；失败或跳过返回 `1`，选项无效、发现失败或未选中任何用例返回 `2`。如果不使用这个入口，原有 `python -m unittest discover -s app/tests -t app` 仍可在应用开发环境中直接运行；使用原生命令时须另外核对跳过数。

**并行是可选项，不等同于完整回归。** 该模式固定跑两组，不接受 `-k`；需要筛选就单跑对应组。每组使用独立的临时目录、测试账本和日志，启动前检查用例标识不重复，子进程重核选择并回报完成结果。屏幕先显示各组启动和状态，结束时按组输出日志与整次墙钟。`--timeout` 可调两组共享的时限，默认 180 秒；超时或有用例未完整通过返回 `1`，中断返回 `130`。正常通过会删除临时产物；失败会打印留在系统临时目录的诊断位置。Windows 作业对象用于回收进程树；如果环境不允许创建或绑定作业对象，运行会失败而不是在无约束下并行。遇到资源争用、环境不支持，或不再需要并行时，直接单跑 `build`、`runtime`，或用原有串行 `all`；没有安装额外工具或修改持久配置。

**采用依据**：Windows／Python 3.13 对同一批 `build` 和 `runtime` 用例进行串行与双进程各两轮对照。168 项均通过，无重复、无跳过；平均墙钟从 75.88 秒降至 46.46 秒。该收益仅适用于测过的两组，不外推到全量、浏览器组或 CI；其他平台仍走串行入口。

`app` 的 Schema 测试同样不允许 skip；`jsonschema` 是测试依赖，不是运行依赖。系统 v2 的 `docs/schema/v2-*.schema.json`（构建变更摘要、验证结果）也纳入同一规则；`docs/schema/v2-rules-feedback.sql` 用临时 SQLite 执行检查，不连接生产账本。

浏览器 fixture（需要 Chromium）：

```powershell
python -m uv run --project app python -m patchright install chromium
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py browser
```

浏览器分组覆盖配置与规则校验、静态／浏览器路由、JavaScript 渲染、本地追加列表、资源表清空、进程退出和临时浏览器配置目录回收。缺少 Chromium 时真实浏览器用例会被 `unittest` 标记为跳过，新入口会返回非零，不能当作通过。

真实站点验证按 [D01 模板](14-D01验证模板.md)、[验收场景](05-验收场景与比较方法.md) 和 [分阶段策略](方法指导/07-分阶段策略与效率.md) 的预算执行，证据写回对应实验目录或基准站文档，不放进默认测试命令。

### 前端测试怎么跑

| 入口 | 验证范围 | 使用时机 |
| --- | --- | --- |
| 在 `app/frontend-v2` 运行 `npm test` | Vitest + jsdom 验证规则和页面行为。候选缺同页回归时，显示原因、禁用激活、不发写请求；任务事件流断开后，页面轮询刷新计数和终态；取消失败时保留可重试对话框，不提示成功。接口和事件流由测试替代，不证明真实联通。 | 日常和合并前。改动单一页面时可用 `npm test -- src/features/tasks/TaskDetailPage.test.tsx` 先快跑。 |
| 从仓库根运行浏览器冒烟 | 单个无头 Chromium 打开 FastAPI 托管的 `/next/` 构建产物，走真实接口、托管 worker、临时 SQLite 和本地商品夹具。 | 改动批次、任务、导出或前后端接线时单独运行；暂不接入默认 CI。 |

浏览器测试复用应用现有的 Patchright Chromium。先按[后端测试环境](#后端测试怎么跑)准备应用开发依赖和 Chromium；首次或前端锁文件变更后，从仓库根运行 `npm --prefix app/frontend-v2 ci`。依赖就绪后，从仓库根按下列顺序执行；构建失败就停止，避免拿旧制品验证当次改动：

```powershell
npm --prefix app/frontend-v2 run build
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/frontend_smoke.py
```

**通过条件**：缺批次名称时显示校验并聚焦名称；导入预览识别一个可采站点且不写入账本；保存草稿后刷新仍能找到同一批次和站点；从批次创建的任务完成后，页面和任务接口都显示两件有效商品；从页面下载完整 ZIP，并核对其中的批次、站点、任务、九列 CSV 及两件商品的名称、价格、币种和来源。未预期的页面错误、错误响应、不完整执行或清理失败不算通过。

冒烟限时 90 秒，清理另设上限。它只使用本轮临时文件和回环服务，不访问真实站点、正式账本或模型；成功后清理临时目录，失败输出诊断目录，页面断言失败时保留浏览器 trace。缺构建产物或 Chromium 时返回非零，不会自动安装，也不会跳过报绿。不运行该入口即可回到原有校验方式，无常驻进程或持久配置。本阶段只在 Windows 本机验证；稳定复跑并完成目标 CI 环境验证后，再评估接入合并检查。不替代窄屏布局、跨浏览器、读屏和实站验收。

## CI 与失败政策

- 每次 push／PR 至少运行文档链接、示例一致性、导出与导出复核；CI 不访问真实站点。
- T1／T2 应在可复现环境中运行；2026-11-24 起 `app.yml` 运行后端 unittest + ruff 和前端 lint／typecheck／test／build，文档检查仍由 `docs.yml` 负责；不得用 skip 冒充通过。
- `test_browser.py` 的真实浏览器用例在缺少 Chromium 时按环境跳过；跳过只表示“未验证”，不能计入通过。`app.yml` 会安装 Chromium；发布或交接证据仍须记录浏览器版本。GitHub Actions 的 Ubuntu 24.04 会限制 Playwright 自带 Chromium 的 sandbox；`GITHUB_ACTIONS=true` 时启动参数自动加 `--no-sandbox`，生产默认仍保留 sandbox，这个差异只用于 CI 的本地 fixture。
- 生产应用 T1 已配置到 `app.yml`（2026-11-24），当日 CI 已通过（后端 281 个测试 + ruff，前端 lint／typecheck／test／build）；真实站点 T3／T4 和跨设备复现仍手工执行，CI 不声称覆盖这些范围。
- T3／T4 不进入默认 CI：真实站点有网络、挑战、限流和成本，必须按预算手工执行并保留证据。
- 失败、跳过、未运行分别记录；不得删除失败用例、弱化断言或把“零用例”写成通过。
- 行为契约变化时，同步更新测试和 AC 归属；旧证据随输入变化失效。

## 维护规则

- 构建提交受理后，从状态接口有界等待目标状态；不要用提交响应必须立即为 `RUNNING` 来验证调度。断言要保留真正的 `RUNNING`、冲突或终态；失败应报告最后观测的状态。临时账本在构建管理器关停、事件流与测试线程退出后再删除，清理超时是测试失败。
- 日常提速优先选小而有针对性的集合，不按耗时从合并门禁移除用例。后续若要加速完整回归，先用慢例报告定位等待或资源成本；实测超时、租约和回收的用例保留对应的真实边界，不用更短的固定等待替代。
- 测试分层、必测项或命令变化时更新本页，并同步 `21` 的测试门与 `15` 的当前状态。
- 不在本页复制业务字段、状态表或验收清单；引用对应正文。
- 新增真实站点证据时写清站点、范围、出口、客户端、请求数、日期和停止原因，不把单次成功写成长期稳定。
