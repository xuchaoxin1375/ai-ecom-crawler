## 用途与边界

本页落实 R12 的测试口径：说明哪些行为必须测、在哪一层测、用什么证据判断通过，以及哪些验证不能放进默认 CI。它不新增业务规则；字段、状态、计数和验收仍以 `01`～`09` 为准，当前完成状态以[交接与继续](15-交接.md)为准。

本页是生产应用测试的起点，不替代 D01／D09 的实站验收，也不把原型测试写成生产测试已完成。

## 测试分层

| 层 | 证明什么 | 不证明什么 | 运行方式 |
|---|---|---|---|
| T1 契约与单元 | manifest／Schema、正则语义、CSV、计数、状态转移、原子写、浏览器配置／路由 | 真实站点行为、浏览器渲染正确性、并发资源回收 | 开发时按改动选跑，合并前跑完整集合 |
| T2 fixture 集成 | discovery 来源、并行、暂停／取消、恢复、重试分类、静态与 JS 渲染 fixture | 真实站点覆盖、反爬、长期漂移 | 开发时跑受影响场景，合并前跑完整集合；缺 Chromium 时真实浏览器用例会跳过，不算完整通过 |
| T3 有界实站验证 | 声明范围内的真实响应、字段来源、停止原因 | 全站覆盖、长期稳定、跨环境 | 手工，按预算和证据要求 |
| T4 生产验收 | 合约、状态、CSV、安全边界和用户旅程在最终制品上成立 | 未测站或未声明范围 | D01／D09，独立记录与签字 |

T1／T2 是开发侧证据；T3／T4 是独立验证与验收，不能用前者的通过替代后者。

## 必测清单

- **契约**：`08` 的 manifest 结构、序列化、入口和版本兼容；`09` 的状态转移、计数、取消和迟到结果；`19` 的规则包与任务字段。
- **状态不变量**：重复提交、暂停／恢复、取消、崩溃对账、重试耗尽、原子替换、迟到结果拒收；检查点必须能解释“为什么重排、为什么失败”。
- **数据与导出**：9 列业务 CSV、公式注入保护、价格与币种、缺失与部分描述、零价变体、任务结果计数。
- **安全边界**：不登录、不付费、不绕过登录／付费／年龄门／地区限制和站点明确拒绝；挑战页按 [ADR 0022](adr/0022-挑战页处理边界.md) 处理；所有阶段 robots 只探测 `Sitemap:` 行，失败不阻塞，不解析其他规则；密钥、Cookie、浏览器 profile 不入库、不进日志；URL 与文件路径按允许范围处理。
- **提取正确性**：用真实页面样本和分层抽样核对字段来源；不以整页快照、测试名含 AC 编号或“能跑通”替代正确性判断。

## 环境与命令

文档检查：

```powershell
python scripts/check_docs_links.py --require-tracked
python scripts/check_examples.py
python scripts/export_docs.py
python scripts/export_docs.py --check dist/ai-ecom-crawler-docs.zip
```

`--require-tracked` 会拒绝工作区中存在但未被 git 跟踪的链接目标；本地检查通过不代表干净检出或 CI 通过。

R06 完整测试（包含 Schema）：

```powershell
python -m uv run --project experiments/framework-compare/scrapling --with "pyyaml==6.0.3" `
  --with "jsonschema>=4.23" `
  python -m unittest discover -s experiments/r06/tests -v
```

`jsonschema` 缺失时先补依赖，再重跑；不允许把 skip 当作通过。只跑 Schema 时加 `-p "test_schema.py"`。

### 后端测试怎么跑

日常编辑先跑 `quick` 或用 `-k` 选受影响用例，常见改动以 5–10 秒内得到结果为目标。改动触及接口、持久化或执行流程时补对应集成组。合并前执行不带筛选的 `all`，运行 `unittest` 自动发现的完整集合。Windows 本地可以用 `all --jobs 2` 执行同一集合，持续集成（CI）使用串行 `all`。真实站点、真实模型和进程级恢复演练按改动风险专项执行。

从仓库根目录运行，先准备 Python 3.11+、`uv` 及应用开发依赖。首次或锁文件变化后运行 `python -m uv sync --project app --extra dev --frozen`；后续示例中的 `--no-sync` 复用已准备好的环境。若运行 `browser` 或 `all`，还需要 Patchright Chromium；安装命令见下方。`build` 和 `all` 里的依赖桥插件测试需要 Node.js，不需要启动真实 OpenCode 或调用模型。测试仅使用临时文件、临时账本及本地模拟服务，不访问真实站点。

#### 什么时候起服务

| 被验证的边界 | 测试怎么跑 | 能验证什么 |
| --- | --- | --- |
| Schema、规则和数据转换 | `quick` 直接调用 Python 入口，部分用例用临时文件 | 校验、字段规范化和导出契约 |
| 应用 API 和账本 | `api` 主要在测试进程内用 FastAPI `TestClient` 调用 ASGI 应用并读写临时 SQLite，无需监听端口 | 实际路由、中间件、输入校验、状态码和持久化。需要验证托管 worker 生命周期时，用 `with TestClient(...)` 触发启动与关闭 |
| 采集运行时和浏览器 | 相关集成用例按需在回环地址启动模拟商品站。`browser` 中的集成用例用真实 Chromium 访问它 | HTTP 响应、分页、JavaScript 渲染和资源回收。商品站与应用 API 是不同服务 |
| 工作台浏览器冒烟 | `frontend_smoke.py` 启动临时 Uvicorn 应用，用真实 Chromium 打开构建产物 | 验证工作台导航、新建批次、可采和待接入节点、任务完成与 ZIP 交付 |
| 启停和进程恢复 | `recovery_drill.py` 用临时账本启动真实 `serve` 子进程，在任务执行中强杀并重启 | 跨进程账本接管、恢复及导出重建 |

涉及 HTTP 监听、连接断开、代理转发或进程退出的改动，用真实端口或进程覆盖相应边界。业务规则的分支优先放在能观察到该行为的最低测试层，跨栈链路留代表性用例。

| 分组 | 什么时候用 | 范围 |
| --- | --- | --- |
| `quick`（默认） | 日常开发先获取反馈 | Schema、字段规范化、业务 CSV、规则差异 |
| `api` | 改了批次、任务接口、反馈或迁移 | 进程内 FastAPI `TestClient` 和临时 SQLite，包含批次从启动采集到交付的回归 |
| `build` | 改了构建、验证、激活或依赖审批 | 假构建适配器、队列、权限与依赖桥、本地集成测试 |
| `runtime` | 改了任务执行、租约、存档或恢复 | 本地 HTTP、临时 SQLite、任务状态、适配器子进程及清理 |
| `parallel` | Windows 本地，要同时验证构建与运行时 | 两个独立进程各跑一组，只覆盖 `build` 和 `runtime`；不启动 Chromium |
| `browser` | 改了浏览器抓取或列表推进 | 配置与路由测试、真实 Chromium 访问本地页面；不是工作台界面验收 |
| `all` | 合并前、CI 或并行出错时排查 | 串行执行自动发现的全部后端用例 |
| `all --jobs 2` | Windows 本地加快完整回归 | 按预计耗时分配全部后端用例，两个浏览器模块在同一进程内串行执行 |

```powershell
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py api -k BatchApiTests
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py build -k price_regression
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py parallel -q
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py all -q
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py all --jobs 2 -q
```

用 `--help` 查看入口。`-k`／`--match` 按用例名片段或通配表达式筛选，可重复传入，命中任一表达式即选入。`-q` 隐藏逐例进度，保留用例数、整组时间和按耗时排序的模块汇总。模块时间累计用例及其 `setUp`、`tearDown` 和清理耗时。模块和类级夹具、发现和进程启动另计，其中模块和类级夹具体现在 `unittest` 的整组时间里。Python 3.12+ 还显示最慢用例。仅当所选用例全部执行且通过才返回 `0`。失败或跳过返回 `1`，选项无效、发现失败或未选中用例返回 `2`。直接运行 `python -m unittest discover -s app/tests -t app` 时须另核跳过数。

两个并行入口都使用 Windows 作业对象回收进程树。子进程各有独立的临时目录、测试账本和日志，启动后按用例 ID 核对选中集合，通过后写回完成回执。全量并行在启动前额外核对两个分片的合并结果与完整发现一致。新测试文件由 `unittest` 自动发现，缺少耗时记录时按用例数估算。

两个并行入口都要求完整运行所选范围，使用 `-k` 时请改用串行命令。并行摘要显示各子进程耗时和全量墙钟，超时时列出未完成分片。`--timeout` 设置两组共享的执行时限，默认 180 秒。超时或任一组未完整通过返回 `1`，中断返回 `130`。成功后清理临时产物，失败时打印诊断目录。遇到资源争用或作业对象不可用时，用串行 `all` 复核全量，或用对应分组复现首个失败用例。

CI 分别记录 Python 依赖同步、Chromium 安装和串行 `all -q` 的步骤耗时。Node.js 和 Chromium 均由 CI 显式准备，必需用例跳过会使测试步骤失败。

回归变慢时，先在同一源码快照、依赖和机器上记录完整用例数、跳过数、模块耗时及串并行墙钟。对最慢模块优先减少重复环境准备、长链路和固定等待。顺序控制用事件或状态同步，超时、限速和租约用例保留相应边界的断言。真实 HTTP、SQLite、Chromium 和交付格式各保留代表性集成场景。分片耗时失衡时用完整串行结果校准模块估时，避免拿重叠的日常分组当完整分片。只有同一用例集合的多轮串并行结果一致、并行收益明显且资源已回收，才考虑增加 worker 或在 CI 启用分片。

本地 HTTP 测试共用 50 ms 退出轮询，构建演练对本地模拟服务使用 50 请求/秒。两处调整保留真实 HTTP、SQLite、导出断言及专门验证限速的用例。

### 前端测试怎么跑

| 入口 | 验证范围 | 使用时机 |
| --- | --- | --- |
| 在 `app/frontend` 运行 `npm test` | Vitest + jsdom 验证规则和页面行为。候选缺同页回归时，显示原因、禁用激活、不发写请求；任务事件流断开后，页面轮询刷新计数和终态；取消失败时保留可重试对话框，不提示成功。接口和事件流由测试替代，不证明真实联通。 | 日常和合并前。改动单一页面时可用 `npm test -- src/features/tasks/TaskDetailPage.test.tsx` 先快跑。 |
| 从仓库根运行浏览器冒烟 | 单个无头 Chromium 使用当前工作台操作并调用真实 HTTP API，核对任务和导出件 | 改动页面挂载、导航、批次加入、任务启动或导出时执行，当前未接入默认 CI |

模型配置页由 `src/features/builds/ModelSettingsPage.test.tsx` 覆盖添加模型并保存顺序、探测结果、恢复环境配置和只读状态。后端 `test_builds.py` 覆盖页面设置持久化、重启读取、新构建热生效、非法保存、损坏设置回退、空池和只读 403。

浏览器测试复用应用现有的 Patchright Chromium。先按[后端测试环境](#后端测试怎么跑)准备应用开发依赖和 Chromium；首次或前端锁文件变更后，从仓库根运行 `npm --prefix app/frontend ci`。依赖就绪后，从仓库根按下列顺序执行；构建失败就停止，避免拿旧制品验证当次改动：

```powershell
npm --prefix app/frontend run build
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/frontend_smoke.py
```

**当前通过条件**。首页与旧批次链接进入 `/#/workbench`。在工作台创建含两个合成站点的批次，刷新后仍能看到可采节点和待接入节点；从可采节点启动运行，等页面自动显示完成、两件有效商品和零失败，通过 API 读回批次归属及终态，从页面下载 ZIP 并核对任务结果、CSV 表头和两件商品的名称、价格、币种及来源。未预期的页面异常、控制台错误、失败请求或 HTTP 错误会使冒烟失败。接入构建、模型供应商和实站验收按各自入口执行。

冒烟限时 90 秒，清理另设上限。它使用临时文件、临时账本和回环服务。成功后清理临时目录，失败输出诊断目录，页面断言失败时保留浏览器 trace。缺构建产物或 Chromium 时返回非零。当前记录为 Windows 本机验证，接入合并检查前需复核目标 CI 环境。窄屏布局、跨浏览器、读屏和实站验收仍按各自场景执行。

## 开发阶段轻量验证

当前阶段以单人／单 agent、快速迭代和 Windows 本机为主。验证采用“1 张卡 + 3 个检查环”，补在 T1／T2 与 T3／T4 之间；不新增测试层级，不替代正式验收。

### 三个检查环

| 检查环 | 时机 | 做什么 | 通过标准 |
| --- | --- | --- | --- |
| 切片检查 | 每次改动 | 只跑受影响的后端分组、前端测试文件、lint／typecheck；文档改动跑链接检查 | 目标用例通过，没有新增错误 |
| 合并检查 | 提交前 | 后端 `all`、前端全量测试与构建、ruff；文档改动补示例与导出复核 | 必需命令退出码为 0，无跳过 |
| 用户路径检查 | 面向用户或交互改动 | 真实入口、全新浏览器 profile、3–5 条场景；覆盖失败／空／慢／无权限中适用的状态 | 对承诺自助完成的功能，用户不看文档能完成任务，失败可恢复 |

命令沿用[环境与命令](#环境与命令)和[前端测试怎么跑](#前端测试怎么跑)，不另写一套。合并检查的典型组合：

```powershell
python -m uv run --project app --extra dev --frozen --no-sync python app/tests/run.py all
python -m uv run --project app --extra dev --frozen ruff check app
npm --prefix app/frontend run lint
npm --prefix app/frontend run typecheck
npm --prefix app/frontend test
npm --prefix app/frontend run format:check
npm --prefix app/frontend run build
```

文档改动另跑[文档检查](#环境与命令)的四条命令。缺 Chromium、跳过或未运行时分别记录，不能写成通过。

按改动类型取最小集：

| 改动 | 切片检查 | 合并检查 | 用户路径 |
| --- | --- | --- | --- |
| 纯文档 | 链接检查 | 示例、导出复核 | 不需要 |
| 纯后端逻辑 | 对应分组 `-k` | `all` + ruff | 不需要 |
| 前端样式／文案 | 单个 Vitest 文件 | 前端全量 + build | 交互或布局变化时做 |
| API + 前端接线 | 后端分组 + 前端文件 | 两端全量 | 必做 |
| 认证、权限、数据迁移、首次配置、密钥、计费 | 两端针对性 + 负向用例 | 两端全量 + 文档检查 | 必做，加全新 profile 和失败路径 |

高风险改动还必须写明回滚或恢复方式；没有恢复证据时结论只能是 `PARTIAL`。

### 验证卡

每次改动只留一张卡，放在任务记录、`docs/15` 当前切片或提交说明里，不单独建正式报告：


### 正式化路径

现在只用验证卡和场景编号，不建新工具。出现下列任一情况再升级：

- 同一类回归出现两次；
- 多人协作或出现外部用户；
- 进入发布／交付节点；
- 认证、权限、数据迁移、计费等高风险改动增多。

升级顺序：

- 把 `V-01` 等场景编号从示例提升为正式验收清单，并映射到 AC；
- 增加 `scripts/verify.py fast|full|ui` 薄封装，输出同一张卡的 Markdown／JSON；
- 把 `full` 接入 CI，`ui` 作为合并前手工或夜间检查；

当前不做：覆盖率阈值、完整 E2E 矩阵、正式签字、多角色审批、测试管理平台。它们要等协作规模和发布承诺需要时再加。

## CI 与失败政策

- 每次 push／PR 至少运行文档链接、示例一致性、导出与导出复核；CI 不访问真实站点。
- T1／T2 应在可复现环境中运行；2026-11-24 起 `app.yml` 运行后端 unittest + ruff 和前端 lint／typecheck／test／build，文档检查仍由 `docs.yml` 负责；不得用 skip 冒充通过。
- `test_browser.py` 的真实浏览器用例在缺少 Chromium 时按环境跳过；跳过只表示“未验证”，不能计入通过。`app.yml` 会安装 Chromium；发布或交接证据仍须记录浏览器版本。GitHub Actions 的 Ubuntu 24.04 会限制 Playwright 自带 Chromium 的 sandbox；`GITHUB_ACTIONS=true` 时启动参数自动加 `--no-sandbox`，生产默认仍保留 sandbox，这个差异只用于 CI 的本地 fixture。
- 生产应用 T1 已配置到 `app.yml`（2026-11-24），当日 CI 已通过（后端 281 个测试 + ruff，前端 lint／typecheck／test／build）；真实站点 T3／T4 和跨设备复现仍手工执行，CI 不声称覆盖这些范围。
- T3／T4 不进入默认 CI：真实站点有网络、挑战、限流和成本，必须按预算手工执行并保留证据。
- 失败、跳过、未运行分别记录；不得删除失败用例、弱化断言或把“零用例”写成通过。
- 行为契约变化时，同步更新测试和 AC 归属；旧证据随输入变化失效。
