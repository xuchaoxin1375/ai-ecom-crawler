## 用途与边界

本页落实 R12 的测试口径：说明哪些行为必须测、在哪一层测、用什么证据判断通过，以及哪些验证不能放进默认 CI。它不新增业务规则；字段、状态、计数和验收仍以 `01`～`09` 为准，当前完成状态以[交接与继续](15-交接.md)为准。

本页是生产应用测试的起点，不替代 D01／D09 的实站验收，也不把原型测试写成生产测试已完成。

## 测试分层

| 层 | 证明什么 | 不证明什么 | 运行方式 |
|---|---|---|---|
| T1 契约与单元 | manifest／Schema、正则语义、CSV、计数、状态转移、原子写、浏览器配置／路由 | 真实站点行为、浏览器渲染正确性、并发资源回收 | 无网络，每次改动都跑 |
| T2 fixture 集成 | discovery 来源、并行、暂停／取消、恢复、重试分类、静态与 JS 渲染 fixture | 真实站点覆盖、反爬、长期漂移 | 本地 fixture，每次改动都跑；真实浏览器用例缺少 Chromium 时跳过 |
| T3 有界实站验证 | 声明范围内的真实响应、字段来源、停止原因 | 全站覆盖、长期稳定、跨环境 | 手工，按预算和证据要求 |
| T4 生产验收 | 合约、状态、CSV、安全边界和用户旅程在最终制品上成立 | 未测站或未声明范围 | D01／D09，独立记录与签字 |

T1／T2 是开发侧证据；T3／T4 是独立验证与验收，不能用前者的通过替代后者。

## 必测清单

- **契约**：`08` 的 manifest 结构、序列化、入口和版本兼容；`09` 的状态转移、计数、取消和迟到结果；`19` 的规则包与任务字段。
- **状态不变量**：重复提交、暂停／恢复、取消、崩溃对账、重试耗尽、原子替换、迟到结果拒收；检查点必须能解释“为什么重排、为什么失败”。
- **数据与导出**：9 列业务 CSV、公式注入保护、价格与币种、缺失与部分描述、零价变体、任务结果计数。
- **安全边界**：不登录、不付费、不绕过访问控制；robots 只探测 `Sitemap:` 行；密钥、Cookie、浏览器 profile 不入库、不进日志；URL 与文件路径按允许范围处理。
- **提取正确性**：用真实页面样本和分层抽样核对字段来源；不以整页快照、测试名含 AC 编号或“能跑通”替代正确性判断。

## 环境与命令

文档检查：

```powershell
python scripts/check_docs_links.py
python scripts/check_examples.py
python scripts/export_docs.py
python scripts/export_docs.py --check dist/ai-ecom-crawler-docs.zip
```

R06 完整测试（包含 Schema）：

```powershell
python -m uv run --project experiments/framework-compare/scrapling --with "pyyaml==6.0.3" `
  --with "jsonschema>=4.23" `
  python -m unittest discover -s experiments/r06/tests -v
```

`jsonschema` 缺失时先补依赖，再重跑；不允许把 skip 当作通过。只跑 Schema 时加 `-p "test_schema.py"`。

生产应用 D02（导出层 T1，无网络）：

```powershell
python -m uv run --project app --extra dev `
  python -m unittest discover -s app/tests -t app -v
python -m uv run --project app --extra dev ruff check app
```

`app` 的 Schema 测试同样不允许 skip；`jsonschema` 是测试依赖，不是运行依赖。

浏览器 fixture（需要 Chromium）：

```powershell
python -m uv run --project app python -m patchright install chromium
python -m uv run --project app --extra dev `
  python -m unittest app.tests.test_browser -v
```

`test_browser.py` 有 8 个用例：配置与规则校验、静态／浏览器路由、JS 渲染 fixture、资源表清空、profile 删除和 PID 退出。缺少 Chromium 时真实浏览器用例跳过，跳过不计入通过；本机有 Chromium 的完整运行结果为 8／8。

真实站点验证按 [D01 模板](14-D01验证模板.md)、[验收场景](05-验收场景与比较方法.md) 和 [分阶段策略](方法指导/07-分阶段策略与效率.md) 的预算执行，证据写回对应实验目录或基准站文档，不放进默认测试命令。

## CI 与失败政策

- 每次 push／PR 至少运行文档链接、示例一致性、导出与导出复核；CI 不访问真实站点。
- T1／T2 应在可复现环境中运行；当前 CI 先覆盖文档检查，运行时测试按上节命令手工执行，接入 CI 后不得用 skip 冒充通过。
- `test_browser.py` 的真实浏览器用例在缺少 Chromium 时按环境跳过；跳过只表示“未验证”，不能计入通过。发布或交接证据必须在装有 Chromium 的环境实际运行，并记录浏览器版本。
- 生产应用 T1 尚未接入 CI；当前 `app` 命令可手工复现，接入前不得声称 CI 已覆盖生产代码。
- T3／T4 不进入默认 CI：真实站点有网络、挑战、限流和成本，必须按预算手工执行并保留证据。
- 失败、跳过、未运行分别记录；不得删除失败用例、弱化断言或把“零用例”写成通过。
- 行为契约变化时，同步更新测试和 AC 归属；旧证据随输入变化失效。

- 生产应用已落地 D02 导出层、D04 v0 执行器和浏览器 adapter v0：T1 覆盖数据合同、9 列 CSV、任务结果、计数不变量、质量异常和 `docs/示例` 回归；本地 HTTP fixture 覆盖规则 → 发现 → 抓取 → 提取 → SQLite 账本 → D02 导出；`test_browser.py` 用 JS 渲染 fixture 覆盖浏览器配置、静态／浏览器路由、渲染后提取、资源表清空、profile 删除和 PID 退出，缺少 Chromium 时跳过并在本机有 Chromium 的环境补跑。D08 的 API／UI 测试设计见 [D08 任务服务与界面设计](26-D08任务服务与界面设计.md)；`serve` API（含规则目录、创建／控制、SSE、归档）和托管 worker 生命周期已由 `test_web.py` 覆盖；完整 UI 原型仍缺。

- 构建 harness 适配器：`test_harness.py` 7 个用例覆盖 HTTP 客户端、session／prompt／permission／interrupt、SSE 解析、事件归一化与推理脱敏、工作区布局、pause-gate 控制文件、依赖策略事件、取消／关闭和 server 进程回收；`test_dependencies.py` 6 个用例覆盖基线、allowlist、安装失败、非法包名／manager 和显式 build interpreter；`test_service.py` 3 个用例覆盖单活动构建、事件泵、暂停期间 held 权限、恢复回复、finished 和依赖委托。真实 `opencode serve` 2.3.2 的无模型 session／事件／权限冒烟、`opencode-go/deepseek-v4.1-flash`（variant high）的 prompt＋执行中 interrupt 冒烟和真实 shell 工具的 pause-gate 冒烟（`shell allow -> ask`）通过。`request_dependency` 工具桥、真实安装、构建会话 UI 和自然完成仍未自动化。同一组 harness／依赖／服务测试在 WSL2 Ubuntu + Python 3.12.3、`PYTHONPATH=app/src` 下通过（WSL 无真实 opencode，仅 fake server）。

- 依赖基线只在本机验证；跨设备复现（R11）完成前，CI 不能声称覆盖目标平台。
- R12 在本页评审通过、并随 D01～D09 补上生产测试计划后才算落地；当前状态是“已起草”。

## 维护规则

- 测试分层、必测项或命令变化时更新本页，并同步 `21` 的测试门与 `15` 的当前状态。
- 不在本页复制业务字段、状态表或验收清单；引用对应正文。
- 新增真实站点证据时写清站点、范围、出口、客户端、请求数、日期和停止原因，不把单次成功写成长期稳定。
