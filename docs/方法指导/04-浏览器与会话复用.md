## 开放Skill参考的采用方式

本篇依据Skill真源中的开放`resilient-browser-fetch`整理，不沿用项目旧版作为标准。工具名称与能力是该源版本的参考，实际接入Scrapling、官方MCP／Skill或其他成熟能力时须按安装版本验证；不要求保留这个封装。

## 先选产物，再选获取方式

| 产物 | 含义 | 对本项目的作用 |
| --- | --- | --- |
| 结构化商品字段 | 名称、价格、描述、选项及来源 | 默认业务交付，不要求保存整页 |
| HTML快照 | HTTP原文或渲染DOM序列化的HTML；图片等仍可指向原站 | 仅获准的开发／诊断证据，不等于离线存档 |
| 截图 | 某视口的可见像素 | 辅助核对描述区域和动态状态，不能证明全部隐藏内容完整 |
| 离线存档 | 连同子资源或内联资源供断网使用 | 额外需求，不因“采集产品信息”自动创建 |

DOM序列化不是写盘，也不包含完整JavaScript运行时、事件监听器或画布状态。等待条件不会自动完成点击／滚动，懒加载或展开内容仍需实际动作。

## 能力和检测维度

开放版本区分标准HTTP、浏览器渲染、挑战处理和可选指纹底座，并有直接调试协议(CDP)与晚接入参考。**能力层级不是隐蔽性或通过率排名**。

| 情况 | 判断与方法 |
| --- | --- |
| 静态字段已足够 | 直接请求，不为“稳”默认启动浏览器 |
| 需要客户端渲染 | 选择合适浏览器，等待稳定主内容或字段 |
| 已确认挑战 | 选实际有能力的处理路径，正常正文仍做内容验证 |
| 多个引擎卡相同挑战 | 比较驱动／控制面、浏览器指纹、出口／地区，不默认再叠一层 |
| 用户浏览器可见而自建浏览器被拒 | 有界核对客户端身份与会话；合法接管或晚接入是可选路线，不保证成功 |
| 边缘直接拒绝且没有挑战窗口 | 区分明确拒绝与挑战等待；不能把没有挑战的拒绝交给求解器无限等 |
| 明确资源不存在 | 404／410无挑战时停止升档，用同站对照区分资源与链路 |

强制指定引擎、浏览器品牌或驱动用于复现实验时，应记录实际选择；不能静默换成别的实现还声称是同一条件。自动模式的真实尝试顺序以该版本代码和元数据为准，不能只根据层号推断。

## 连续批量工作

1. 按站点源、出口和浏览器身份分组，选择静态会话、普通渲染会话或带挑战恢复的会话。
2. 对需要预热／验证的站点，先单路访问首页并验证有效内容，再放开后续并发。
3. 目录、商品、同站对照页和公开接口探针共享合适会话，不为每个网址新建浏览器。
4. 复用同一上下文、出口和身份，限制标签页并发；跨站或出口改变不能假定原验证态继续有效。
5. 子页遇新挑战时暂停派发、由一次协调恢复重新确认，再继续；普通404不触发全会话升档。
6. 任务结束释放全部自建会话、进程、调试端口和临时目录；长期profile(浏览器配置目录)另按所有权管理。

Cookie导出或存储状态恢复不等于原浏览器上下文，不能承诺跨重启验证继续有效。同一profile不能同时被多个进程打开；不要把多个全新浏览器当作标签页并发。

## 等待、验证与回收

页面加载事件、网络空闲和目标字段就绪不是同一条件。长连接可能使网络一直不空闲；优先实际内容判断，状态码和正文大小只是基础检查，商品页至少核主内容或稳定字段以防软错误壳。

成功、失败、硬超时和启动者异常退出均须有回收路径。只回收自己启动的进程树，不能按进程名批量杀浏览器；接管用户已有浏览器时只释放连接，默认不导航、不关闭或删除其profile。

报告实际启动／回收数量和残留；回收未确认时先停新增实例。调用方的`finally`不能保证应对被强制结束，应由受管运行器提供相应生命周期兜底。

这些是设计与验收指导，不证明新团队已具备任何反检测效果。原版附件及许可见[来源说明](../来源与维护.md)。
