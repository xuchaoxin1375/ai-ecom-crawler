## 从结果反推方法

目标是用直接、高效、可复用的方法产出符合[数据标准](../02-数据标准与导出.md)的商品。不限定唯一分析顺序，不要求先把所有规则语言能力试完才允许程序／浏览器。

| 观察 | 方法取舍 |
| --- | --- |
| 已有方案与当前证据一致 | 复用并验证，不重复调用模型构建 |
| 公开JSON字段稳定完整 | 可直接读取；缺正文／币种时按字段补足，不伪装成HTML解析 |
| 页面语义结构清楚 | 用主商品DOM(文档对象模型)及结构化解析 |
| 多模板字段位置不同 | 各自保留有效来源，避免一条宽选择器误命中 |
| 字段由动态动作生成 | 观察必要动作和就绪条件，再选择浏览器或可验证公开请求 |
| 声明式表达绕远 | 用站点程序及成熟库，不为单站持续扩大共享规则语言 |

## 按页面层级选源

字段选源不只看 JSON-LD／CSS，还要看它最早出现在哪一层：

| 页面层级 | 常见字段 | 默认动作 |
| --- | --- | --- |
| 列表／型号／系列 | 名称、编号、价格、状态、缩略图 | 先取；字段足够就不下钻 |
| 详情 | 正文、规格、兼容关系、结构化报价 | 只补缺失或独有字段 |
| 搜索／公开接口 | 编号查找、定点核验 | 有界使用，不当全量目录 |
| SPA 公开 JSON | 商品基本字段、详情块 | 从内联配置找 API origin／path，用一次浏览器 XHR 确认请求头后重放；字段完整就不逐页渲染 |
| 变体 JSON／公开变体接口 | 变体价格、可售、SKU、选项 | 公开 JSON 已列出的变体直接读取；基础价取最低变体价，不把变体当独立商品 |
| WooCommerce 变体 | `data-product_variations` 的 display_price／is_in_stock／SKU | 价格常为十进制；父级 JSON-LD availability 不可替代变体状态 |
| Marketplace 商品／offer | 商品页 `/p/...` 的 AggregateOffer low／high／count；item 页 seller／condition／price／shipping | 先定商品或 offer 单位；历史 price guide 不是当前价；聚合 itemCondition 不能替代 item 级成色 |

同一字段在多层都有时优先浅层；深层值用于校验或补缺，不重复抓取。型号页的多行零件表通常是入口，不聚成一个商品；零件行有独立编号和报价时，按零件身份记录。详情页没有正文时，按数据标准标“原站未提供／摘要回退／部分提取”，不要用模板摘要冒充完整正文。

## 基础字段与进阶字段

默认交付先保证基础字段：商品身份与来源 URL、名称、当前价格与币种、可售状态、主图，以及描述是否存在。完整正文与规格、兼容关系、选项变体、文档和全量覆盖属于进阶项，任务未要求时不作为默认目标。

| 层级 | 字段 | 默认动作 |
| --- | --- | --- |
| 基础 | 身份与来源 URL、名称、价格与币种、状态、主图 | 必取；缺失、占位或冲突要留因 |
| 基础（描述存在性） | 是否为主商品、是否有实质内容、状态 | 记录完整／部分／摘要／原站未提供／提取失败 |
| 进阶 | 完整正文与规格、兼容关系、选项变体、文档、全量覆盖 | 任务明确要求再做；先抽样证明增量价值 |

描述缺失时，数据字段留空并标 `not_provided`；产品名兜底只放在展示层，不写回 `description_html`。源码只有空标签时按“原站未提供”或“提取失败”区分；JSON-LD 模板摘要按“摘要回退”记录，不算完整正文。

## 逐字段核对

1. 确认主商品身份及价格上下文，排除推荐、促销组件和其他市场。
2. 对名称、价格、币种、图片、正文、选项和变体分别选源，依据完整性、稳定性和试跑结果，不强求固定源优先级；描述先判断存在性与状态，再谈完整度。
3. 正文优先真实主描述及分散规格；摘要不代表完整。先按标题或嵌入 JSON 的 section 拆块，适配车型、套装清单、配料／营养／过敏原、运费／退换政策不拼进描述；清洗后只有空标签时按“原站未提供”或“提取失败”区分；复杂部分可按新业务口径标注，不能隐藏已知缺失。
4. 币种需要同报价证据；同一主商品所有报价明确同币种且无相反市场信息时，可利用该一致性，不重复无关调查。接口商品对象未带币种时，用同一门店／报价上下文的币种字段补齐（如 Shopify 的 `Shopify.currency`），不凭域名或符号猜。
5. 原站未提供的品牌／规格留空，实际存在却漏采的字段修复。不要因库存样式差异扩大调查，也不枚举SKU报价组合。
6. 所有金额比较按数值进行，税价采用实际选定口径并注明；有效商品必须正价。
7. 库存、停售、无价格和未知状态分开记录；停售可能仍有价格，不能因价格存在就当可售；零价、无价不进入有效商品集。`OnlineOnly`／`InStoreOnly` 是销售渠道，不是库存状态。公开接口的 availability 要确认是门店级、市场级还是默认店级，不默认全站。
8. 主图排除 `none.jpg`、Logo、占位图和推荐图；文件名、alt 和渲染结果都要看，占位资源不算有效主图。
9. 同一字段多个来源冲突时，记录冲突来源和采用依据；源码看不到描述、主图或购买控件时，可用浏览器截图核对可见状态，截图不作为批量提取手段。
10. 变体商品：商品可售＝任一公开变体可售；基础价取公开最低变体价；缺 SKU 用商品 ID／handle＋选项值；平台字段可能是 Shopify `variants`、WooCommerce `data-product_variations`、Magento configurable，父级 JSON-LD availability 不能替代变体级库存。公开 JSON 可能含内部说明或隐藏捆绑，交叉核对店面可见性。多门店跨店合并优先 UPC／EAN／GTIN／MPN，先用样本验证 URL UUID／slug／catalogue ID 是否全局唯一。
11. 公开 JSON 目录先读分页元数据（skip／take、page／limit、total），空页或 skip ≥ total 停止；列表对象已含基础字段时先列表层取数，详情只补描述／规格。
12. 多市场：同一商品按目标市场分别记录价格／币种；`?country=`／市场路径与 `Shopify.currency`／`og:price:currency` 交叉核对；价格单位（分或十进制）先确认，不跨市场取最低价或仅按汇率换算。
13. 多卖家 marketplace：商品页是一个 model，item 是 offer；先定计数单位。商品页价格用 AggregateOffer 的 low／high／count 或声明的聚合口径；item 页逐 offer 记录 seller、condition、price、shipping，运费注明目的地；不要把推荐卡价格或历史 price guide 当当前主价。

## 试跑和修订

积极使用提供的观察和试跑工具，拿真实反馈在同次任务里修订。反馈定位到网址、样本、字段、实际错误及所用方法。没有工具时说明具体缺什么、为何需要及替代办法，不凭空声称已验证。

正常模板与失败模板同时复核；修正只影响实际问题，必要时审计同类入口。不能更改真实样本或降低数据要求来洗绿。工具格式通过、字段测试通过、来源核对和正式运行分别报告。

## Agent活动与时间

公开记录证据、方法、动作、结果和下一步，可保留足够解释，不只输出阶段名。模型速度和网站复杂度不同，不用统一安静时长判断卡死；模型总时长与请求／浏览器硬上限分别设计，取消和进程回收始终真实生效。

这类经验原来自采集方案开发Skill，已移除其特定`.agent-task`目录、专用DSL和宿主许可版本；新团队绑定自己的实际接口。方案保存与复用的结构见[采集方案与兼容契约](../08-采集方案与兼容契约.md)。
