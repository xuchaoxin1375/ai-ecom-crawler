## 用途与边界

本文定义构建 Agent 的预置环境和依赖请求规则，目标是让常见站点分析、规则编写和试跑不被缺包打断。它不是执行期的依赖清单，也不是方案包的一部分；执行期仍以方案包和项目运行时为准。

v1 不建设 AI Agent 安全沙箱；本文的边界是工作区、浏览器 profile 和权限规则，不是 OS／VM 级隔离。

相关决策见[构建 Harness 选型与集成方式](adr/0006-构建Harness选型与集成方式.md)；方案包见[采集方案与兼容契约](08-采集方案与兼容契约.md)；运行时见[采集规则与任务运行时](19-采集规则与任务运行时.md)。

## 基线分层

| 层 | 预置内容 | 说明 |
| --- | --- | --- |
| 运行时 | Python 3.11+、uv、Node.js LTS、Git、curl、ripgrep、jq、解压工具 | 版本在共享 venv 或设备镜像上锁定，不依赖系统最新版 |
| 采集库 | httpx／requests、lxml、beautifulsoup4、selectolax、Scrapling、Playwright／Patchright | 覆盖静态 HTML、JSON、SPA、挑战站和浏览器操作；具体版本按基线锁定 |
| 浏览器 | Chromium／Chrome 稳定版 + Playwright 浏览器；可选 Firefox／WebKit | 浏览器与驱动版本匹配；每个构建独立 profile |
| Agent | OpenCode 固定版本、provider 配置、DeepSeek key 通过环境变量 | 不把 key 写入镜像、工作区或日志 |
| 控制工具 | `pause-gate` 插件、`request_dependency` 工具 | 暂停门和依赖请求由 BuildService 提供 |

- 预置以“常用、稳定、许可兼容、可自动验证”为准；站点专用库和一次性脚本不预置。
- 不预置 Cookie、登录态、用户浏览器 profile、付费工具、站点专用代码或整页样本。
- 基线用 `YYYY.MM.DD` 标识；`out/result.json` 记录基线版本和本次新增依赖。

## 快速构建

仓库提供 `baseline/requirements.txt`、`baseline/requirements.lock.txt` 和 `scripts/setup_crawl_env.py`。脚本创建仓库外的 uv venv，安装锁文件，执行导入和 Chromium 冒烟，写入 `baseline.json`。

| 操作 | 命令 |
| --- | --- |
| 默认安装 | `python scripts/setup_crawl_env.py` |
| 指定位置 | `python scripts/setup_crawl_env.py --path D:/crawl-base` |
| 只装 Python 包 | `python scripts/setup_crawl_env.py --skip-browser` |
| 只看计划 | `python scripts/setup_crawl_env.py --dry-run --json` |

- 默认路径：Windows `%LOCALAPPDATA%\crawl-base`；其他平台 `~/.local/share/crawl-base`；可用 `CRAWL_BASE_HOME` 覆盖。
- Windows 入口：`<base>\bin\crawl-python.cmd`；POSIX：`<base>/bin/crawl-python`。
- 本机 2026-11-20 验证：Python 3.13.13、37 个包、Scrapling 0.5.1、Chromium 冒烟通过。D05 于 2026-11-21 在 WSL2 Ubuntu、Python 3.12.3 的干净 venv 复现 familidoo 6 商品（7 请求、6／6）；Scrapling 的 `FetcherSession` 还需显式安装 `curl_cffi`、`patchright`、`browserforge`，`StealthySession` 还需要 `msgspec`，因此项目统一使用 `scrapling[fetchers]`。跨物理设备复现仍未验证。
- 脚本只管理 Python venv；Git、Node、OpenCode、jq、ripgrep、curl 等系统工具由设备预置或包管理器安装，预检只报告缺失。
- 脚本不写全局 site-packages，不安装系统包；系统级组件仍按依赖请求处理。

## 权限基线

默认策略是“常规放行、高风险询问、硬边界拒绝”。完整矩阵以本节为准，ADR 0006 只记录决策。权限基线是审批和边界规则，不是安全沙箱；v1 不依赖它提供强隔离。

| 类别 | 默认 | 说明 |
| --- | --- | --- |
| 工作区内读写、目录浏览 | `allow` | 只限本次构建工作区 |
| 业务文档读取 | `allow` | 只读挂载 |
| 浏览器启动、操作、截图 | `allow` | 独立 profile，按构建回收 |
| 公开网页 webfetch／websearch | `allow` | 允许的 origin／路径；robots 只取 Sitemap 行，遵守 ToS |
| 工作区内 Python／Node／CLI | `allow` | 非破坏性；shell 扫描器尽力而为 |
| 基线或 allowlist 依赖安装 | `allow` | 通过 `request_dependency`；只装构建环境 |
| 未知依赖、系统级包、全局配置 | `ask` | 一次性审批；失败回退 |
| 工作区外访问（非主目录／凭据） | `ask` | 需要 `build-task` 声明或一次性审批 |
| 用户主目录、凭据、密钥 | `deny` | 不作为构建输入 |
| 登录、付费、验证码、访问控制 | `deny` | 不绕过 |
| git push、外部消息、购买、系统服务 | `deny` | 构建期不需要 |

- `allow` 不等于无边界：工作区、origin、超时、输出上限和资源配额仍然生效。
- `ask` 只在真正影响安全或环境时出现；常规分析不逐次弹窗。
- `deny` 由配置硬拒绝；OpenCode 权限 hook 不能把显式 `deny` 改成 `allow`。
- 直接 `pip install`／`npm install` 到全局环境不属于 `allow`；依赖安装走 `request_dependency`。

## 出口代理与市场本地化

价格和币种可能按出口 IP、语言或市场路径本地化。浏览器里的样本、构建 Agent 的静态请求和运行期 fetcher 如果走不同出口，可能得到不同市场的结果；2026-11-23 的 `sixmoondesigns.com` 真实构建中，本地直连得到 CNY，换 US 出口后得到 USD。构建、主机验证和后续任务必须使用同一出口，并把出口当作观察上下文记录，不能凭代理国家猜币种。

| 配置 | 作用 | 默认 |
| --- | --- | --- |
| `ECOM_BUILD_PROXY` | 构建工作的默认出口；写入构建简报，主机验证使用同一出口 | 空，回退 `ECOM_FETCH_PROXY` 或直连 |
| `ECOM_FETCH_PROXY` | `worker`／`run` 的静态和浏览器 fetcher 出口 | 空，直连 |
| `--proxy` | `serve`／`worker`／`run`／`submit` 的进程级覆盖 | 空 |
| `POST /api/builds/...` 的 `proxy` | 单次构建出口；构建记录和批次站点保存，批次启动沿用 | 空，回退服务默认 |
| `fetch.browser.proxy` | 规则内浏览器出口；不写进方案包正文的本地路径 | 空 |

- 代理 URL 接受 `http`／`https`／`socks5`，不写凭据；日志和 API 展示会遮蔽 userinfo。
- 构建简报要求 Agent 用 `curl --proxy <url>` 做静态价格／币种核对；主机验证使用同一 `proxy`，避免“浏览器看到 USD、静态请求看到 CNY”。
- 规则包不保存代理 URL；换出口视为新的市场上下文，重新构建或重新验证币种／市场，不把旧价格直接复用。
- 本机 mihomo 的 `crawler-us`（`127.0.0.1:17211`）和 `crawler-fr`（`127.0.0.1:17216`）已在 2026-11-23 用回显服务核验为 US／FR 出口；入口端口可用不等于出口地区正确，使用前用目标站或回显服务的一次请求核对。
- 代理不可达、出口地区不符、市场／币种与批次不一致时，构建按失败处理，不安装规则；错误写入构建记录，站点回到 `needs_onboarding`。
- 当前一次只支持一个构建出口；并发构建、按站点自动选出口、出口健康检查和轮换策略后置。

### 构建 trace 与思考过程

- 每次构建在 `out/trace.json`／`out/trace.md` 记录阶段、工具调用、命令／路径摘要、截断输出、可见消息、tokens／费用、主机验证、自动修复轮次和错误；默认不保存 reasoning。站点详情的“模型输出”通过 `/api/builds/{id}/messages` 展示构建中的流式时间线和结束后的完整可见消息；`timeline` 把思考、工具调用和文本按时间合并，工具块可展开入参和输出。
- 需要复盘模型思考过程时，以 `ECOM_BUILD_CAPTURE_REASONING=1` 启动服务，或在构建 API／站点详情勾选“保留思考过程”；trace 对单段 reasoning 截断 4,000 字符、总量 20,000 字符，并跳过原始导出、整页 HTML 和完整文件内容。
- 思考过程可能包含页面内容或业务信息；证据目录默认剥离，只有显式 `--include-reasoning` 才复制。模型、provider 和 variant（思考等级）在构建状态和 trace 中标出。
- 验证前先用 `lxml.cssselect` 静态编译规则中的 CSS 选择器；验证失败默认把精确错误和失败样例回给同一会话自动修复 1 轮，再重新预检和验证。`ECOM_BUILD_MAX_REPAIR_ROUNDS` 控制上限（0 关闭），`ECOM_BUILD_REPAIR_SECONDS` 控制额外时间；轮次和是否解决写入构建状态与 trace，仍不替代主机验证和人工签字。
- 描述块审计：规则用 `compose` 合并叙事正文、`ul.feature-list`、规格标签页等多个块，并用 `extract.fields.description_html.audit.blocks` 声明页面块；主机验证检查 `content_audit.description_gaps`，有缺口时把缺口样例回给同一会话修复。审计只覆盖规则声明的块，不凭空推断页面还有哪些内容。
- 已 `ready` 站点可在站点详情发起“重新验证／修复规则”：构建记录 `mode=repair`，主机把已安装规则复制到工作区，Agent 只做定向修复并 bump `rule_version`；修复失败保留原规则和已有采集数据，不删除任务。
- 视觉抽样审计：`ecom-crawler audit-content --rule ... --url ... --out ...` 用 Patchright 渲染商品页，读取商品区 `innerText` 与提取字段做覆盖 diff，并保存整页截图和 `visual-audit.json`；它是人工审计和规则复核工具，不进入批量运行路径，也不把截图当结构化提取来源。

### 页面存档与离线回放

- 存档模式：`off`（默认）、`sample`（适量）和 `full`（完整）。`sample` 每个抓取阶段最多写 20 页，适合规则复验和减少重复请求；`full` 保存所有成功响应，支持严格离线回放。
- 存储布局：`<archive-root>/<host>/<url-hash>.html.gz` 保存 gzip 原始 HTML，同名 `.json` 保存 `url/final_url/status/content_type/sha256/raw_bytes/stored_bytes/fetched_at/engine/task_id`；根目录 `index.jsonl` 追加索引。默认 `--archive-root` 为 `<out-root>/archive`。
- 构建期：构建默认 `archive_mode=off`；WebUI 构建面板可勾选“归档样例页面”，主机在验证前抓取规则声明的 `evidence.sample_urls` 和入口／分类页，验证时优先复用已存档页面。样例只用于复验，不承诺完整离线。
- 运行期：批次启动和 CLI `run`／`submit` 可传 `archive_mode=off|sample|full`、`archive_sample_limit`、`archive_max_bytes` 和 `archive_reuse`；`worker` 按任务输入执行并共享同一 archive root。
- 离线：`--offline` 只允许 `archive_mode=full`，缺失 URL 以 `ARCHIVE_MISS` 停止；`--archive-reuse` 在 `sample`／`full` 下优先读存档、缺页回退网络。存档只保存 HTML 和元数据，不保存图片／字体资源，也不保证浏览器交互可重放。
- 容量：`full` 会按任务页数增长，抓取前先估算站点商品数和单页大小；默认不开启，设置 `archive_max_bytes` 或任务上限，避免无界占用磁盘。


## 暂停门

- 每个构建工作区加载 `pause-gate` 插件；插件在 `permission.hook("evaluate")` 中检查 `control/pause.json`。
- 暂停时把进入权限检查的工具动作提升为 `ask`，BuildService 扣住权限请求；恢复时回复 `once`，工具继续。
- 这样即使常规工具动作是 `allow`，暂停也能在工具执行前生效；显式 `deny` 仍然最终生效。
- 控制文件不可读或插件异常时 fail closed，按暂停处理并记录错误。
- 暂停门只覆盖进入权限检查的工具动作；未走权限检查的内部动作不在范围内，需要硬停时用取消。
- 当前已启动的工具允许跑完；不承诺暂停模型内部推理。

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (await isPaused(event.sessionID)) {
    event.effect = "ask"
    event.message = "Build paused; request held until resume"
  }
})
```

## 依赖请求

Agent 不应直接安装到全局环境；缺失依赖时调用 `request_dependency` 工具，或在没有工具时发出结构化请求。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `package` | 是 | 包名或工具名 |
| `manager` | 是 | `uv`、`pip`、`npm` 或系统包管理器 |
| `version` | 是 | 固定版本或明确范围；不接受“最新” |
| `reason` | 是 | 为什么基线不够用 |
| `source` | 是 | 官方 registry 或已批准镜像 |
| `license` | 是 | 许可；不明确时先查 |
| `scope` | 是 | `build` 或 `system`；默认 `build` |
| `fallback` | 是 | 装不上时的替代路径 |

处理顺序：

- 基线已有：返回版本，不安装。
- allowlist 内：自动装入构建 venv 或工具缓存，记录事件和 `out/result.json`。
- 未知或系统级：生成一次性审批请求；批准后装入隔离环境，拒绝则返回原因和 fallback。
- 安装失败：返回 stderr 摘要和退出码；Agent 选择 fallback 或停止，不循环重试。
- 安装完成后重跑最小验证（import、版本或 `--help`），不把“装完”当“可用”。

约束：

- 不写全局 site-packages、系统目录或用户主目录；`sudo`／管理员操作默认拒绝。
- `scope=system` 只表示需要系统级组件；由操作者在当前设备或已有专用设备上安装，Agent 不直接写系统目录或提权。
- 不使用任意 URL、网盘或未校验的二进制；优先官方 registry 或已批准镜像。
- 记录包名、版本、来源、许可、安装位置和哈希（可得时）。
- 依赖安装是代码执行，按高风险处理；不复用日常浏览器 profile 或密钥。

**2026-11-22 实现状态**：`request_dependency` 工作区插件、host 侧 `DependencyBridge`、一次性审批和安装后校验已落地。当前自动安装只覆盖 Python 的 `uv`／`pip` 到构建解释器，且只接受固定版本（不接受范围），以保证安装结果可解释；`npm`／`system` 返回 `approval_required`，由操作者在设备上安装。未知包在显式批准且带固定版本时可由构建策略安装；系统级包不由 Agent 直接写系统目录。证据见 `experiments/harness/README.md`。

## 运行位置与基本边界

- v1 不建设 AI Agent 安全沙箱；使用当前设备或已有专用设备，每个构建一个独立工作区。
- 使用独立浏览器 profile，不共享日常账号、Cookie 和密钥。
- 工作区可快照或重置；构建失败先回滚工作区，不重装整机。
- 网络按允许 origin／路径；代理和镜像登记在环境配置，不写进方案包。
- 构建结束回收进程树、浏览器、临时目录和锁；残留写入结果。
- 专用设备、VM、容器、独立 OS 用户和网络隔离属于进阶项；出现不可信站点、多人共用或高价值凭据时再评估。

## 预检清单

| 检查 | 命令或方法 | 通过条件 |
| --- | --- | --- |
| 环境安装 | `python scripts/setup_crawl_env.py --json` | 退出码 0，`browser=installed` |
| Python | `python --version` | 3.11+ |
| uv | `uv --version` | 可用 |
| Node／OpenCode | `node --version`、`opencode --version` | 版本与基线一致 |
| Git／CLI | `git --version`、`rg --version`、`jq --version` | 可用 |
| Python 采集库 | `python -c "import httpx, bs4, lxml, yaml, pydantic, scrapling, playwright, curl_cffi, patchright, browserforge"` | 无 ImportError |
| 浏览器 | 启动 Chromium 打开 `about:blank` | 能启动、能退出、profile 可回收 |
| OpenCode | `opencode serve` 健康检查或 `opencode --version` | 版本匹配，API 可连 |
| 暂停门 | 触发一次权限请求，暂停／恢复 | 暂停时请求被扣住，恢复后继续 |

- Windows 用 PowerShell，Python 加 `-X utf8`；路径和浏览器 profile 锁单独检查。
- 预检结果写入 `out/result.json` 的 `environment` 段；失败项生成依赖请求或阻塞说明。
- 没有实际预检和最小采集冒烟证据时，不把基线标成“已准备”。

## 更新与验证

- 基线版本按 `YYYY.MM.DD` 递增；升级依赖或浏览器时重跑预检和最小采集冒烟。
- 不在构建中途升级基线；新构建使用新基线，旧构建保留原版本和结果。
- 修改 `baseline/requirements.txt` 后，重新生成 `baseline/requirements.lock.txt`，再跑 `scripts/setup_crawl_env.py`。
- 变更记录写清包、旧版本、新版本、原因、许可和回滚方式。
- 常见采集路径至少覆盖静态 HTML、公开 JSON、SPA／公开 API 和一个浏览器页面。
