## 设计目标与方式

界面围绕用户从**一批站点到结果交付**的工作流组织：提交批次、判断站点能否采集、配置采集、执行与监控、验收与导出、历史复用。当前 v1 只覆盖其中的任务执行段；目标工作流和页面结构见[用户工作流与前端信息架构](33-用户工作流与前端信息架构.md)。允许采用现成免费面板、前端框架或重新设计，不沿用旧表单和技术层级作为前提。

用户强调：先基于功能和操作目标专注设计前端原型，避免一边设计一边受既有后端实现细节牵制；再按契约接后端，发现不合理处时调整并保持一致的视觉风格。原型可以使用明确标识的模拟数据，但接入时必须区分模拟、提交请求和真实执行成功。

项目方可能没有前端设计或编码背景，Agent 不应把“怎么设计”原样抛回给项目方；Agent 应先给出可预览的页面结构、线框、状态清单和取舍选项，项目方确认目标用户、用户任务和选择。前端最终是给用户使用的，优先级是任务可完成、状态真实、控制可理解、结果可核对，而不是视觉效果本身。

v1 的界面形态是本地 Web UI：单机单用户，浏览器访问，默认只绑定回环地址；不做桌面壳，决策见[任务粒度、资源配额与 Web 界面 ADR](adr/0004-任务粒度、资源配额与Web界面.md)。

本文件是业务简报，不是冻结布局；初步设计稿见[D08 初步设计稿](29-D08初步设计稿.md)，线框和线框确认的含义见[开发、界面与运行时概念说明](27-开发与运行时概念说明.md)的“界面设计”和“线框确认与验收的区别”两节，设计稿已于 2026-11-22 评审通过。新团队应提供能预览的页面结构／线框，核心数据执行闭环仍优先，不让完善面板阻塞第一阶段证明。任务状态、计数和取消语义以[任务状态与计数契约](09-任务状态与计数契约.md)为准；操作、状态和失败分类的用户速查见[术语表](术语表.md)。本文件只描述用户可见行为。v1.0 的必须有／可后置清单和 API 范围见 [v1 界面范围](25-v1界面范围.md)，服务、API 和前端实现设计见 [D08 任务服务与界面设计](26-D08任务服务与界面设计.md)，最小设计包和评审门见[D08 前端设计包与评审](28-D08前端设计包.md)。2026-11-21 已确认 v1.0 保留暂停／恢复／取消，构建会话 UI 后置。

v1 当前实现从**受管规则包**开始：新站首次方案由技术操作者在构建 harness 中构建并标记 `verified`，界面不承担构建会话。创建任务时选择已受管规则包、市场和预算；角色与交接见[用户角色与职责](31-用户角色与职责.md)。这是过渡范围，不是目标用户工作流：业务用户应从一批站点开始，规则包是站点背后的内部资产。目标设计见[用户工作流与前端信息架构](33-用户工作流与前端信息架构.md)。

## 用户工作流与当前范围

目标工作流按“提交批次 → 站点核验与匹配 → 批次计划 → 接入与构建 → 执行 → 监控与异常 → 验收与导出 → 历史复用”组织。当前 v1 任务控制台只覆盖“已接入站点”的执行段，缺少批次导入、站点接入状态、批量操作和批次交付；差距、对象模型和线框见 `33`。当前页面不能替代目标工作流设计，也不能把“规则包下拉框”写成用户入口。

## 前后端边界

v1 的 Web 界面采用前后端分离：前端只通过本地 API 读取任务、商品、方案和构建会话信息，不在页面内直接访问数据库或启动采集进程。可以先交付 CLI，但 CLI 与 Web 共用同一任务服务；API 契约与实现设计见 [D08 任务服务与界面设计](26-D08任务服务与界面设计.md)。允许选择现成面板或自建前端，不因此绕过状态、计数、权限和资源回收契约。

任务列表至少区分 `discovery` 和 `product`：前者显示 URL 计数和清单，后者显示商品计数。多个任务并行时，分别显示各任务状态和全局资源占用，不用一个总进度掩盖单任务停止原因。

## 任务粒度与资源配额

- 默认一个采集任务对应一个站点、一个方案版本和一个市场；范围、预算和输出是任务参数。
- 同一站点的多个任务只在复采、方案版本切换、不同市场或不同深度时出现；界面提示同站任务，并显示它们共享站点限速。
- 批次和站点分组用于组织、筛选和交付，不合并任务计数；批次汇总由成员任务派生。当前实现尚未提供批次对象，目标设计见 `33`。
- 并发分三层：全局同时运行任务数、任务内工作项并发、浏览器实例上限；创建和详情页显示当前配额与排队原因。
- 资源不足时任务保持排队并说明原因，不先启动再争抢。

## 最小操作闭环

以下是**当前 v1 任务控制台**的最小闭环，前提是站点已经接入；从一批站点开始的目标闭环见 `33`。

1. 从任务列表创建目标，选择已受管规则包，确认必要市场／语言和资源默认值，不要求普通用户填选择器。
2. 进入任务详情，看到真实阶段、Agent公开活动、已发现及有效商品数量、失败和阻塞。
3. 查看网址或商品明细，保留筛选与返回上下文；完整HTML描述、部分正文标记、币种和价格口径可见。
4. 执行当前合法控制操作，反馈请求是否接收和后台是否已落实，断连时可核原操作结果。
5. 下载完整有效结果及失败／排除说明；保存或导出方案，在兼容环境创建新任务复用。

## 操作语义

界面按钮使用“暂停”和“取消任务”，不使用“停止”；如果保留“停止”，必须让用户二选一。

| 操作 | 应有行为 |
| --- | --- |
| 创建／启动 | 区分保存、排队、实际运行；重复点击不创建重复执行 |
| 停止／暂停 | 清楚说明属于暂停还是取消；暂停停止新工作，在途结清后才称已暂停；强制中止在途是单独的高级操作 |
| 恢复 | 从原进度继续；环境或方案不兼容时解释，不承诺恢复原浏览器内存 |
| 取消 | 实际阻止后续执行与迟到写入，回收自建资源，保留已接纳结果及历史；取消是终态，不能恢复 |
| 崩溃后重启 | 先对账再显示；未结任务标恢复中或已暂停，不把未知在途当成功；恢复条件不满足时说明原因并要求新建任务 |
| 业务验收／调整状态 | 用户可认定已满足需要，记录人、时间、理由、适用范围；不覆盖系统停止原因、待处理和未知覆盖 |
| 回收／还原列表 | 已结束且在途结清的任务移到回收区，还原只恢复显示，不重新采集 |
| 永久移除 | 明确对象和后果，独立确认；删除任务记录、结果和产物，不误删共享方案、配置或其他任务数据；文件占用时异步回收并报告残留 |
| 修复／再采 | 原目标错误修复与新时点／新范围采集区分，旧有效性和失败历史保留 |

## 构建会话控制

构建 Agent 会话与采集任务是两个受管对象。界面至少能查看构建会话的阶段、公开活动、启动时间、资源占用和最近错误，并支持暂停、取消和移除；取消后不再派发新的工具调用，当前调用按取消或超时处理，相关进程、浏览器和临时目录按所有权回收。2026-11-23 的 v1 先在站点详情提供最小控制：启动构建、阶段／工具／消息摘要、暂停／恢复／取消、失败原因和 trace 下载；完整构建会话 UI（多轮对话、权限／依赖审批页面、移除）后置。

构建会话使用独立状态（`CREATED`／`RUNNING`／`PAUSING`／`PAUSED`／`CANCELLING`／`CANCELLED`／`FINISHED`），不复用采集任务状态；契约见[构建 Agent Harness 契约](adr/0005-构建Agent与Harness契约.md)，选型与集成方式见[构建 Harness 选型与集成方式](adr/0006-构建Harness选型与集成方式.md)。

构建会话默认自动批准常规工作区读写、浏览器和公开网页访问；只在未知依赖安装、系统级操作、工作区外访问、密钥和访问控制边界请求确认。暂停由 `pause-gate` 在工具执行前拦截，不靠每次弹权限；显式拒绝项不能被暂停门绕过。依赖基线见[构建环境与依赖基线](20-构建环境与依赖基线.md)。

v1 不建设 AI Agent 安全沙箱；工作区隔离、独立浏览器 profile 和权限规则提供基本边界，专用设备／VM／容器后置。

暂停只在工具调用边界生效：当前调用结束后不再派发下一步，不承诺暂停模型内部推理。恢复从最近检查点继续，不能保证保留原浏览器内存。会话结束后，已保存的方案按[采集方案与兼容契约](08-采集方案与兼容契约.md)交付，不依赖原会话继续存在。

## 进度和结果显示

v1 以计数为主，不要求进度条：发现网址、去重商品候选、已处理、待处理、在途、有效、排除、失败分别展示和解释；HTTP请求和重试次数不重复计入商品产量。discovery 显示 URL 计数，product 显示商品计数，两者不互相折算。

只有已知分母（`coverage.status = KNOWN`）或明确预算上限时才显示比例；其余显示阶段和增长计数，不编造整站覆盖率、百分比、速率或剩余时间。进度条、瞬时速率、ETA 和图表属于进阶项。

显示观测时间，读取失败保留上次可信值并标过时；页面隐藏停止前端读取，后台任务继续。重开详情从持久事实恢复，不能用页面缓存当状态真源。

Agent自报与执行器确认的结果有来源区别。日志、错误和HTML预览按不可信内容呈现，不执行原站脚本、不显示密钥或Cookie。

## 界面验收

以真实操作检查列表→创建→详情→数据→导出→返回，以及当前承诺的任务控制、构建会话暂停／取消／移除和恢复；按钮可点、截图好看不等于业务已执行。前端通过 API 访问服务，不直接读数据库或启动进程。功能齐全、页面能点也不等于前端设计评审通过；A16 需保留[D08 前端设计包与评审](28-D08前端设计包.md)的评审记录。当前验收只覆盖任务控制台；从一批站点开始的批次提交、接入判断、批量执行和批次导出见[用户工作流与前端信息架构](33-用户工作流与前端信息架构.md)，未实现前不能写成 A16 覆盖。先提供清楚易用的本地 Web 界面（单机单用户、浏览器访问），至少覆盖任务列表、创建、详情、暂停／恢复／取消、计数和导出；开发期只承诺主规格和单一主题，窄屏与完整主题放到交付前适配阶段，不以超出承诺范围的细节拖住核心。
