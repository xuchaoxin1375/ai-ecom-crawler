## 设计目标与方式

界面围绕用户的**创建任务、看到工作、控制运行、查看网址／商品、导出结果、复用方案**组织。允许采用现成免费面板、前端框架或重新设计，不沿用旧表单和技术层级作为前提。

用户强调：先基于功能和操作目标专注设计前端原型，避免一边设计一边受既有后端实现细节牵制；再按契约接后端，发现不合理处时调整并保持一致的视觉风格。原型可以使用明确标识的模拟数据，但接入时必须区分模拟、提交请求和真实执行成功。

v1 的界面形态是本地 Web UI：单机单用户，浏览器访问，默认只绑定回环地址；不做桌面壳，决策见[任务粒度、资源配额与 Web 界面 ADR](adr/0004-任务粒度、资源配额与Web界面.md)。

本文件是业务简报，未给出冻结布局或可预览设计稿。新团队应提供能预览的页面原型再进入实现，核心数据执行闭环仍优先，不让完善面板阻塞第一阶段证明。任务状态、计数和取消语义以[任务状态与计数契约](09-任务状态与计数契约.md)为准；操作、状态和失败分类的用户速查见[术语表](术语表.md)。本文件只描述用户可见行为。

## 前后端边界

v1 的 Web 界面采用前后端分离：前端只通过本地 API 读取任务、商品、方案和构建会话信息，不在页面内直接访问数据库或启动采集进程。可以先交付 CLI，但 CLI 与 Web 共用同一任务服务；API 契约由项目技术文档维护。允许选择现成面板或自建前端，不因此绕过状态、计数、权限和资源回收契约。

任务列表至少区分 `discovery` 和 `product`：前者显示 URL 计数和清单，后者显示商品计数。多个任务并行时，分别显示各任务状态和全局资源占用，不用一个总进度掩盖单任务停止原因。

## 任务粒度与资源配额

- 默认一个采集任务对应一个站点、一个方案版本和一个市场；范围、预算和输出是任务参数。
- 同一站点的多个任务只在复采、方案版本切换、不同市场或不同深度时出现；界面提示同站任务，并显示它们共享站点限速。
- 站点分组和批次只做展示，不合并任务计数。
- 并发分三层：全局同时运行任务数、任务内工作项并发、浏览器实例上限；创建和详情页显示当前配额与排队原因。
- 资源不足时任务保持排队并说明原因，不先启动再争抢。

## 最小操作闭环

1. 从任务列表创建目标，确认必要市场／语言和资源默认值，不要求普通用户填选择器。
2. 进入任务详情，看到真实阶段、Agent公开活动、已发现及有效商品数量、失败和阻塞。
3. 查看网址或商品明细，保留筛选与返回上下文；完整HTML描述、部分正文标记、币种和价格口径可见。
4. 执行当前合法控制操作，反馈请求是否接收和后台是否已落实，断连时可核原操作结果。
5. 下载完整有效结果及失败／排除说明；保存或导出方案，在兼容环境创建新任务复用。

## 操作语义

界面按钮使用“暂停”和“取消任务”，不使用“停止”；如果保留“停止”，必须让用户二选一。

| 操作 | 应有行为 |
| --- | --- |
| 创建／启动 | 区分保存、排队、实际运行；重复点击不创建重复执行 |
| 停止／暂停 | 清楚说明属于暂停还是取消；暂停停止新工作，在途结清后才称已暂停；强制中止在途是单独的高级操作 |
| 恢复 | 从原进度继续；环境或方案不兼容时解释，不承诺恢复原浏览器内存 |
| 取消 | 实际阻止后续执行与迟到写入，回收自建资源，保留已接纳结果及历史；取消是终态，不能恢复 |
| 崩溃后重启 | 先对账再显示；未结任务标恢复中或已暂停，不把未知在途当成功；恢复条件不满足时说明原因并要求新建任务 |
| 业务验收／调整状态 | 用户可认定已满足需要，记录人、时间、理由、适用范围；不覆盖系统停止原因、待处理和未知覆盖 |
| 回收／还原列表 | 已结束且在途结清的任务移到回收区，还原只恢复显示，不重新采集 |
| 永久移除 | 明确对象和后果，独立确认；删除任务记录、结果和产物，不误删共享方案、配置或其他任务数据；文件占用时异步回收并报告残留 |
| 修复／再采 | 原目标错误修复与新时点／新范围采集区分，旧有效性和失败历史保留 |

## 构建会话控制

构建 Agent 会话与采集任务是两个受管对象。界面至少能查看构建会话的阶段、公开活动、启动时间、资源占用和最近错误，并支持暂停、取消和移除；取消后不再派发新的工具调用，当前调用按取消或超时处理，相关进程、浏览器和临时目录按所有权回收。

构建会话使用独立状态（`CREATED`／`RUNNING`／`PAUSING`／`PAUSED`／`CANCELLING`／`CANCELLED`／`FINISHED`），不复用采集任务状态；契约见[构建 Agent Harness 契约](adr/0005-构建Agent与Harness契约.md)。

暂停只在工具调用边界生效：当前调用结束后不再派发下一步，不承诺暂停模型内部推理。恢复从最近检查点继续，不能保证保留原浏览器内存。会话结束后，已保存的方案按[采集方案与兼容契约](08-采集方案与兼容契约.md)交付，不依赖原会话继续存在。

## 进度和结果显示

v1 以计数为主，不要求进度条：发现网址、去重商品候选、已处理、待处理、在途、有效、排除、失败分别展示和解释；HTTP请求和重试次数不重复计入商品产量。discovery 显示 URL 计数，product 显示商品计数，两者不互相折算。

只有已知分母（`coverage.status = KNOWN`）或明确预算上限时才显示比例；其余显示阶段和增长计数，不编造整站覆盖率、百分比、速率或剩余时间。进度条、瞬时速率、ETA 和图表属于进阶项。

显示观测时间，读取失败保留上次可信值并标过时；页面隐藏停止前端读取，后台任务继续。重开详情从持久事实恢复，不能用页面缓存当状态真源。

Agent自报与执行器确认的结果有来源区别。日志、错误和HTML预览按不可信内容呈现，不执行原站脚本、不显示密钥或Cookie。

## 界面验收

以真实操作检查列表→创建→详情→数据→导出→返回，以及当前承诺的任务控制、构建会话停止／移除和恢复；按钮可点、截图好看不等于业务已执行。前端通过 API 访问服务，不直接读数据库或启动进程。先提供清楚易用的本地 Web 界面（单机单用户、浏览器访问），至少覆盖任务列表、创建、详情、暂停／恢复／取消、计数和导出；响应式与主题范围由阶段计划明确，不以超出承诺范围的细节拖住核心。
