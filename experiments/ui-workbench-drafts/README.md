# 工作台三窗格布局草稿

目的：比较三种“左侧目录 + 右上任务 + 右下日志”的固定三窗格布局，解决当前工作台里
“看运行中任务要跳页、运行日志分散、站点/任务操作入口分散”的问题。参考对象是火车头采集器的
单窗口三窗格，但不复制它的视觉样式。

## 快速预览

```powershell
python -m http.server 8801 --directory experiments/ui-workbench-drafts
```

打开 <http://127.0.0.1:8801/>。

- `index.html`：四版对比、推荐稿与取舍
- `draft-d.html`：D · 任务树 + 最近任务（按补充调整）
- `draft-a.html`：A · 批次工作台
- `draft-b.html`：B · 站点操作树
- `draft-c.html`：C · 运行驾驶舱
- `draft.css` / `draft-icons.js` / `draft-data.js`：四版共用样式、图标和示例数据

四页均为静态原型，不调用后端 API，不写入真实账本；示例数据每 2.8 秒在浏览器内推进一次，
用于观察进度条、树计数和日志追加。窄屏下缩到 900px 以下可查看目录抽屉和「任务 / 日志」切换。
外壳按现有侧栏收起态（60px 图标栏）展示；展开侧栏时三窗格按比例压缩，不另做一套布局。

## 四版差异

- D 按补充调整：左侧是无限层级任务树，右侧是最近任务列表；树头「+」或右键目录可新建目录/任务组、新建单个任务、添加已有批次、新建批次，右键任务可控制任务。当前 D 是**布局原型**，树节点用站点任务示意，已演示拖拽调整归属、改名、新建/解散目录、终止状态移除和撤销；长期任务定义属性、运行映射、批次批量添加/新建批次的完整交互尚未在原型中实现，最新语义以[任务树与最近任务工作台设计](../../docs/49-任务树与最近任务工作台设计.md)为准。
- A 以批次为上下文：左树选批次，右上站点任务表带进度与行内控制，右下日志跟随选中行；
  顶部可切到跨批次的运行中、排队中、需关注视图。
- B 把操作下沉到树：批次 → 站点两级树，站点行直接启停/导出；右上显示选中站点的当前任务、
  任务历史和站点资料。
- C 以运行监控为核心：左侧是运行筛选与批次过滤，右上跨批次任务表支持批量暂停/继续，右下日志。

- 批次与站点命名、市场、规则版本取自当前仓库文档中的真实批次；

## 结论与边界

本轮只选布局方向，不是实现规格。D 的任务树归属、拖动排序和最近任务移除都只在浏览器内存中，
刷新会恢复示例初始状态；它演示交互，不代表已经确定后端模型。选定后需要：

- 明确任务树归属的持久化方式：复用 `batch_folders` 扩展，还是新增独立的树节点与排序表；
  明确拖动只改组织归属，还是也允许跨批次重新归属，以及后者的市场/规则校验；
- 明确“从最近列表移除”的产品语义：当前草稿按“仅本列表移除，任务仍在树中”实现，
  如果实际需要删除任务或从树中移除，必须单独设计确认和回滚；
- 按项目既有设计流程补设计说明与 Mermaid 机制图，确认页面清单、状态矩阵和验收条件；
- 把草稿中的 mock 行操作映射到真实 API 与权限，明确哪些操作只读；
- 复核窄屏（390/320）、键盘、焦点、axe 和长列表性能；原型未覆盖这些验收项。

原型文件可提交；预览截图和运行产物放在仓库外证据目录，不进入版本控制。
