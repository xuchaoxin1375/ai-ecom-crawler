# 批次工作台前端原型（2026-11-22）

这是一个**可浏览的静态前端原型**，用于验证“从一批站点到结果交付”的工作流、信息架构和关键状态。它不是生产页面，也没有接入后端。

## 为什么做这个原型

当前 `app/` 的页面是“已接入站点的任务控制台”，从规则包开始；它不能承接“一批法国手工／纺织网站”的真实工作流。这个原型把对象模型改成：

```text
批次（项目） → 站点 → 任务 → 结果
```

规则包降为站点背后的技术资产，只在站点技术详情中出现。

## 打开方式

在本目录启动一个静态服务器：

```powershell
python -m http.server 8780
```

然后打开：

```text
http://127.0.0.1:8780/
```

不要直接用 `file://` 打开，ES modules 可能被浏览器拦截。

## 页面与流程

- **采集批次**：批次列表、状态、站点数、可采／待接入、任务状态。
- **新建批次**：命名和归类 → 粘贴／上传站点 → 解析与匹配预览 → 保存草稿或启动可采站点。
- **批次详情**：整批摘要、站点筛选、可采／待接入／运行／完成／失败、批次级操作。
- **站点／任务详情**：单站状态、计数、质量异常、商品／网址明细、技术详情。
- **全部任务**：技术排查视图，显示任务所属批次。
- **规则包（技术）**：说明规则包是内部资产，不作为业务入口。

## 原型覆盖的状态

- 批次：草稿、部分就绪、运行中、已完成。
- 站点：可采、待接入、无效／重复、未开始、运行中、已暂停、已完成、失败。
- 任务：计数、覆盖、停止原因、质量异常、商品／网址明细。
- 空状态、筛选无结果、导入校验、部分启动提示、导出说明、控制确认。

## 明确不做

- 不连接真实 API、数据库、worker 或构建 harness。
- 不执行真实采集、文件解析或 zip 导出；相关按钮只展示确认和反馈。
- 不覆盖完整 768／320 响应式矩阵、深色主题、登录和多用户权限。
- 不代表 `25` 的当前 v1 范围；批次工作台是否进入 v1 仍需项目方确认。

## 文件

- `index.html`：应用外壳、侧栏、顶栏、视图容器。
- `styles.css`：原型样式和基础响应式。
- `app.js`：mock 数据、hash 路由、页面渲染和交互。
- `capture.py`：1280 截图、768 基础检查、交互冒烟和结构检查（需要 Patchright/Chromium）。
- `screens/`：批次列表、批次详情、新建导入、匹配预览、站点详情和 768 截图。
- `evidence.json`：截图运行的结构检查结果；没有真实后端证据。

## 评审时看什么

1. 用户是否从“批次”开始，而不是从“规则包”开始。
2. 站点“可采／待接入／失败”是否有清楚的下一步。
3. 批次详情是否能回答“整批现在怎样、哪些需要处理”。
4. 规则包是否被放到技术详情，而不是业务主流程。
5. 部分启动、部分导出和失败是否没有被伪装成整批完成。

原型评审通过后，才把选定方向映射到 `25`／`26` 的 API、账本和实现切片。
